## Быстрый ответ

Семантическая вёрстка выбирает HTML-элементы по назначению содержимого и действия, а не по внешнему виду. `<nav>` обозначает навигацию, `<article>` — самостоятельный материал, `<section>` — тематическую часть документа, `<button>` — действие, а `<a href>` — переход к другому адресу.

Такой выбор позволяет браузеру и вспомогательным технологиям распознать структуру и назначение интерфейса. Для многих нативных элементов браузер также предоставляет готовое поведение: например, клавиатурную активацию кнопки или обычные возможности ссылки. `<div>` и `<span>` остаются правильным выбором, когда нужна нейтральная группировка без более точного смысла.

## Карта темы

| Смысл | Подходящий элемент | Важная граница |
| --- | --- | --- |
| Основное содержимое документа | `<main>` | в документе не должно быть больше одного `main` без атрибута `hidden` |
| Навигационный раздел | `<nav>` | не каждая группа ссылок требует отдельного `nav` |
| Самостоятельный материал | `<article>` | материал в принципе можно использовать отдельно от окружающей страницы |
| Тематическая часть | `<section>` | это не универсальная обёртка; обычно у раздела есть заголовок |
| Косвенно связанное содержимое | `<aside>` | оно связано с основным материалом, но не является его центральной частью |
| Действие | `<button>` | запускает действие, а не переход к URL |
| Навигация | `<a href>` | представляет ссылку на адрес |
| Нейтральная группировка | `<div>` / `<span>` | используется, когда дополнительная семантика не нужна |

## Как выбирать семантический элемент

Сначала определяют, что представляет собой содержимое или действие, затем выбирают HTML-элемент и только после этого стилизуют его. Одинаковый внешний вид не означает одинаковую семантику.

Например, визуальная карточка может быть:

- `<article>`, если это самостоятельный материал;
- `<li>`, если карточка является пунктом списка;
- `<div>`, если она нужна только как нейтральная layout-обёртка.

Главный вопрос — не «как элемент выглядит?», а «что он означает и какое поведение ожидает пользователь?».

## Структура страницы и заголовки

`<main>` обозначает основное содержимое документа. `<nav>` выделяет раздел с навигационными ссылками. `<aside>` содержит материал, который связан с окружающим содержимым косвенно, например боковую справку или дополнительный блок.

`<article>` представляет самостоятельную композицию, которую в принципе можно переиспользовать или распространять отдельно: например, пост, новость или комментарий. `<section>` представляет тематическую часть документа или приложения и обычно получает заголовок. Если обёртка нужна только для CSS или JavaScript, вместо `<section>` используют `<div>`.

Заголовки `h1`–`h6` имеют явные уровни. `h1` обозначает верхний уровень, `h2` — следующий уровень вложенности, затем `h3` и так далее. Визуальный размер заголовка задаётся CSS и не должен определять его уровень.

`<header>` содержит вводную часть страницы или раздела, а `<footer>` — завершающую. Они не создают новый раздел сами по себе.

Если `<header>` не вложен в `article`, `aside`, `main`, `nav`, `section` или элемент с ARIA-ролью `article`, `complementary`, `main`, `navigation` или `region`, браузер сопоставляет его с landmark `banner`. При тех же условиях `<footer>` сопоставляется с `contentinfo`. Внутри таких контейнеров эти landmark-роли не применяются.

## Ссылка, кнопка, список и таблица

Кнопка запускает действие в текущем интерфейсе: отправляет форму, открывает диалог, переключает режим или изменяет состояние. Ссылка ведёт к URL и сохраняет обычные возможности навигации: копирование адреса, открытие в новой вкладке и контекстное меню ссылки.

```html
<a href="/orders/42">Открыть заказ</a>
<button type="button">Повторить заказ</button>
```

CSS может сделать ссылку похожей на кнопку и наоборот, но внешний вид не меняет назначение элемента.

Набор однородных пунктов размечают через `<ul>` или `<ol>` и `<li>`. Таблица предназначена для данных, где важны отношения строк и столбцов. Для обычной раскладки страницы таблицу не используют.

## Нативная семантика и ARIA

Если подходящий нативный элемент уже существует, обычно используют его. ARIA может добавить или уточнить доступное имя, роль, состояние или связь, но не реализует поведение интерфейса.

Например:

```html
<div role="button">Сохранить</div>
```

получает роль кнопки для accessibility API, но разработчику всё равно нужно самостоятельно обеспечить фокус, обработку `Enter` и `Space`, состояние disabled и видимый индикатор фокуса. Нативный `<button>` уже предоставляет эти базовые возможности.

## Пример

```html
<header>
  <nav aria-label="Основная навигация">
    <a href="/catalog">Каталог</a>
    <a href="/profile">Профиль</a>
  </nav>
</header>

<main>
  <article>
    <h1>Как выбрать ноутбук</h1>

    <section>
      <h2>Экран</h2>
      <p>Сравните диагональ, разрешение и тип матрицы.</p>
    </section>
  </article>
</main>
```

Здесь `<nav>` обозначает навигацию, `<main>` — основное содержимое, `<article>` — самостоятельный материал, а `<section>` — его тематическую часть. Заголовки показывают иерархию содержимого независимо от того, как они будут оформлены CSS.

## Где применяется во frontend

- При проектировании компонентов: можно выбрать между ссылкой, кнопкой, списком, таблицей, `section` и нейтральным контейнером по смыслу, а не по дизайну.
- При разработке доступного интерфейса: нативная семантика помогает браузеру сформировать корректное представление для вспомогательных технологий.
- При навигации по большой странице: landmarks и уровни заголовков дают пользователю понятную структуру.
- При работе с дизайн-системой: один визуальный стиль может применяться к разным семантическим элементам без потери их назначения.
- При создании custom widget: ARIA используется только для недостающей семантики, а клавиатурное и focus-поведение реализуется отдельно.

## Ключевые уточнения

- Семантику определяет назначение содержимого или действия, а не CSS-класс и не внешний вид.
- `<article>` — самостоятельный материал; `<section>` — тематическая часть более крупного материала; `<div>` — нейтральная группировка.
- Уровни `h1`–`h6` передают иерархию содержимого, а визуальный размер заголовка задаётся отдельно.
- `<button>` запускает действие, `<a href>` выполняет навигацию по адресу.
- `<header>` вне `article`, `aside`, `main`, `nav`, `section` и соответствующих ARIA-контейнеров получает landmark `banner`; `<footer>` при тех же условиях получает `contentinfo`.
- ARIA дополняет семантику, но не добавляет клавиатурное взаимодействие автоматически.
