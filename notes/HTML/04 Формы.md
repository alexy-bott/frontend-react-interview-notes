## Быстрый ответ

HTML-форма — нативный механизм ввода и отправки данных. `<form>` задаёт адрес и способ нативной отправки, элементы управления получают имена через `name`, `<label>` связывает подпись с полем, а submit-кнопка запускает стандартный процесс отправки.

При обычной отправке браузер сначала выполняет встроенную проверку ограничений (constraint validation), если она не отключена. Если данные допустимы, браузер отправляет событие `submit`. Если обработчик его не отменил, браузер строит список отправляемых значений и выполняет навигацию или другую операцию, заданную формой.

JavaScript может отменить `submit`, создать `FormData` и отправить данные через `fetch`. При этом важно различать нативную отправку и `new FormData(form)`: нативная отправка учитывает кнопку, которой отправили форму, а `FormData(form)` без второго аргумента её значение не включает.

## Карта темы

```text
пользователь активирует submit
        ↓
constraint validation
        ↓
если форма валидна → событие submit
        ↓
если submit не отменён
        ↓
построение entry list (списка отправляемых значений)
        ↓
GET / POST / dialog по правилам формы
```

| Часть | Назначение |
| --- | --- |
| `action` | URL нативной отправки |
| `method` | способ нативной отправки, например `get` или `post` |
| `name` | имя элемента управления в отправляемых данных |
| `<label>` | видимая подпись и обычный источник доступного имени поля |
| `type` | определяет поведение конкретного `input` или `button` |
| `enctype` | формат тела при нативной POST-отправке |
| submitter | кнопка, которая запустила отправку и может переопределить `action`, `method`, `enctype` и другие параметры |

## Какие данные попадают в отправку

В список данных входит не каждый DOM-элемент внутри формы. Элемент управления без `name`, disabled control и unchecked checkbox обычно не создают entry.

У checkbox и radio отправляется значение `value`, а не логическое `true` или `false`. Если `value` не указан, для этих типов используется значение по умолчанию `on`.

Несколько элементов могут иметь одинаковый `name`. Тогда список данных содержит несколько entries с одним именем. Это важно, например, для группы checkbox.

Связь подписи с полем создают через `for` и `id`:

```html
<label for="email">Email</label>
<input id="email" name="email" type="email">
```

или вложением элемента управления в `<label>`. Placeholder может давать короткую подсказку, но не заменяет постоянную подпись.

## Как проходит submit

Кнопка внутри `<form>` по умолчанию является submit-кнопкой, если её тип не задан иначе. Для локальных действий вроде «Показать пароль» или «Добавить поле» используют `type="button"`.

```html
<button type="button">Показать пароль</button>
<button type="submit" name="intent" value="login">Войти</button>
```

Стандартная отправка проходит так:

1. Браузер проверяет ограничения формы, если validation не отключена через `novalidate` или `formnovalidate`.
2. Если проверка не пройдена, отправка останавливается и событие `submit` не происходит.
3. Если проверка пройдена, браузер отправляет cancelable-событие `submit`.
4. Если обработчик не вызвал `preventDefault()`, браузер строит entry list и выполняет действие формы.
5. Конкретный submitter может изменить параметры через `formaction`, `formmethod`, `formenctype`, `formtarget` и `formnovalidate`.

`SubmitEvent.submitter` позволяет узнать кнопку, которая запустила отправку. При implicit submit, например по `Enter`, конкретная кнопка может отсутствовать.

## `requestSubmit()`, `submit()` и `FormData`

`form.requestSubmit(button)` запускает обычный процесс как пользовательская submit-кнопка: учитывает submitter, выполняет constraint validation и отправляет событие `submit`.

`form.submit()` работает иначе: он отправляет форму напрямую, обходя интерактивную constraint validation и не создавая событие `submit`. Поэтому для программного запуска обычного пользовательского процесса отправки обычно нужен `requestSubmit()`.

`new FormData(form)` строит список текущих значений формы, но не включает значение submit-кнопки. Если значение submitter нужно сохранить, его передают вторым аргументом:

```js
form.addEventListener("submit", async (event) => {
  event.preventDefault();

  const data = new FormData(form, event.submitter);

  await fetch(form.action, {
    method: form.method,
    body: data,
  });
});
```

В этом примере `FormData` учитывает `name` и `value` кнопки, которая запустила submit. Если несколько полей имеют одинаковый `name`, получить все значения можно через `getAll()`.

Значением entry может быть строка или `File`. При передаче `FormData` как `body` в `fetch` браузер кодирует данные как `multipart/form-data` и формирует `Content-Type` с нужным `boundary`. Такой заголовок не нужно собирать вручную.

## Валидация, группы и autocomplete

Constraint validation использует встроенные ограничения: `required`, подходящий `type`, `min`, `max`, `minlength`, `maxlength`, `pattern` и другие правила конкретного элемента.

Клиентская validation улучшает обратную связь, но не является границей доверия. Сервер должен повторно проверять данные, права доступа и бизнес-правила, потому что встроенную проверку браузера можно обойти.

Связанные radio и checkbox удобно объединять через `<fieldset>` и `<legend>`. Корректные значения `autocomplete`, например `email` и `current-password`, помогают браузеру и password manager понять назначение поля.

## Пример

```html
<form id="login-form" action="/login" method="post">
  <label for="email">Email</label>
  <input
    id="email"
    name="email"
    type="email"
    autocomplete="email"
    required
  >

  <label for="password">Пароль</label>
  <input
    id="password"
    name="password"
    type="password"
    autocomplete="current-password"
    required
  >

  <button type="submit" name="intent" value="login">Войти</button>
</form>
```

```js
const form = document.querySelector("#login-form");

form.addEventListener("submit", async (event) => {
  event.preventDefault();

  const data = new FormData(form, event.submitter);

  await fetch(form.action, {
    method: form.method,
    body: data,
  });
});
```

Обработчик работает и для клика по submit-кнопке, и для клавиатурной отправки. `event.submitter` сохраняет информацию о кнопке, когда отправку действительно запустила кнопка.

## Где применяется во frontend

- При нативной отправке формы без JavaScript: браузер сам выполняет validation, строит данные и переходит по `action`.
- При SPA-отправке через `fetch`: обработчик `submit` отменяет навигацию и использует `FormData`.
- При нескольких submit-кнопках: `event.submitter` позволяет различить действия вроде «Сохранить черновик» и «Опубликовать».
- При загрузке файлов: `FormData` передаёт `File`, а браузер формирует корректный multipart boundary.
- При доступности формы: `label`, `fieldset`, `legend` и нативный submit сохраняют ожидаемое клавиатурное поведение.
- При валидации: браузер даёт быструю клиентскую проверку, а сервер остаётся окончательной границей доверия.

## Ключевые уточнения

- `name` определяет имя элемента управления в отправляемых данных; `id` сам по себе в отправку не попадает.
- Disabled controls и unchecked checkbox обычно не создают entries.
- Нативная отправка учитывает submitter; `new FormData(form)` без второго аргумента значение submit-кнопки не включает.
- `requestSubmit()` запускает обычную validation и событие `submit`, а `form.submit()` их обходит.
- При `fetch(..., { body: formData })` браузер сам формирует `multipart/form-data` и boundary.
- Client validation улучшает UX, но сервер всё равно должен проверять недоверенные данные.
