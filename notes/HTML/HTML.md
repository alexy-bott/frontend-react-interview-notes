## Быстрый ответ

HTML (HyperText Markup Language) - язык разметки, который описывает структуру и смысл веб-документа: заголовки, абзацы, ссылки, формы, таблицы, изображения и области страницы. Браузер разбирает HTML и строит Document Object Model (DOM) - дерево объектов, с которым затем работают CSS, JavaScript и browser APIs.

HTML также задаёт встроенное поведение элементов. Ссылка выполняет навигацию, кнопка участвует в клавиатурном взаимодействии, форма умеет отправлять данные, а `<details>` раскрывает содержимое. Поэтому выбор элемента влияет не только на читаемость исходника, но и на поведение браузера, доступность и работу инструментов.

## Ключевая схема

```text
HTML-байты
-> декодирование и tokenizer
-> построение дерева с правилами HTML parser
-> DOM
-> CSS, JavaScript, accessibility tree и rendering
```

| Часть | Назначение |
| --- | --- |
| Элемент | задаёт тип и смысл узла, например `<button>` |
| Атрибут | настраивает элемент, например `type="submit"` |
| Текстовый узел | содержит текст документа |
| Вложенность | задаёт отношения между частями документа |
| DOM | runtime-представление документа в браузере |

## Базовая модель

HTML parser одновременно преобразует входной поток в tokens и строит дерево по правилам стандарта. При ошибочной вложенности он может автоматически закрыть элемент, вставить недостающий узел или переставить часть содержимого. Поэтому DOM иногда отличается от визуально ожидаемой структуры исходного файла.

Элементы имеют допустимую модель содержимого. Например, интерактивные элементы обычно нельзя произвольно вкладывать друг в друга, а строки и ячейки таблицы должны находиться в правильной табличной структуре. Проверка validator помогает найти нарушение, но итоговое поведение определяется parser браузера.

Семантический элемент сообщает назначение и часто получает нативное поведение. `<button>` фокусируется, активируется с клавиатуры и имеет button role; `<a href>` является ссылкой и поддерживает открытие в новой вкладке; `<label>` связывает текст с form control. Универсальные `<div>` и `<span>` не несут такого контракта.

## Развернутый ответ

**HTML и DOM.** HTML - входная разметка, DOM - изменяемая объектная модель текущего документа. JavaScript может добавить или удалить узлы, а browser extension - изменить страницу, поэтому после загрузки DOM не обязан совпадать с исходным response.

**Разделение технологий.** HTML задаёт содержание, семантику и нативное поведение; CSS управляет представлением; JavaScript добавляет прикладную логику и динамические изменения. Граница не абсолютна: часть поведения уже декларативно встроена в HTML, а CSS влияет на доступность и rendering.

**Атрибуты и свойства.** Атрибут записан в разметке, а DOM property хранит текущее состояние объекта. Для некоторых сущностей они отражают друг друга, но не являются общим синонимом. Например, атрибут `value` задаёт начальное значение input, а property `input.value` меняется при вводе пользователя.

**Семантика и accessibility tree.** Браузер использует DOM, CSS и ARIA для построения дерева доступности, которое читают вспомогательные технологии. Правильный нативный элемент даёт более полный контракт, чем добавление одной ARIA role к `div`.

## Пример

```html
<main>
  <article>
    <h1>История заказа</h1>
    <p>Заказ передан в службу доставки.</p>
    <a href="/orders/42">Открыть заказ</a>
    <button type="button">Повторить заказ</button>
  </article>
</main>
```

Ссылка выполняет переход к другому URL, а кнопка запускает действие в текущем интерфейсе. Внешний вид обоих элементов можно изменить CSS, но их назначение и нативное поведение остаются разными.

## Ключевые уточнения

- HTML описывает не только геометрию блоков, а смысл и отношения содержимого, от которых зависит нативное поведение.
- DOM строится из HTML по правилам parser и затем может изменяться; это не неизменная копия исходного текста.
- Нативная семантика включает больше одной role: клавиатуру, focus, состояния и интеграцию с формой.
- Атрибут разметки и одноимённое DOM property могут отражать разные состояния, например начальное и текущее значение input.
- `div` и `span` уместны для группировки без собственного смысла; проблема возникает при замене ими подходящего смыслового или интерактивного элемента.
