## Быстрый ответ

HTML (HyperText Markup Language) — язык разметки, который описывает структуру и назначение частей веб-документа: заголовков, абзацев, ссылок, элементов формы, изображений и других областей страницы.

Браузер разбирает HTML в два связанных этапа: токенизатор распознаёт в потоке символов теги, атрибуты и текст, а этап построения дерева создаёт и изменяет узлы DOM. DOM — текущее объектное представление документа. Оно может отличаться от исходной разметки, потому что HTML-парсер исправляет некоторые ошибки структуры, а JavaScript может менять дерево после разбора.

Выбор HTML-элемента задаёт не только структуру, но и семантику и встроенное поведение. `<a href>` является ссылкой, `<button>` — кнопкой, `<label>` связывает подпись с элементом формы, а `<details>` управляет раскрытием содержимого. Универсальные `<div>` и `<span>` не получают такой семантики и поведения автоматически.

## Карта темы

```text
HTML
├── исходная разметка
│   ├── элементы
│   ├── атрибуты
│   ├── текст
│   └── вложенность
├── разбор браузером
│   └── символы → токены → построение дерева
├── DOM
│   └── текущее дерево объектов документа
├── выбор элемента
│   ├── семантика
│   └── встроенное поведение
└── отличие DOM от исходника
    ├── правила HTML-парсера
    └── изменения через JavaScript
```

## Как браузер строит DOM

HTML-парсер получает поток символов и передаёт его через токенизацию и построение дерева. Токенизатор выделяет, например, открывающий тег, закрывающий тег, текст или комментарий. Затем этап построения дерева смотрит на уже открытые элементы, применяет правила HTML и добавляет соответствующие узлы в объект `Document`.

DOM появляется постепенно по мере разбора документа. Браузер не обязан сначала получить и разобрать весь HTML. Например, обычный классический `<script>` без `async` или `defer` может остановить HTML-парсер, выполниться и только после этого позволить разбору продолжиться.

Правила парсера определяют итоговое дерево даже при ошибках или сокращённой разметке. Например, в исходном HTML можно не указывать `<tbody>`:

```html
<table>
  <tr>
    <td>42</td>
  </tr>
</table>
```

При построении DOM браузер вставит узел `<tbody>`:

```text
TABLE
└── TBODY
    └── TR
        └── TD
```

Поэтому исходный HTML и DOM в DevTools не обязаны совпадать буквально.

## Семантика и встроенное поведение

Элемент сообщает браузеру и вспомогательным технологиям, что представляет собой часть интерфейса. Для многих элементов браузер также реализует готовое поведение.

| Элемент | Что он обозначает | Что браузер предоставляет |
| --- | --- | --- |
| `<a href>` | ссылку на URL | навигацию и обычные действия со ссылкой, например открытие в новой вкладке |
| `<button>` | кнопку для действия | фокус, клавиатурную активацию и поведение кнопки формы в зависимости от `type` |
| `<label>` | подпись элемента формы | связь подписи с соответствующим элементом управления |
| `<details>` | раскрываемый блок | состояние открытия и закрытия и событие `toggle` |
| `<div>` / `<span>` | нейтральную группировку | без специальной семантики и встроенного интерактивного поведения |

ARIA может дополнить доступное имя, роль, состояние или связь, но одна ARIA-роль не воспроизводит поведение нативного элемента. Например, `<div role="button">` не начинает автоматически получать фокус и реагировать на `Enter` и `Space`: это поведение разработчику пришлось бы реализовать отдельно.

## Исходный HTML, DOM, атрибуты и свойства

Исходный HTML — текст разметки, а DOM — текущее дерево объектов в памяти браузера. После построения дерева JavaScript может добавлять и удалять узлы, менять атрибуты и текст. Поэтому DOM после запуска приложения может заметно отличаться от исходного ответа сервера.

Атрибут записан в разметке, а DOM-свойство хранится в JavaScript-объекте элемента. Некоторые пары отражают друг друга, но не всегда представляют одно и то же текущее состояние.

Например, атрибут `value` у текстового `input` задаёт значение по умолчанию, а свойство `input.value` хранит текущее значение:

```html
<input id="name" value="Анна">
```

```js
const input = document.querySelector("#name");

input.value = "Олег";

console.log(input.value); // "Олег"
console.log(input.getAttribute("value")); // "Анна"
```

После изменения свойства текущее значение поля стало `Олег`, но значение атрибута осталось `Анна`.

## Где применяется во frontend

- При выборе элемента интерфейса: ссылка сохраняет поведение навигации, кнопка — поведение действия, а `label` связывает подпись с полем формы.
- При отладке DOM: можно понять, почему браузер вставил или переставил узел и почему дерево в DevTools отличается от исходного HTML.
- При работе с формами: важно различать значение, записанное в атрибуте, и текущее DOM-состояние элемента управления.
- При анализе загрузки страницы: DOM строится постепенно, а некоторые скрипты могут приостанавливать HTML-парсер.
- При разработке доступного интерфейса: нативный элемент обычно даёт больше готовой семантики и поведения, чем нейтральный элемент с добавленной ролью.

## Ключевые уточнения

- HTML задаёт структуру и назначение содержимого; внешний вид и геометрию в основном определяет CSS.
- HTML-парсер состоит из связанных стадий токенизации и построения дерева.
- DOM строится постепенно и может отличаться от исходной разметки из-за правил парсера и последующих изменений JavaScript.
- Нативный элемент предоставляет семантику и встроенное поведение; одна ARIA-роль не добавляет клавиатурное взаимодействие автоматически.
- Атрибут разметки и одноимённое DOM-свойство не всегда хранят одно и то же текущее состояние.
- `<div>` и `<span>` подходят для нейтральной группировки, когда более точная семантика не нужна.
