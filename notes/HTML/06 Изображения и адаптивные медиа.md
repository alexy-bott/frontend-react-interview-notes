## Быстрый ответ

Responsive image позволяет браузеру выбрать подходящий файл для текущего layout и плотности экрана. `srcset` перечисляет варианты изображения, `sizes` сообщает ожидаемую ширину изображения в CSS-пикселях, а браузер выбирает подходящий файл. `<picture>` используют, когда нужно дополнительно менять композицию изображения или предлагать разные форматы.

`width` и `height` помогают браузеру заранее зарезервировать место и уменьшить layout shift. `alt` передаёт смысл или функцию изображения в текущем контексте. Изображение первого экрана, особенно вероятный LCP, не следует lazy-loadить; `loading="lazy"` подходит изображениям ниже первого экрана.

## Карта темы

| Механизм | Что сообщает браузеру | Когда нужен |
| --- | --- | --- |
| `src` | URL одного изображения | обязателен только если у `<img>` нет `srcset`; при наличии `srcset` может отсутствовать |
| `srcset` с `w` | варианты разной ширины в пикселях | когда CSS-размер изображения меняется |
| `sizes` | ожидаемую ширину изображения в layout | вместе с width descriptors |
| `srcset` с `x` | варианты разной pixel density | когда CSS-размер фиксирован, а различается плотность |
| `<picture><source>` | дополнительные условия выбора | для art direction или разных форматов |
| `width` / `height` | размеры и preferred aspect ratio | чтобы заранее зарезервировать место |
| `alt` | текстовую альтернативу | для смысла или функции изображения |
| `loading="lazy"` | возможность отложить загрузку | для некритичных изображений вне первого экрана |
| `fetchpriority` | подсказку сетевого приоритета | точечно для действительно важного ресурса |

## Как браузер выбирает изображение

При width descriptors `srcset` содержит варианты разной intrinsic width:

```html
<img
  src="/product-800.jpg"
  srcset="/product-400.jpg 400w, /product-800.jpg 800w, /product-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 600px"
  alt="Красное кресло"
>
```

`sizes` не перечисляет размеры файлов. Он сообщает расчётную ширину изображения (source size) в layout для подходящего media condition. Браузер сопоставляет эту ширину с плотностью экрана (`devicePixelRatio`) и выбирает подходящий файл из `srcset`.

Если фактическая карточка имеет ширину 400 CSS-пикселей, а `sizes` ошибочно сообщает `100vw` на широком экране, браузер может выбрать файл заметно больше необходимого.

Descriptors `1x`, `2x` подходят для случая, когда CSS-размер изображения известен, а варианты отличаются только плотностью:

```html
<img
  src="/avatar.png"
  srcset="/avatar.png 1x, /avatar@2x.png 2x"
  width="64"
  height="64"
  alt="Анна"
>
```

В одном `srcset` не смешивают `w` и `x` descriptors.

## `<picture>`: art direction и форматы

`<picture>` даёт несколько `source` перед обязательным `img`. Браузер проверяет `source` сверху вниз и выбирает первый, у которого подходит `media` и поддерживается указанный `type`.

Art direction нужен, когда на разных экранах должна меняться сама композиция изображения, а не только его разрешение. Например, desktop может показывать широкий кадр команды, а mobile — более крупный crop с людьми в центре.

```html
<picture>
  <source
    media="(max-width: 640px)"
    type="image/avif"
    srcset="/team-mobile-480.avif 480w, /team-mobile-800.avif 800w"
    sizes="100vw"
    width="800"
    height="800"
  >
  <source
    type="image/avif"
    srcset="/team-wide-960.avif 960w, /team-wide-1440.avif 1440w"
    sizes="(max-width: 1200px) 100vw, 1200px"
    width="1200"
    height="675"
  >
  <img
    src="/team-wide-960.jpg"
    width="1200"
    height="675"
    alt="Команда разработки обсуждает макет интерфейса"
  >
</picture>
```

`source` внутри `picture` может иметь собственные `width` и `height`. Если art direction использует изображения с разным соотношением сторон, эти размеры позволяют выбранному `source` задать соответствующие размеры и aspect ratio для `img`.

Если меняется только разрешение одного и того же кадра, обычно достаточно одного `<img>` с `srcset` и `sizes`.

## Геометрия и layout shift

`width` и `height` на `img` позволяют браузеру определить preferred aspect ratio до загрузки файла. Responsive CSS может менять фактическую ширину:

```css
img {
  max-width: 100%;
  height: auto;
}
```

При этом браузер уже знает пропорции и может заранее зарезервировать место.

Размеры помогают только тогда, когда соответствуют выбранному изображению. Если файл имеет другое соотношение сторон, зарезервированная геометрия окажется неверной. Для art direction с разными пропорциями можно задавать размеры на соответствующих `source`.

## `alt` и смысл изображения

`alt` описывает не всё, что физически видно на картинке, а информацию или функцию, которую изображение выполняет в текущем контексте.

Примеры:

- содержательное фото получает краткий текст, передающий нужный смысл;
- изображение внутри ссылки может описывать цель действия, например `alt="На главную"`;
- график требует передать существенный вывод или данные в доступной форме;
- декоративный `<img>` получает `alt=""`, чтобы не создавать лишнюю информацию для screen reader.

`figcaption` подписывает `figure` для всех пользователей. Он может дополнять изображение, но не автоматически заменяет подходящий `alt`: эти элементы выполняют разные функции.

## Загрузка и приоритет

`loading="lazy"` разрешает браузеру отложить загрузку изображения, пока оно не приблизится к viewport. Точная дистанция остаётся эвристикой браузера.

```html
<img
  src="/gallery-12.webp"
  width="800"
  height="600"
  loading="lazy"
  alt="Интерфейс отчёта"
>
```

Изображение, которое видно при первоначальной загрузке, обычно оставляют eager. Вероятный LCP image не следует lazy-loadить: это откладывает начало запроса до момента, когда браузер сможет подтвердить его положение в layout.

Для важного изображения можно точечно использовать:

```html
<img
  src="/hero.webp"
  width="1200"
  height="640"
  fetchpriority="high"
  alt="Панель управления заказами"
>
```

`fetchpriority="high"` является подсказкой, а не гарантией. Если назначить высокий приоритет множеству ресурсов, они начнут конкурировать друг с другом.

Содержательное изображение лучше выражать через `<img>`, когда это возможно. CSS background не имеет `alt` и обычно обнаруживается только после получения и разбора соответствующих стилей.

## Где применяется во frontend

- В карточках товаров и каталогах: `srcset` и `sizes` помогают не скачивать desktop-изображение для маленькой mobile-карточки.
- В hero-блоках: важное изображение должно обнаруживаться рано и не использовать `loading="lazy"`.
- В адаптивном дизайне: `<picture>` позволяет менять crop или формат без JavaScript.
- При борьбе с CLS: корректные `width` и `height` резервируют место до загрузки файла.
- В доступности: `alt` передаёт смысл содержательного изображения, а декоративное исключается пустым `alt`.
- В длинных лентах и галереях: `loading="lazy"` экономит загрузку изображений, которые пользователь может не увидеть.

## Ключевые уточнения

- `srcset` перечисляет варианты файлов, а `sizes` сообщает ожидаемую ширину изображения в layout.
- Width descriptors и density descriptors решают разные задачи и не смешиваются в одном `srcset`.
- `<picture>` нужен для art direction или выбора формата, а не как обязательная оболочка каждого responsive image.
- `source` внутри `picture` может задавать собственные `width` и `height`, что полезно при разных aspect ratios.
- `alt` передаёт функцию или смысл изображения в контексте, а не механическое описание всех деталей.
- LCP image не следует lazy-loadить; `fetchpriority="high"` используют точечно, когда повышенный приоритет действительно нужен.
- Размеры уменьшают layout shift только при соответствии реальному соотношению сторон выбранного изображения.
