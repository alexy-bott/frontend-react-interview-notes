## Быстрый ответ

Реактивность Vue связывает чтение состояния с кодом, который от него зависит. Когда render effect, `computed`, `watchEffect` или watcher читает реактивное значение, Vue регистрирует зависимость; при изменении значения связанные эффекты помечаются для повторного выполнения или ставятся в scheduler.

Во Vue 3 `reactive()` создаёт Proxy для объектов, а `ref()` возвращает контейнер с реактивным свойством `.value`. `computed` описывает кешируемое производное значение, `watch` запускает побочный эффект по явно заданному источнику, `watchEffect` собирает зависимости из синхронных чтений callback. DOM updates батчатся, поэтому для чтения уже обновлённого DOM используют `nextTick()` или post-flush watcher.

## Ключевая схема

```text
effect выполняется
-> читает reactive/ref
-> Vue регистрирует dependency
-> значение изменяется
-> dependency trigger
-> scheduler объединяет jobs
-> render/patch или watcher callback
```

| API | Назначение | Существенная граница |
| --- | --- | --- |
| `ref` | реактивная ссылка на заменяемое значение | в JS используется `.value` |
| `reactive` | глубокий reactive Proxy объекта | возвращённый Proxy имеет другую identity |
| `computed` | производное кешируемое значение | getter должен оставаться без побочных эффектов |
| `watch` | эффект по явному source | по умолчанию callback не запускается сразу |
| `watchEffect` | эффект с автоматическим tracking | зависимости менее явны и собираются синхронно |
| `nextTick` | ожидание следующего DOM flush | не означает новый macrotask по контракту приложения |

## Базовая модель

Каждый экземпляр компонента создаёт reactive effect для render. Во время render Vue видит, какие refs и reactive properties были прочитаны. Изменение неиспользуемого свойства не обязано обновлять компонент; изменение прочитанной зависимости планирует новый render и patch.

`ref` подходит примитиву и объекту. Если объект передан обычному `ref`, Vue глубоко преобразует его через `reactive`; `shallowRef` отслеживает только замену `.value` и полезен для внешнего immutable state или крупных объектов, которыми управляет другая система. `reactive` удобен для объекта со стабильной identity, но заменить всю переменную новым raw object без ref нельзя с сохранением прежних подписок.

`computed` лениво вычисляется при чтении и кеширует результат до изменения зависимости. Если значение можно выразить из другого state без побочного эффекта, computed точнее watcher: оно описывает данные, а не последовательность команд.

## Развернутый ответ

**`watch`.** Source может быть ref, reactive object, getter или массив sources. `watch(reactiveObject, callback)` создаёт глубокое наблюдение за вложенными мутациями. Getter вроде `() => state.user` по умолчанию срабатывает при замене возвращаемого объекта; для вложенных изменений задают `deep` либо наблюдают точное поле. Глубокий обход крупной структуры имеет стоимость.

**`watchEffect`.** Callback выполняется сразу и автоматически подписывается на реактивные значения, прочитанные синхронно. В async callback чтения после первого `await` не попадают в начальный dependency tracking. Для сложного эффекта явный `watch` обычно легче анализировать и отменять.

**Порядок DOM update.** Несколько синхронных записей объединяются в один flush, чтобы компонент не patch-ился после каждой строки. По умолчанию watcher callback запускается до DOM update своего owner component, но после update родителя. `flush: "post"` нужен для чтения DOM после patch, `flush: "sync"` отключает batching для callback и используется редко из-за риска множества вызовов.

**Деструктурирование.** Локальная переменная, полученная через `const { count } = reactiveState`, содержит текущее значение и больше не выполняет Proxy `get`; дальнейшие изменения не отслеживаются через неё. `toRef`/`toRefs` создают связанные refs. Это ограничение относится к извлечённому property, а вложенный объект, уже ставший Proxy, сохраняет собственную реактивность.

**Identity.** `reactive(raw) !== raw`. Map или Set, где raw object используется как key, не найдёт Proxy по той же ссылке. Лучше последовательно использовать reactive-версию или стабильный примитивный id, а `toRaw` оставлять кратким escape hatch, не постоянной моделью хранения.

## Пример

```vue
<script setup lang="ts">
import { computed, nextTick, ref, watch } from "vue";
import { loadUsers } from "./users-api";
import type { User } from "./types";

const query = ref("");
const users = ref<User[]>([]);

const normalizedQuery = computed(() => query.value.trim().toLowerCase());
const visibleUsers = computed(() =>
  users.value.filter((user) =>
    user.name.toLowerCase().includes(normalizedQuery.value),
  ),
);

watch(query, async (nextQuery, _previousQuery, onCleanup) => {
  const controller = new AbortController();
  onCleanup(() => controller.abort());

  users.value = await loadUsers(nextQuery, controller.signal);
});

async function clearSearch() {
  query.value = "";
  await nextTick();
  // DOM теперь отражает очищенный query и новый visibleUsers.
}
</script>
```

Computed values описывают чистые преобразования, а watcher выполняет отменяемый внешний запрос. Реальный код дополнительно обрабатывает ошибку и не обязан отправлять запрос для каждого символа без debounce.

## Ключевые уточнения

- `ref` не ограничен примитивами; он также даёт стабильный контейнер для заменяемого объекта.
- `computed` хранит производное значение, а `watch` выполняет побочный эффект. Замена computed на watcher часто создаёт лишний state.
- Deep watch зависит от формы source: reactive object наблюдается глубоко, getter - нет без дополнительной настройки.
- `watchEffect` отслеживает только реактивные чтения во время синхронной части выполнения callback.
- Изменение state синхронно, а DOM patch планируется scheduler; `nextTick` ждёт завершения соответствующего flush.
