## Быстрый ответ

Portal позволяет отрисовать React children в другом DOM-контейнере через `createPortal(children, domNode)`. Компонент остаётся на прежнем месте в React tree: продолжает получать context, а React-события всплывают к React-родителям. Меняется только физическое положение созданных DOM-узлов.

Portal используют для dialog, tooltip, dropdown и toast, когда overlay нужно вынести из контейнера с `overflow`, локальным stacking context или неподходящей DOM-структурой. Portal решает размещение, но не поведение overlay: focus management, клавиатура, ARIA-семантика, блокировка фона и scroll остаются ответственностью компонента или готовой headless-библиотеки.

## Ключевая схема

| Аспект | Поведение Portal |
| --- | --- |
| API | `createPortal(children, domNode, key?)` из `react-dom` |
| DOM tree | children вставляются в указанный `domNode` |
| React tree | логический родитель, context и state сохраняются |
| События React | всплывают по React tree, а не по физическому DOM tree |
| CSS | selectors и наследование зависят от реального DOM-положения |
| SSR | DOM-контейнер доступен только на клиенте |

## Базовая модель

Обычный компонент создаёт DOM внутри контейнера своего DOM-родителя. Portal возвращается из render так же, как React element, но React помещает его children в другой существующий DOM-узел, например `#portal-root` рядом с корнем приложения.

Логические отношения не меняются. Компонент внутри portal читает Provider, расположенный выше в React tree, и его click может дойти до React `onClick` логического родителя. При этом CSS работает по DOM: selector вроде `.card .dialog` перестанет совпадать, если dialog физически находится вне `.card`.

## Развернутый ответ

### Какие проблемы решает Portal

`overflow: hidden` или `overflow: auto` может обрезать overlay. `transform`, `filter`, `opacity` и некоторые другие свойства создают stacking context, внутри которого большой `z-index` не позволяет перекрыть элементы из другого контекста. Перенос overlay в общий верхнеуровневый контейнер убирает зависимость от этих предков.

Portal не отменяет CSS-правила. Если сам `portal-root` находится внутри обрезающего контейнера или неподходящего stacking context, проблема сохранится. Контейнер выбирают осознанно, обычно рядом с основным root или внутри `body`.

### React events и DOM events

Событие физически возникает в DOM-узле portal, но синтетическое событие React продолжает всплывать по React tree. Поэтому `onClick` логического родителя может выполниться, хотя в DOM он не является предком overlay.

Если это нежелательно, propagation останавливают внутри portal или меняют расположение обработчика в React tree. Native listener, установленный через `addEventListener`, следует обычному DOM event path, поэтому эти две модели нельзя смешивать в одном объяснении.

### Доступность overlay

Для modal dialog нужны как минимум доступное имя, `role="dialog"`, `aria-modal="true"`, перенос focus внутрь, закрытие по Escape, возврат focus к инициатору и запрет взаимодействия с фоном. Для сложного содержимого также нужен надёжный focus trap. Блокировка scroll не должна ломать положение страницы после закрытия.

`createPortal` ничего из этого не добавляет. В production чаще используют Radix UI Dialog или другую проверенную headless-реализацию, а Portal остаётся её инфраструктурной частью.

### SSR и hydration

На сервере нет `document`, поэтому контейнер нельзя искать на верхнем уровне модуля или во время server render. Безопасная модель: первоначально вернуть тот же результат на сервере и первом client render, затем получить DOM-контейнер в Effect и создать portal.

Передача другого `domNode` при обновлении пересоздаёт содержимое portal. Поэтому контейнер должен быть стабильным и существовать всё время жизни overlay.

## Пример

Пример показывает Portal и базовые требования modal: имя, перенос и возврат focus, Escape, блокировку фонового root и scroll. Для сложного dialog с динамическим набором элементов лучше использовать готовый focus-management primitive.

```tsx
import { type ReactNode, useEffect, useId, useRef, useState } from "react";
import { createPortal } from "react-dom";

type ModalProps = {
  open: boolean;
  title: string;
  onClose: () => void;
  children: ReactNode;
};

export function Modal({ open, title, onClose, children }: ModalProps) {
  const [portalRoot, setPortalRoot] = useState<HTMLElement | null>(null);
  const dialogRef = useRef<HTMLDivElement>(null);
  const titleId = useId();

  useEffect(() => {
    setPortalRoot(document.getElementById("portal-root"));
  }, []);

  useEffect(() => {
    if (!open || !portalRoot) return;

    const previousFocus = document.activeElement as HTMLElement | null;
    const appRoot = document.getElementById("app-root");
    const previousOverflow = document.body.style.overflow;

    appRoot?.setAttribute("inert", "");
    document.body.style.overflow = "hidden";
    dialogRef.current?.focus();

    return () => {
      appRoot?.removeAttribute("inert");
      document.body.style.overflow = previousOverflow;
      previousFocus?.focus();
    };
  }, [open, portalRoot]);

  useEffect(() => {
    if (!open) return;

    function handleKeyDown(event: KeyboardEvent) {
      if (event.key === "Escape") onClose();
    }

    document.addEventListener("keydown", handleKeyDown);
    return () => document.removeEventListener("keydown", handleKeyDown);
  }, [open, onClose]);

  if (!open || !portalRoot) return null;

  return createPortal(
    <div className="modal-backdrop">
      <div
        ref={dialogRef}
        role="dialog"
        aria-modal="true"
        aria-labelledby={titleId}
        tabIndex={-1}
      >
        <h2 id={titleId}>{title}</h2>
        {children}
        <button type="button" onClick={onClose}>Close</button>
      </div>
    </div>,
    portalRoot
  );
}
```

HTML должен содержать независимые контейнеры `#app-root` и `#portal-root`. Первый временно получает `inert`, поэтому фон исключается из focus и взаимодействия; второй остаётся доступен для dialog.

## Где применяется во frontend

| Ситуация | Зачем нужен Portal | Что дополнительно требуется |
| --- | --- | --- |
| Modal dialog | вынести overlay из layout и stacking contexts | focus, Escape, inert background, scroll lock |
| Tooltip | избежать clipping | позиционирование, accessible description и правила показа |
| Dropdown menu | перекрыть соседние контейнеры | keyboard navigation, focus и collision handling |
| Toast region | общий слой уведомлений | live region, порядок и управление временем показа |
| Embedded widget | выбрать контейнер вне локального root | явная DOM-граница и стили для нового расположения |

## Ключевые уточнения

- Portal меняет DOM-положение, но сохраняет принадлежность к React tree и доступ к context.
- React-события всплывают по React tree; native listeners используют DOM event path.
- CSS inheritance и selectors следуют физическому DOM, поэтому стили предка могут перестать действовать.
- Portal устраняет clipping только относительно предков выбранного DOM-контейнера.
- Доступность modal не входит в `createPortal`; её реализует dialog-компонент или библиотека.
