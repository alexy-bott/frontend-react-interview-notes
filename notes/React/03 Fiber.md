## Быстрый ответ

Fiber - это внутренняя архитектура React, которая представляет работу по обновлению UI как дерево маленьких единиц работы. До Fiber рендеринг был ближе к рекурсивному обходу дерева: React начинал вычислять обновление и должен был пройти его синхронно до конца. Fiber позволяет React хранить работу в виде объектов, разбивать её на части, назначать приоритеты, прерывать, возобновлять или отбрасывать незавершённый render, если пришло более важное обновление.

Fiber стоит понимать не как публичный API, а как основу современных возможностей React: concurrent rendering, transitions, Suspense, Error Boundaries, более гибкое планирование и разделение render/commit. Fiber не меняет декларативную модель для разработчика: мы всё ещё описываем UI как функцию от state/props. Но внутри React получает больше контроля над тем, когда и какую работу выполнять.

## Ключевая схема

```text
update
-> create work-in-progress fiber tree
-> render phase: process fibers, can be interrupted
-> complete work
-> commit phase: apply DOM mutations synchronously
```

| Понятие | Что означает |
| --- | --- |
| Fiber node | объект, который описывает компонент/DOM-узел и работу по нему |
| Fiber tree | внутреннее дерево React для текущего UI |
| current tree | уже показанное пользователю дерево |
| work-in-progress tree | дерево, которое React готовит для следующего UI |
| render phase | вычисление следующего дерева; concurrent render может быть прерван |
| commit phase | применение подготовленных изменений к host-среде |
| priority | важность обновления для планировщика |

## Развернутый ответ

До Fiber React был ближе к синхронному рекурсивному обходу: если обновление началось, React должен был пройти дерево до конца, прежде чем пользователь увидит результат. Fiber меняет представление работы: каждый компонент или host node соответствует fiber node, а всё дерево можно обходить как набор маленьких units of work.

В React одновременно важны два дерева. `current tree` - то, что уже committed и соответствует UI на экране. `work-in-progress tree` - следующая версия UI, которую React готовит во время render phase. Пока work-in-progress не committed, пользователь его не видит, поэтому React может прервать эту работу, пересчитать её с новыми props/state или отбросить устаревший render.

Приоритеты нужны, чтобы React не относился ко всем обновлениям одинаково. Ввод текста, клик и фокус должны быть отзывчивыми; тяжёлый список результатов или переход вкладки может быть менее срочным. В современных версиях React это проявляется через transitions, deferred values, Suspense и работу Scheduler. Fiber не убирает стоимость render, но позволяет React распределять её во времени.

Commit phase устроена иначе. Когда React уже подготовил итоговые изменения, он должен применить их к DOM согласованно: DOM mutations, refs, layout effects. Если прервать commit посередине, UI мог бы оказаться в неконсистентном состоянии. Поэтому прерываемой делают render phase, а не commit phase.

**Fiber - это Virtual DOM?**

Нет. Virtual DOM - это общее описание идеи: React хранит легковесное представление UI и сравнивает его между обновлениями. Fiber - конкретная внутренняя архитектура reconciler, которая хранит дерево работы и позволяет планировать обновления. Можно сказать так: Virtual DOM отвечает на вопрос “что сравниваем”, Fiber - “как организуем и планируем работу”.

**Что такое fiber node?**

Fiber node - это JavaScript-объект с информацией о конкретной части дерева: тип компонента, key, props, state, ссылки на child/sibling/parent, флаги подготовленной работы и связь с альтернативным fiber. Это похоже на stack frame, который React может держать в памяти и продолжать позже.

**Прерываемость render phase**

Render phase только вычисляет следующий UI и список изменений. Пока React не дошёл до commit, пользователь ещё не видит результат. Поэтому React может остановить эту работу, дать приоритет вводу пользователя или отбросить устаревший render.

**Непрерываемость commit phase**

Commit phase применяет изменения к DOM и запускает layout effects. Если прервать commit посередине, пользователь мог бы увидеть неконсистентный UI. Поэтому commit выполняется синхронно и атомарно относительно подготовленного результата.

**Fiber и `key`**

Во время reconciliation React решает, можно ли переиспользовать старый fiber для нового элемента. `type` и `key` помогают понять идентичность узла. Если key нестабилен, React менее точно сопоставляет элементы, может пересоздавать fibers и терять состояние.

**Нужно ли разработчику знать поля fiber?**

Обычно нет. В production-коде нельзя опираться на внутренние поля React. Практический уровень понимания: tree, unit of work, priority, render/commit, current/work-in-progress.

## Пример

Если пользователь печатает в input, а рядом рендерится тяжёлый список, React должен быстро отреагировать на ввод. Благодаря Fiber React может начать рендерить список, затем прерваться ради более срочного обновления input, а потом продолжить или пересчитать список уже по новому значению. Пользователь не должен ждать, пока тяжёлый render полностью закончится, чтобы увидеть символ в поле.

Fiber делает render phase планируемой, но не делает тяжёлые вычисления бесплатными. Concurrent rendering означает, что render может быть начат, прерван, повторён или отброшен. Поэтому render должен быть чистым: без side effects, запросов, мутаций DOM и записи во внешнее состояние.

Commit phase остаётся синхронной: DOM-мутации и layout effects применяются после завершения render. `StrictMode` в dev помогает находить код, который не выдерживает повторного render/effect lifecycle. Fiber - implementation detail: знать концепцию полезно, полагаться на внутренние поля нельзя.

## Ключевые уточнения

- Fiber является внутренней архитектурой reconciler, а не публичным API приложения.
- Fiber даёт React возможность планировать работу, но не уменьшает автоматически стоимость тяжёлого вычисления.
- Прерываемость относится к concurrent render; обычное обновление React 18 не обязано прерываться.
- Render компонента, commit DOM и browser paint являются разными этапами.
- Чистый render необходим, потому что незавершённая работа может быть повторена или отброшена.
