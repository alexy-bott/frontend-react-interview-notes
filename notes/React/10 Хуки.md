## Быстрый ответ

Hooks - функции React, через которые function components используют state, context, refs, Effects и другие возможности React без class component. Hook вызывается только во время render React-компонента или другого Hook и на верхнем уровне функции. Это позволяет React сохранять state между renders и сопоставлять внутренние данные с последовательностью вызовов.

Hook выбирают по задаче: `useState` и `useReducer` хранят состояние, `useContext` читает context, `useRef` сохраняет изменяемое значение без render, `useEffect` и `useLayoutEffect` синхронизируют компонент с внешними системами, а `useMemo` и `useCallback` являются оптимизациями. Custom Hook объединяет повторяемую логику, но каждый его вызов получает собственные state и Effects.

## Ключевая схема

| Категория | Hooks React 18 | Задача |
| --- | --- | --- |
| State | `useState`, `useReducer` | хранить snapshot и описывать переходы состояния |
| Context | `useContext` | читать значение ближайшего Provider |
| Ref | `useRef`, `useImperativeHandle` | хранить DOM-ссылку или mutable value вне render-данных |
| Effects | `useEffect`, `useLayoutEffect`, `useInsertionEffect` | синхронизироваться с внешней системой на нужном этапе commit |
| Производительность | `useMemo`, `useCallback` | кешировать значение или ссылку на функцию при доказанной необходимости |
| Concurrent UI | `useTransition`, `useDeferredValue` | отделить срочное обновление от несрочной render work |
| Внешние stores | `useSyncExternalStore` | безопасно подписаться на snapshot внешнего источника |
| Идентификаторы | `useId` | создать стабильный ID для accessibility и SSR, но не для list keys |
| Отладка custom Hooks | `useDebugValue` | показать полезную подпись в React DevTools |

## Базовая модель

При каждом render функция компонента выполняется заново. Локальные переменные создаются заново, но React хранит данные Hooks отдельно и возвращает нужный state или ref для текущей позиции вызова. Поэтому порядок вызовов должен оставаться одинаковым между renders.

Публичная модель проста:

1. компонент вызывает Hooks на верхнем уровне;
2. React возвращает state, ref, context или регистрирует Effect;
3. компонент вычисляет JSX;
4. Effects выполняются только после commit согласно своему типу.

Внутри React данные Hooks связаны с Fiber компонента и последовательностью вызовов. Эта деталь объясняет правило порядка, но для выбора Hook важнее его публичный контракт.

## Развернутый ответ

### State Hooks

`useState` подходит для независимого значения и простых обновлений. `useReducer` полезен, когда несколько событий изменяют связанную структуру state и переходы удобнее описать через actions и одну reducer-функцию. Оба Hook возвращают snapshot текущего render; setter или `dispatch` ставит обновление в очередь.

Reducer не делает state глобальным и не заменяет Redux автоматически. Он только переносит вычисление следующего локального state в отдельную чистую функцию.

### Effects и refs

Effect нужен для синхронизации с системой вне React: подпиской, browser API, сторонним widget или сетью. Вычисление значения из props/state и обработка конкретного клика обычно выполняются без Effect.

`useRef` возвращает стабильный объект с полем `current`. Изменение `current` не запрашивает render, поэтому ref подходит для DOM-узла, timer ID или другого mutable value, который не определяет UI. Если изменение должно отобразиться на экране, используется state.

### Мемоизация

`useMemo` кеширует результат вычисления, а `useCallback` - ссылку на функцию. Оба Hook сравнивают dependencies через `Object.is` и не нужны для корректности обычного компонента. Их добавляют, когда измерение показало дорогой повторный расчёт, когда стабильность значения нужна memoized-потомку или когда она является частью контракта другого Hook.

Кеш React может отбросить по причинам, описанным API, поэтому `useMemo` нельзя использовать как постоянное хранилище данных. Для такого значения подходит state или ref.

### Custom Hooks

Custom Hook - функция с именем, начинающимся с `use`, которая вызывает другие Hooks. Он переиспользует stateful-логику и скрывает детали подписки или синхронизации за понятным контрактом.

Два компонента, вызвавшие один `useOnlineStatus`, не получают общий state автоматически. Каждый вызов регистрирует собственный набор Hooks. Общими могут быть только данные внешнего источника, к которому оба экземпляра подписались.

### Специализированные Hooks React 18

`useTransition` и `useDeferredValue` используют concurrent-возможности React 18 для несрочной render work. `useSyncExternalStore` задаёт корректный контракт подписки на внешний store. `useId` создаёт согласованные client/server ID для связей `label` и `input`; он не генерирует `key` для списка. `useInsertionEffect` предназначен прежде всего для CSS-in-JS библиотек и редко нужен прикладному компоненту.

## Версии

Базовая версия этой карточки - React 18. `useActionState`, `useOptimistic`, `useFormStatus` и `use` относятся к React 19 и не включены в основной набор React 18. `useEffectEvent` появился позже и разобран отдельно в [useEffectEvent](<./35 useEffectEvent.md>). Версионные отличия собраны в [React 18 и 19](<./32 React 18 и 19.md>).

## Пример

Custom Hook объединяет state и Effect подписки на browser events. Пример выполняется в браузере.

```tsx
import { useEffect, useState } from "react";

function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(() => navigator.onLine);

  useEffect(() => {
    function updateStatus() {
      setIsOnline(navigator.onLine);
    }

    window.addEventListener("online", updateStatus);
    window.addEventListener("offline", updateStatus);

    return () => {
      window.removeEventListener("online", updateStatus);
      window.removeEventListener("offline", updateStatus);
    };
  }, []);

  return isOnline;
}

export default function SaveButton() {
  const isOnline = useOnlineStatus();

  return (
    <button disabled={!isOnline}>
      {isOnline ? "Save" : "Waiting for connection"}
    </button>
  );
}
```

`useOnlineStatus` вызывается на верхнем уровне. State определяет текст и доступность кнопки, Effect подписывается на внешнюю систему браузера, а cleanup удаляет обработчики. Повторный setup/cleanup в Strict Mode не создаёт утечку, потому что обе подписки симметрично удаляются.

## Где применяется во frontend

| Задача | Инструмент | Почему |
| --- | --- | --- |
| Открытие модального окна | `useState` | простое локальное UI state |
| Сложные переходы wizard | `useReducer` | actions и допустимые переходы собраны в одном месте |
| Подписка на WebSocket | custom Hook + `useEffect` | компонент получает простой контракт и корректный cleanup |
| Фокус input | `useRef` | нужен доступ к DOM без хранения узла в state |
| Дорогая фильтрация | `useMemo` после измерения | повторный расчёт можно пропустить при тех же dependencies |
| Большой список при вводе | `useDeferredValue` или `useTransition` | ввод остаётся срочным, список обновляется как несрочная работа |
| Подписка библиотеки состояния | `useSyncExternalStore` | store согласуется с моделью concurrent rendering |

## Ключевые уточнения

- Hooks вызываются во время render только из function component или custom Hook и в стабильном порядке.
- Custom Hook переиспользует логику, но не создаёт общее состояние между своими вызовами.
- Ref хранит значение вне render-данных; изменение UI должно идти через state.
- `useMemo` и `useCallback` являются оптимизациями, а не обязательной частью каждого компонента.
- React 19 Hooks не относятся к базовому ответу про React 18 и должны быть явно помечены по версии.
