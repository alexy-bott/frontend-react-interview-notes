# Поднятие объявлений (hoisting) и TDZ

## Быстрый ответ

Hoisting - разговорное название наблюдаемого поведения, при котором объявления учитываются до пошагового выполнения кода в своей области видимости. Движок не переносит строки исходника вверх: при подготовке контекста выполнения он заранее создаёт привязки имён для объявлений.

Function declaration обычно создаётся сразу вместе с функцией, `var` создаётся и инициализируется `undefined`, а `let`, `const` и `class` создаются неинициализированными. Участок до их инициализации называется temporal dead zone (TDZ): обращение в нём приводит к `ReferenceError`.

## Ключевая схема

| Конструкция | До строки объявления |
| --- | --- |
| `function declaration` | можно вызвать |
| `var` | доступна как `undefined` |
| `let` | `ReferenceError` из-за TDZ |
| `const` | `ReferenceError` из-за TDZ |
| `class declaration` | `ReferenceError` из-за TDZ |
| `function expression` в `var` | переменная `undefined`, вызвать нельзя |

## Базовая модель

Execution context, или контекст выполнения, - внутренняя структура для выполнения скрипта, модуля или функции. В упрощённой модели его окружение связывает имена со значениями и хранит ссылку на внешнюю область. До выполнения операторов JavaScript создаёт привязки для объявлений текущей области, а затем выполняет код по порядку.

Привязка может существовать без доступного значения. Именно это происходит с объявлениями `let`, `const` и `class` в TDZ. Поэтому hoisting лучше объяснять через создание и инициализацию привязок, а не через физическое перемещение объявлений.

## Развернутый ответ

### Function declaration и function expression

Function declaration (объявление функции) инициализируется объектом функции при создании области, поэтому её можно вызвать раньше текстового объявления. Function expression (функциональное выражение) является обычным выражением: момент доступности зависит от переменной, в которую записывается результат.

Если expression присваивается в `var`, до строки присваивания переменная содержит `undefined`, и попытка вызова даёт `TypeError`. Если используется `let` или `const`, чтение самой переменной в TDZ даёт `ReferenceError`.

### TDZ и смысл ограничения

TDZ не означает, что привязка отсутствует. Она уже участвует в разрешении имени и скрывает внешнюю переменную, но прочитать её до инициализации нельзя. Запрет не позволяет коду получить случайное `undefined` до установки обязательного начального значения.

Даже `typeof` не обходит TDZ: `typeof missingName` возвращает `"undefined"` для необъявленного имени, но `typeof value` до локального `let value` бросает `ReferenceError`.

### Область видимости определяет границу подготовки

`var` создаётся для всей функции или скрипта. `let`, `const` и `class` создаются для ближайшей лексической области, например блока. Function declaration относится к своей области, но объявления функций внутри блоков в старых скриптах без strict mode имеют особые правила совместимости. Базовую модель лучше разбирать на объявлении функции на уровне функции или модуля.

## Пример

```js
console.log(a); // undefined
var a = 1;

console.log(b); // ReferenceError
let b = 2;

sayHi(); // "hi"
function sayHi() {
  console.log("hi");
}

sayBye(); // TypeError: sayBye is not a function
var sayBye = function () {
  console.log("bye");
};

{
  console.log(typeof value); // ReferenceError из-за TDZ
  let value = 1;
}
```

## Где применяется во frontend

Hoisting и TDZ объясняют ошибки инициализации модулей, затенение имён (shadowing) внутри блоков, различие function declaration и function expression, а также поведение старого кода с `var`. Это модель разрешения имён, а не рекомендация намеренно вызывать функции и читать переменные до объявления.

## Ключевые уточнения

- Hoisting не перемещает исходный код; разные объявления по-разному создаются и инициализируются перед выполнением операторов.
- Function declaration доступна раньше своей строки, потому что привязка сразу получает функцию.
- `var` до присваивания содержит `undefined`, поэтому вызов функционального выражения через `var` приводит к `TypeError`.
- `let`, `const` и `class` существуют в области, но недоступны в TDZ до инициализации.
- `typeof` безопасен для необъявленного имени, но не для лексической привязки в TDZ.
