## Быстрый ответ

Функции в JavaScript являются значениями первого класса (`first-class values`): их можно хранить, передавать и возвращать. Функция высшего порядка (`higher-order function`, HOF) принимает функцию, возвращает функцию или делает и то и другое. На этом основаны callback-функции, методы массивов, middleware, декораторы и фабрики хуков.

Частичное применение (`partial application`) заранее фиксирует часть аргументов функции. Каррирование (`currying`) преобразует функцию нескольких аргументов в последовательность функций по одному аргументу. Композиция соединяет функции так, чтобы результат одной стал входным значением следующей.

Эти приёмы полезны, когда уменьшают повторение и явно собирают поведение. Избыточные обёртки, каррирование ради стиля и длинные цепочки без явных параметров ухудшают стек ошибок, вывод типов и читаемость.

IIFE - функциональное выражение, которое вызывается сразу после создания. Раньше оно создавало закрытую область видимости функции в классических скриптах; в современном коде эту задачу чаще решают блочная область и ES modules.

## Ключевая схема

```text
функция как значение первого класса
├─ передать как callback-функцию
├─ вернуть настроенную функцию
└─ сохранить как значение

partial:  f(a, b, c) → g(b, c), где a уже задан
currying: f(a, b, c) → f(a)(b)(c)
compose:  f(g(x))
pipe:     g(x) → f(result)
```

## Функция высшего порядка

```js
function withLogging(fn, logger) {
  return function logged(...args) {
    logger("start", args);

    try {
      const result = fn.apply(this, args);
      logger("success", result);
      return result;
    } catch (error) {
      logger("error", error);
      throw error;
    }
  };
}
```

`withLogging` принимает функцию и возвращает новую функцию, поэтому является HOF. Обёртка сохраняет объект-получатель и аргументы через `apply`, а синхронную ошибку повторно выбрасывает после логирования.

Для async function такой декоратор должен дождаться Promise, чтобы логировать его выполнение или отклонение, а не только сам созданный объект Promise:

```js
function withAsyncLogging(fn, logger) {
  return async function logged(...args) {
    logger("start", args);

    try {
      const result = await fn.apply(this, args);
      logger("success", result);
      return result;
    } catch (error) {
      logger("error", error);
      throw error;
    }
  };
}
```

Синхронный и асинхронный контракты нельзя смешивать одной обёрткой без ясного правила: добавление `async` всегда меняет возвращаемый тип на Promise.

## Callback-функции

Callback - функция, переданная другому коду для последующего вызова. Само слово ничего не говорит о времени выполнения:

```js
[1, 2, 3].map((value) => value * 2); // callback синхронный

setTimeout(() => {
  console.log("later");
}, 0); // callback в будущей задаче event loop
```

Нельзя считать любой callback асинхронным. Порядок и время вызова определяет контракт вызывающего API.

Callback может вызываться ноль, один или много раз, синхронно или позже, с конкретным `this` и правилами обработки ошибок. Публичная функция высшего порядка должна описывать эти свойства.

## Частичное применение

```js
function request(method, url, options) {
  return fetch(url, {
    ...options,
    method,
  });
}

const get = (url, options) => request("GET", url, options);
```

`get` фиксирует первый аргумент `method`. Сигнатура вызывающего кода становится короче и не позволяет случайно передать другой HTTP-метод.

Общий вариант через `bind`:

```js
const get = request.bind(null, "GET");
```

Явная обёртка часто лучше документирует имена параметров и позволяет преобразовать аргументы. `bind` полезен, когда нужно одновременно закрепить объект-получатель и начальные аргументы.

## Каррирование

```js
const multiply = (a) => (b) => a * b;

const double = multiply(2);
double(5); // 10
```

Каррирование превращает вызов `multiply(2, 5)` в `multiply(2)(5)`. Это удобно, если значения появляются по этапам или API ожидает callback-функции с одним аргументом.

```js
const hasRole = (role) => (user) => user.roles.includes(role);
const admins = users.filter(hasRole("admin"));
```

Обычное частичное применение также решило бы эту задачу. В JavaScript каррирование не является обязательной моделью языка; выбор должен быть оправдан читаемостью и соглашениями команды.

Автоматическое каррирование по `fn.length` ненадёжно для параметров по умолчанию, rest-параметров и необязательных аргументов. Для production-кода используют проверенную библиотеку или явные функции.

## Композиция и pipe

Композиция выполняется справа налево:

```js
const compose = (...functions) => (value) =>
  functions.reduceRight(
    (result, fn) => fn(result),
    value,
  );
```

Pipe слева направо:

```js
const pipe = (...functions) => (value) =>
  functions.reduce(
    (result, fn) => fn(result),
    value,
  );
```

```js
const normalizeName = pipe(
  (value) => value.trim(),
  (value) => value.toLocaleLowerCase("ru"),
);
```

Такая цепочка проста, если каждый шаг принимает одно значение, возвращает следующее и имеет понятный контракт.

Для асинхронных шагов обычного `pipe` недостаточно: результатом может стать Promise. Нужен отдельный асинхронный `pipe`, который последовательно ожидает каждый этап, либо явная async function с именованными промежуточными значениями.

```js
async function loadViewModel(id) {
  const user = await loadUser(id);
  const permissions = await loadPermissions(user);
  return createViewModel(user, permissions);
}
```

Явную последовательность часто легче отлаживать, чем универсальную абстракцию ради трёх шагов.

## Замыкание и фабрика

Возвращённая функция сохраняет привязки конфигурации:

```js
function createApiClient({ baseUrl, tokenProvider }) {
  return async function request(path, options = {}) {
    return fetch(`${baseUrl}${path}`, {
      ...options,
      headers: {
        Authorization: `Bearer ${tokenProvider()}`,
        ...options.headers,
      },
    });
  };
}
```

Токен читается при каждом вызове, а не фиксируется навсегда при создании. Это важный выбор: замыкание может сохранить снимок значения либо функцию для получения актуального значения.

Фабрика позволяет внедрить зависимости без класса. Но долгоживущая возвращённая функция удерживает окружение, поэтому большие временные данные не должны случайно попадать в замыкание.

## IIFE

```js
(function initialize() {
  const privateValue = 42;
  expose(privateValue);
})();
```

Функциональное выражение заключено в скобки, чтобы parser не воспринимал `function` как объявление, а затем сразу вызывается.

Async IIFE:

```js
void (async () => {
  try {
    await initializeApp();
  } catch (error) {
    reportError(error);
  }
})();
```

Возможное отклонение Promise должно быть обработано. В ES module верхнеуровневый `await` или обычная именованная async function часто читаются лучше.

Современная альтернатива IIFE, которое использовалось только ради отдельной области видимости:

```js
{
  const blockPrivate = 42;
}
```

Другой вариант - ES modules, которые дают область модуля и явные экспорты.

IIFE остаётся полезным внутри выражения, для одноразовой инициализации или старого скрипта, но не требуется вокруг каждого модуля.

## Идентичность функции

Каждый вызов обёртки или фабрики создаёт новый объект функции:

```js
withLogging(save, logger) !== withLogging(save, logger);
```

Это важно для `removeEventListener`, мемоизации, React props и API подписок. Если нужна стабильная идентичность, обёртку создают один раз на нужный жизненный цикл или кэшируют по понятному ключу.

Стабильная функция при этом может захватить устаревшие значения. Стабильность идентичности и актуальность данных являются отдельными задачами.

## Когда абстракция оправдана

HOF полезна, если единообразно добавляет определённое поведение: повтор запроса, авторизацию, метрики, мемоизацию или debounce. Она должна сохранять важный контракт исходной функции: `this`, аргументы, возвращаемое значение или отклонение Promise и отмену операции.

Отдельная именованная функция лучше, если абстракция:

- используется один раз;
- скрывает ветвления и побочные эффекты;
- создаёт сложные вложенные стеки ошибок;
- ухудшает вывод типов TypeScript;
- требует читать общую реализацию ради простого бизнес-сценария.

## Где применяется во frontend

- Методы массивов принимают синхронные callback-функции.
- Middleware и декораторы добавляют авторизацию, логирование или метрики вокруг операции.
- Фабрика фиксирует зависимости API-клиента.
- Частичное применение создаёт предметный обработчик из общей функции.
- `pipe` собирает небольшие чистые преобразования.
- IIFE изолирует инициализацию старого кода, когда модули недоступны.

## Ключевые уточнения

- HOF определяется тем, что принимает или возвращает функцию; callback при этом не обязательно асинхронный.
- Обёртка должна сохранять объект-получатель, аргументы, возвращаемое значение и правила обработки ошибок.
- Частичное применение фиксирует часть аргументов, а каррирование меняет форму вызова на цепочку функций с одним аргументом.
- Композиция удобна для небольших единообразных преобразований, но не должна скрывать сложный поток выполнения.
- Возвращённая функция хранит замыкание и может удерживать как функцию получения актуального значения, так и устаревший снимок.
- Каждая обёртка создаёт новую идентичность функции, что влияет на обработчики, мемоизацию и React.
- IIFE исторически создавало область функции; модули и блочная область часто являются современной заменой.
