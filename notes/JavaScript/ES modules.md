## Быстрый ответ

ES modules, или ESM, - стандартная модульная система JavaScript. `export` объявляет публичные значения модуля, а `import` создаёт явные зависимости между файлами.

Каждый модуль имеет собственную область видимости, автоматически выполняется в strict mode (строгом режиме), а `this` на верхнем уровне равен `undefined`. Статические импорты позволяют среде заранее загрузить и связать граф зависимостей до выполнения кода.

Импортированное имя является live binding (живой привязкой), то есть даёт доступ к текущему экспортируемому значению, а не к его копии. Импортёр не может присвоить этому имени новое значение, но видит изменения, сделанные модулем-экспортёром.

Статический `import` используют для обязательных зависимостей. `import()` возвращает Promise и загружает модуль по требованию, поэтому подходит для маршрутов, тяжёлых редакторов и других необязательных частей интерфейса.

## Ключевая схема

```text
входной модуль
→ найти статические import
→ определить адреса зависимостей
→ загрузить и разобрать граф модулей
→ связать импорты с экспортами
→ выполнить зависимости
→ выполнить входной модуль
```

| Этап | Что происходит | Возможная ошибка |
| --- | --- | --- |
| Разрешение | среда превращает specifier, то есть строку пути, в конкретный модуль | файл или экспорт пакета не найден |
| Загрузка и разбор | получает исходный код и проверяет синтаксис | сеть, CORS, синтаксическая ошибка |
| Связывание (`linking`) | сопоставляет импортированные и экспортированные имена | запрошенного именованного экспорта нет |
| Выполнение (`evaluation`) | выполняет код верхнего уровня | ошибка во время выполнения, отклонённый top-level await |

Разделение этапов объясняет, почему ошибка `import { missing }` обнаруживается до выполнения входного модуля, а ошибка внутри функции возникает только при её вызове.

## Экспорт и импорт

Именованный экспорт (`named export`) имеет фиксированное имя, которое импортёр указывает в фигурных скобках. Экспорт по умолчанию (`default export`) представляет одно значение, а локальное имя выбирает импортёр.

```js
// math.js
export const PI = 3.14;

export function sum(a, b) {
  return a + b;
}

export default function multiply(a, b) {
  return a * b;
}
```

```js
// app.js
import multiply, { PI, sum as add } from "./math.js";

console.log(add(PI, 2));
console.log(multiply(2, 3));
```

Именованные экспорты удобны, когда файл предоставляет несколько сущностей и важно единое имя по проекту. Экспорт по умолчанию уместен, когда модуль представляет одну главную сущность, но разные импортёры могут назвать её по-разному. Выбор чаще относится к соглашениям команды, а не к техническому превосходству одного вида экспорта.

`export { value } from "./file.js"` переэкспортирует имя, а `export * from` собирает публичные экспорты нескольких модулей. Такие barrel-файлы упрощают пути импорта, но могут скрыть реальные зависимости и создавать циклы, поэтому их применяют на понятных границах пакета или функционального модуля.

## Область видимости и strict mode

Объявления верхнего уровня модуля не становятся свойствами `window`:

```js
// module.js
const secret = 42;

console.log(window.secret); // undefined
console.log(this); // undefined
```

Модуль автоматически работает в строгом режиме. Например, присваивание необъявленной переменной приводит к ошибке, а обычный вызов функции не подставляет `globalThis` в `this`.

Изоляция имён устраняет случайные конфликты глобальных переменных. При этом модуль всё ещё может сознательно изменять глобальное состояние через `globalThis`, DOM или другие общие объекты.

## Live bindings

Импорт связывается с переменной экспортёра. Если экспортёр изменил её, импортёр при следующем чтении увидит новое значение:

```js
// counter.js
export let count = 0;

export function increment() {
  count += 1;
}
```

```js
// app.js
import { count, increment } from "./counter.js";

console.log(count); // 0
increment();
console.log(count); // 1

// count = 10; // TypeError: импортированному имени присваивать нельзя
```

Запрет присваивания относится к самому импортированному имени. Если экспортировано изменяемое значение вроде объекта, импортёр всё ещё способен изменить его свойства, если API модуля это допускает.

## Загрузка, связывание и выполнение

Статические `import` и `export` разрешены только на верхнем уровне. Благодаря этому среда видит зависимости без запуска веток, циклов и функций.

После загрузки этап linking связывает импортируемые и экспортируемые имена. Затем зависимости обычно выполняются раньше импортирующего модуля, поэтому их побочные эффекты верхнего уровня уже произошли к началу его тела.

```js
// setup.js
console.log("setup");

// app.js
import "./setup.js";
console.log("app");

// setup
// app
```

Модуль выполняется один раз для одной записи в карте модулей среды, а последующие импорты переиспользуют результат. В браузере ключ связан с итоговым URL: `./config.js?theme=dark` и `./config.js?theme=light` являются разными URL и могут создать разные экземпляры модуля.

Импорт только ради действия верхнего уровня называется side-effect import. Он бывает нужен для регистрации custom element или подключения polyfill, но скрытые глобальные изменения усложняют тестирование и порядок инициализации.

## Статический и динамический import

Статический import выражает обязательную зависимость и участвует в первоначальном графе:

```js
import { formatDate } from "./date.js";
```

Динамический `import()` является выражением, поэтому может находиться внутри функции или условия. Он возвращает Promise с объектом пространства имён модуля:

```js
button.addEventListener("click", async () => {
  const { openEditor } = await import("./editor.js");
  openEditor();
});
```

В браузере модуль загрузится при первом выполнении `import()`, если его ещё нет в карте модулей. Сборщик обычно превращает такую границу в отдельный chunk, но точная стратегия разбиения зависит от инструмента и его конфигурации.

Динамический импорт выбирают, когда зависимость необязательна для первого экрана и стоимость отдельной загрузки оправдана. Слишком мелкие chunks увеличивают число запросов и накладные расходы, а слишком крупный входной файл задерживает первое взаимодействие.

## Циклические зависимости

ESM умеет связывать граф с циклами, но цикл не гарантирует, что любое значение уже инициализировано в момент чтения.

```text
a.js imports b.js
b.js imports a.js
```

Во время связывания зависимости уже известны, но этап выполнения должен выбрать порядок. Обращение к `let`, `const` или `class` до инициализации может дать `ReferenceError` из-за TDZ. Объявленная через `function declaration` функция может быть доступна раньше, но её вызов всё равно способен прочитать ещё не готовое состояние другого модуля.

Цикл между самостоятельными слоями часто означает, что границы ответственности размыты. Общий контракт выносят в третий модуль, инвертируют зависимость или передают нужную функцию явно. Полностью запрещать циклы не требуется, но их поведение должно быть понятным и проверенным.

## Top-level await

В модуле разрешён `await` на верхнем уровне. Такой модуль становится асинхронной зависимостью: импортирующие его модули не начинают выполняться, пока Promise не завершится.

```js
// config.js
export const config = await loadConfig();
```

Это может быть полезно для обязательной инициализации, но медленная или зависшая операция задержит весь зависимый граф. Для необязательных данных чаще понятнее экспортировать функцию `loadConfig()` и явно контролировать состояния загрузки и ошибки.

## ESM в браузере

Входной модуль подключают так:

```html
<script type="module" src="/src/app.js"></script>
```

Модульные скрипты по умолчанию выполняются после разбора HTML и загружаются по правилам CORS. Локальное открытие страницы через `file://` часто не даёт корректно загрузить модули, поэтому разработку запускают через HTTP-сервер.

В браузере относительный specifier обычно содержит путь и расширение: `./math.js`. Bare specifier - имя вроде `react` без `./` или `/` - браузер не умеет разрешать без import map или преобразования сборщиком.

`import.meta.url` содержит URL текущего модуля и позволяет строить путь к ресурсу относительно файла:

```js
const workerUrl = new URL("./worker.js", import.meta.url);
```

## ESM и tree shaking

Статическая структура ESM позволяет сборщику определить, какие экспорты импортируются. На этой основе он может удалить часть неиспользуемого кода при production-сборке; такую оптимизацию называют tree shaking.

ESM сам по себе ничего не удаляет. Результат зависит от сборщика, режима сборки, побочных эффектов модуля, способа переэкспорта и метаданных пакета, например поля `sideEffects`. Динамический доступ и побочные эффекты верхнего уровня также ограничивают оптимизацию.

Поэтому утверждение «именованный импорт гарантированно уменьшает bundle» неверно. Размер проверяют анализатором bundle, а не только видом синтаксиса.

## ESM и CommonJS

| Свойство | ESM | CommonJS |
| --- | --- | --- |
| Синтаксис | `import` / `export` | `require` / `module.exports` |
| Основной анализ | статический граф | загрузка через вызовы `require` |
| Экспорт | live bindings | значение объекта `exports` в модели CommonJS |
| Браузер | нативно через `type="module"` | обычно нужен сборщик |
| Современный Node.js | поддерживается | поддерживается |

Смешение форматов может приводить к отличиям импорта по умолчанию, двойной загрузке пакета и ошибкам разрешения. Публичный пакет явно описывает точки входа через `package.json`, а приложение следует модели используемой среды и сборщика.

## Где применяется во frontend

- Модули разделяют приложение на явные зависимости без глобальных переменных.
- Динамический импорт создаёт границу ленивой загрузки для маршрута, модального окна или тяжёлого редактора.
- Публичные экспорты формируют API функционального модуля или пакета и скрывают внутренние файлы.
- Статический граф помогает сборщику создавать chunks и выполнять tree shaking.
- Side-effect import регистрирует polyfill или custom element, когда действие действительно должно произойти при загрузке.

## Ключевые уточнения

- ESM - часть стандарта JavaScript, а разрешение путей и загрузку выполняет среда: браузер, Node.js или сборщик.
- Импорт является доступной только для чтения live binding, а не снимком экспортированного значения.
- Связывание имён происходит до выполнения; код зависимостей обычно выполняется до тела импортёра.
- Один модуль обычно выполняется один раз для одного разрешённого идентификатора, но разные URL считаются разными модулями.
- `import()` загружает модуль по требованию и возвращает Promise; отдельный chunk является решением сборщика, а не гарантией языка.
- Цикл допустим, но раннее чтение неинициализированной переменной может привести к TDZ-ошибке.
- ESM создаёт условия для tree shaking, но не гарантирует удаление кода.
