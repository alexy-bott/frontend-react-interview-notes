# Map, Set, WeakMap и WeakSet

## Быстрый ответ

`Map` хранит пары ключ-значение, где ключом может быть значение любого типа. `Set` хранит уникальные значения. Обе коллекции итерируются, сохраняют порядок вставки и предоставляют свойство `size`.

`WeakMap` хранит значения по слабым ключам, а `WeakSet` - слабые элементы. Обычно такими ключами являются объекты. Если объект больше не достижим из приложения, присутствие в слабой коллекции не мешает сборщику мусора освободить его.

Слабые коллекции нельзя перечислить и у них нет `size`, потому что момент сборки мусора недетерминирован. Если бы содержимое можно было наблюдать без исходного ключа, поведение программы зависело бы от решения сборщика мусора.

Практический выбор: `Map` для явного словаря и управляемого кэша, `Set` для уникальности и проверки наличия, `WeakMap` для метаданных с жизненным циклом объекта, `WeakSet` для отметки конкретных объектов без их удержания в памяти.

## Ключевая схема

| Коллекция | Содержимое | Удерживает элементы | Итерируется | Типичная задача |
| --- | --- | --- | --- | --- |
| `Map` | ключ → значение | сильно | да | словарь, кэш, счётчики |
| `Set` | уникальные значения | сильно | да | дедупликация, проверка наличия |
| `WeakMap` | слабый ключ → значение | не удерживает ключ сам по себе | нет | приватные метаданные объекта |
| `WeakSet` | слабые значения | не удерживает значение само по себе | нет | отметка обработанных объектов |

Сильная ссылка участвует в обычной достижимости и сохраняет значение живым. Слабая связь позволяет сборщику удалить запись, когда ключ больше недостижим обычным путём.

## `Map`

`Map` предназначен для динамической коллекции пар. Ключом может быть строка, число, объект, функция, `NaN` или другое JavaScript-значение.

```js
const requests = new Map();
const user = { id: 42 };

requests.set(user, { status: "pending" });
console.log(requests.get(user)); // { status: "pending" }
console.log(requests.size); // 1
```

Объектный ключ сравнивается по идентичности. Новый объект с теми же свойствами является другим ключом:

```js
const map = new Map();

map.set({ id: 1 }, "first");
console.log(map.get({ id: 1 })); // undefined
```

`Map` хранит сильные ссылки и на ключи, и на значения. Пока достижим сам `Map` и запись не удалена, объектный ключ остаётся достижимым через коллекцию.

## `Map` или `Object`

Обычный объект естественно описывает сущность с заранее известными полями:

```js
const user = {
  id: 42,
  name: "Ann",
};
```

`Map` удобнее, когда набор записей динамический и воспринимается именно как коллекция:

- ключи не ограничены строками и символами (`Symbol`);
- нужны `size`, `clear()` и прямой API итерации;
- значения часто добавляются и удаляются;
- важно не смешивать собственные записи с цепочкой прототипов.

Для словаря со строковыми ключами объект остаётся нормальным выбором. Если нужно исключить унаследованные свойства, можно создать `Object.create(null)`, но у него нет методов `Map` и обычного прототипа.

Спецификация требует от коллекций с ключами в среднем сублинейное время доступа, но не гарантирует конкретную реализацию или точную сложность `O(1)` для каждого вызова. Практический выбор делают по семантике и измерениям, а не по предположению о конкретной хеш-таблице.

## `Set`

`Set` хранит каждое значение не более одного раза. Это удобно для дедупликации примитивов и быстрой проверки наличия:

```js
const uniqueIds = [...new Set([1, 2, 2, 3])];
console.log(uniqueIds); // [1, 2, 3]

const selectedIds = new Set([1, 3]);
console.log(selectedIds.has(3)); // true
```

`Map` и `Set` используют сравнение SameValueZero. Оно считает `NaN` равным самому себе, а `0` и `-0` - одним значением. Объекты и функции сравниваются по идентичности.

Поэтому `Set` не удалит объекты-дубликаты по содержимому:

```js
const values = new Set([{ id: 1 }, { id: 1 }]);
console.log(values.size); // 2
```

Если уникальность определяется полем, данные индексируют через `Map`:

```js
const users = [
  { id: 1, name: "Ann" },
  { id: 1, name: "Anna" },
];

const uniqueById = [...new Map(
  users.map((user) => [user.id, user]),
).values()];
```

В этом варианте запись с последним одинаковым `id` заменяет предыдущую. Если нужна первая, условие добавления задают явно.

## `WeakMap`

`WeakMap` связывает метаданные с ключом, не продлевая его жизненный цикл. Когда объект-ключ становится недостижим обычными сильными ссылками, сборщик мусора может удалить объект и соответствующую запись.

```js
const metadata = new WeakMap();

function initialize(element) {
  metadata.set(element, {
    initializedAt: Date.now(),
  });
}
```

Пока DOM-элемент нужен приложению, по нему можно получить метаданные. Когда элемент и остальные сильные ссылки на него исчезнут, отдельно удалять запись `WeakMap` не требуется.

Значение записи может ссылаться обратно на ключ. Слабая коллекция использует специальную ephemeron-семантику: связь, существующая только внутри этой записи, не должна сама сохранять ключ живым. Для практического использования достаточно модели «`WeakMap` не удерживает ключ только своим присутствием»; точный алгоритм сборки мусора зависит от движка.

`WeakMap` не является кэшем с ограничением размера, временем жизни или LRU-вытеснением. Если нужна статистика, перебор, ручная очистка либо политика вытеснения, используют `Map` и явно управляют записями.

## `WeakSet`

`WeakSet` отвечает на вопрос, встречался ли конкретный объект, не сохраняя его навсегда:

```js
const processed = new WeakSet();

function process(node) {
  if (processed.has(node)) {
    return;
  }

  processed.add(node);
  // обработка node
}
```

Это подходит для отметки DOM-узлов, объектов конфигурации или элементов графа, если полный список обработанных объектов не нужен.

В современном ECMAScript слабым ключом также может быть символ, который допускается хранить слабо. Зарегистрированные символы из `Symbol.for()` для этого не подходят, поскольку доступны через глобальный реестр. В повседневном frontend-коде основным слабым ключом всё равно остаётся объект.

## Почему weak-коллекции не итерируются

Сборщик мусора сам выбирает момент удаления недостижимых значений. Если бы у `WeakMap` были `keys()` или `size`, один и тот же код мог бы наблюдать разный результат только из-за того, запускалась ли сборка мусора между строками.

Поэтому API требует уже имеющийся ключ: можно вызвать `has(key)`, `get(key)` или `delete(key)`, но нельзя спросить «какие ключи ещё живы». Это сохраняет момент сборки мусора ненаблюдаемой деталью реализации.

## Практический выбор

| Требование | Выбор | Почему |
| --- | --- | --- |
| Динамический словарь с перебором | `Map` | любые ключи, `size`, итерация |
| Уникальные значения | `Set` | модель множества и `has()` |
| Метаданные живут не дольше объекта | `WeakMap` | ключ не удерживается коллекцией |
| Нужно отметить конкретные объекты | `WeakSet` | проверка наличия без перечисления |
| Кэш с лимитом и очисткой | `Map` + политика вытеснения | слабая коллекция не даёт контроля |
| Сущность с известными полями | `Object` | свойства описывают структуру данных |

## Ключевые уточнения

- `Map` и `Set` сохраняют порядок вставки, но это не делает их отсортированными коллекциями.
- `Set` сравнивает объекты по идентичности, а не по содержимому.
- `Map` удерживает ключи и значения сильными ссылками; растущий кэш нужно очищать.
- `WeakMap` слабо удерживает ключ, но значение доступно, пока ключ доступен вызывающему коду.
- Отсутствие итерации и `size` у слабых коллекций скрывает недетерминированный момент сборки мусора.
- Слабая коллекция не заменяет LRU, TTL и другие политики вытеснения кэша.
- В современном стандарте слабым ключом может быть объект или допустимый незарегистрированный символ.
