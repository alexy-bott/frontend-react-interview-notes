## Быстрый ответ

`Array` - объект для упорядоченной коллекции значений с индексными свойствами и специальным свойством `length`. Элементы могут иметь разные типы, а индексом массива считается строковый ключ свойства в допустимом диапазоне целых неотрицательных чисел.

Методы различаются назначением и изменяемостью. `map`, `filter`, `slice`, `concat` и `toSorted` создают новый массив; `push`, `splice`, `sort` и `reverse` изменяют исходный. Новый массив не означает глубокую копию: ссылки на вложенные объекты обычно переиспользуются.

Для выбора метода сначала определяют результат: преобразовать каждый элемент - `map`, выбрать часть - `filter`, найти один - `find`, проверить условие - `some` или `every`, выполнить побочный эффект - `forEach`, свернуть коллекцию в другое значение - `reduce`.

Callback-функции обычных методов массива синхронны. `forEach(async ...)` не ждёт Promise; для последовательного выполнения используют `for...of`, для параллельного - `Promise.all(array.map(...))`, а для ограничения числа одновременных операций - пул задач.

## Ключевая схема

| Задача | Метод | Результат | Изменяет исходный |
| --- | --- | --- | --- |
| Преобразовать каждый элемент | `map` | новый массив | нет |
| Оставить подходящие | `filter` | новый массив | нет |
| Найти первый элемент | `find` | значение или `undefined` | нет |
| Найти индекс | `findIndex` | индекс или `-1` | нет |
| Проверить хотя бы один | `some` | boolean | нет |
| Проверить все | `every` | boolean | нет |
| Выполнить side effect | `forEach` | `undefined` | сам метод нет |
| Свернуть в аккумулятор | `reduce` | любое значение | сам метод нет |
| Вставить/удалить внутри | `splice` | удалённые элементы | да |
| Получить диапазон | `slice` | новый массив | нет |
| Отсортировать | `sort` / `toSorted` | тот же / новый массив | да / нет |

## Массив как объект

```js
const values = ["a", "b"];

console.log(values[0]); // "a"
console.log(values.length); // 2
console.log(typeof values); // "object"
console.log(Array.isArray(values)); // true
```

`Array.isArray` проверяет внутренний тип массива и работает надёжнее `instanceof Array` между разными глобальными окружениями, например страницей и `iframe`.

Индексные свойства связаны с `length`. Запись за текущим концом увеличивает это значение:

```js
const values = [];
values[3] = "x";

console.log(values.length); // 4
console.log(values); // [empty × 3, "x"]
```

Уменьшение `length` удаляет элементы за новой границей:

```js
const values = [1, 2, 3];
values.length = 1;
console.log(values); // [1]
```

Произвольное строковое свойство не является элементом и не меняет `length`:

```js
values.meta = "cached";
```

Для метаданных лучше отдельный объект: многие операции массива игнорируют такие свойства, и структура становится неожиданной.

## Мутация и новый массив

Изменяющие методы:

- `push`, `pop`, `shift`, `unshift`;
- `splice`;
- `sort`, `reverse`;
- `fill`, `copyWithin`.

Неизменяющие методы и варианты с копированием:

- `slice`, `concat`;
- `map`, `filter`, `flat`, `flatMap`;
- spread `[...array]`;
- `toSorted`, `toReversed`, `toSpliced`, `with`.

```js
const original = [3, 1, 2];

const sameArray = original.sort((a, b) => a - b);
console.log(sameArray === original); // true

const source = [3, 1, 2];
const sorted = source.toSorted((a, b) => a - b);
console.log(sorted); // [1, 2, 3]
console.log(source); // [3, 1, 2]
```

Оба варианта сортируют элементы, но `toSorted` сохраняет исходный массив. Это важно для состояния, мемоизации и кода, где исходный массив используется в другом месте.

Копия остаётся поверхностной:

```js
const source = [{ id: 1 }];
const copy = source.slice();

copy[0].id = 2;
console.log(source[0].id); // 2
```

## `map`, `filter` и `flatMap`

`map` вызывает callback для существующих элементов и создаёт результат той же длины:

```js
const prices = [10, 20];
const withTax = prices.map((price) => price * 1.2);
```

`filter` включает только элементы, для которых callback вернул truthy:

```js
const activeUsers = users.filter((user) => user.active);
```

`flatMap` сначала преобразует каждый элемент, затем разворачивает один уровень. Он удобен, когда один вход создаёт ноль, один или несколько результатов:

```js
const tags = posts.flatMap((post) => post.tags);
```

Если callback используется только для побочного эффекта, а возвращённый массив не нужен, `map` выражает неверное намерение. В таком случае выбирают `forEach` или цикл.

## Поиск и проверка

```js
users.find((user) => user.id === id);      // element | undefined
users.findIndex((user) => user.id === id); // index | -1
users.some((user) => user.isAdmin);        // хотя бы один
users.every((user) => user.isActive);      // все
users.includes(selectedUser);              // SameValueZero
```

`some`, `every`, `find` и `findIndex` прекращают обход, когда результат уже известен. `filter` всегда должен проверить все существующие элементы, чтобы построить полный массив.

`includes` использует SameValueZero и находит `NaN`. `indexOf` использует строгое равенство и `NaN` не находит:

```js
[NaN].includes(NaN); // true
[NaN].indexOf(NaN);  // -1
```

Для объектов оба метода проверяют идентичность, а не содержимое.

## `reduce`

`reduce` последовательно обновляет аккумулятор:

```js
const total = items.reduce(
  (sum, item) => sum + item.price,
  0,
);
```

Начальное значение задаёт тип аккумулятора и поведение для пустого массива. Без него первый существующий элемент становится аккумулятором, а вызов `reduce` для пустого массива выбрасывает `TypeError`.

```js
const byId = users.reduce((result, user) => {
  result.set(user.id, user);
  return result;
}, new Map());
```

`reduce` может выразить почти любой обход, но универсальность не делает его самым читаемым выбором. `map`, `filter`, `some` и обычный цикл часто яснее показывают цель и позволяют проще поставить точку останова или выполнить ранний `break`.

## `slice` и `splice`

Названия похожи, но контракты разные:

```js
const source = ["a", "b", "c"];

source.slice(1, 3); // ["b", "c"], source не меняется
source.splice(1, 1, "x"); // ["b"], source = ["a", "x", "c"]
```

`slice(start, end)` возвращает поверхностную копию диапазона, не включая `end`. `splice(start, deleteCount, ...items)` изменяет массив и возвращает удалённые элементы.

Для immutable-вставки современный `toSpliced` повторяет идею splice, но возвращает новый массив.

## Сортировка

Без comparator элементы преобразуются в строки и сравниваются по UTF-16 code units:

```js
[1, 10, 2].sort(); // [1, 10, 2]
```

Числам нужен comparator:

```js
numbers.toSorted((a, b) => a - b);
```

Comparator должен последовательно задавать порядок:

- отрицательное значение: `a` раньше `b`;
- положительное: `a` после `b`;
- `0`: элементы считаются равными по порядку.

Нельзя возвращать только boolean: `a > b` даёт `true/false`, которые превращаются в `1/0` и не задают обратное отношение корректно.

Современный ECMAScript требует стабильную сортировку: элементы, для которых comparator вернул `0`, сохраняют относительный порядок.

## Разреженные массивы и `undefined`

Пустая позиция (`hole`) означает отсутствие собственного индексного свойства, а не элемент со значением `undefined`:

```js
const sparse = new Array(3);
const dense = [undefined, undefined, undefined];

console.log(0 in sparse); // false
console.log(0 in dense);  // true
```

Поведение методов различается. `map`, `forEach`, `filter` и многие другие методы с callback-функцией пропускают пустые позиции; `for...of` читает позиции и выдаёт `undefined`; spread также создаёт явные `undefined`.

Разреженные массивы усложняют рассуждение и могут ухудшать оптимизацию движка. Обычно массив строят плотным через `Array.from`, `fill` или последовательный `push`.

```js
Array(3).map(() => 1);       // пустые позиции остаются
Array.from({ length: 3 }, () => 1); // [1, 1, 1]
```

## Асинхронные callback-функции

Методы массива не ожидают Promise, возвращённые callback-функциями:

```js
items.forEach(async (item) => {
  await save(item);
});
```

`forEach` сразу завершит синхронный обход и вернёт `undefined`. Для параллельного ожидания:

```js
await Promise.all(items.map((item) => save(item)));
```

Для последовательного:

```js
for (const item of items) {
  await save(item);
}
```

Для большого массива нужен pool, если одновременный запуск всех операций создаст лишнюю нагрузку.

## Стоимость операций

`push` и `pop` работают с концом массива и обычно дешевле `shift` и `unshift`, которым нужно изменить позиции остальных элементов. Поиск через `find`, `includes` и `indexOf` в худшем случае проходит весь массив. `sort` требует больше линейного времени и зависит от функции сравнения и реализации движка.

Точные оценки и причины разобраны в [Сложность Array методов](<../Алгоритмы/02 Сложность методов массивов.md>). Семантика всё равно важнее микровыбора: заменять понятный массив на `Map` следует при реальном требовании быстрого многократного поиска по ключу.

## Где применяется во frontend

- `map` преобразует предметные данные в модель представления или React-элементы.
- `filter` строит видимую выборку без изменения исходных данных.
- `find` получает сущность по id для единичного поиска; частые поиски могут оправдать индекс `Map`.
- `toSorted` сохраняет immutable state при сортировке таблицы.
- `some` и `every` выражают правила permissions или validation с ранним завершением.
- Pool ограничивает concurrency при обработке большого массива запросов.

## Ключевые уточнения

- Массив является объектом со специальной семантикой индексных свойств и `length`.
- Методы с новым массивом обычно копируют только структуру верхнего уровня.
- `sort`, `reverse` и `splice` изменяют исходный массив; варианты с копированием выражают намерение сохранить исходное значение.
- Метод выбирают по форме результата, а не по привычке использовать `reduce` или `map` везде.
- Пустая позиция разреженного массива отличается от явного `undefined`, и методы обрабатывают такие позиции по-разному.
- Обычные callback-функции методов массива синхронны и не ожидают Promise.
- Comparator возвращает отрицательное, положительное значение или ноль, а не boolean.
