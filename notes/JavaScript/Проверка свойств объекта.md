## Быстрый ответ

В JavaScript нужно различать два вопроса: доступно ли свойство где-либо в цепочке прототипов (`prototype chain`) и принадлежит ли оно непосредственно объекту. Оператор `key in obj` проверяет всю цепочку, а `Object.hasOwn(obj, key)` - только собственное свойство (`own property`).

`obj.hasOwnProperty(key)` отвечает на второй вопрос, но полагается на унаследованный метод. Объект может быть создан через `Object.create(null)` или переопределить имя `hasOwnProperty`. Поэтому для современного кода надёжнее `Object.hasOwn`, а для старой среды - `Object.prototype.hasOwnProperty.call(obj, key)`.

Чтение `obj[key] !== undefined` проверяет значение, а не существование свойства. Ключ может присутствовать со значением `undefined`, а getter при чтении может выполнить код. `in` и `Object.hasOwn` проверяют наличие свойства, не вызывая getter.

## Ключевая схема

| Способ | Проверяет цепочку прототипов | Работает с `Object.create(null)` |
| --- | --- | --- |
| `"key" in obj` | да | да |
| `Object.hasOwn(obj, "key")` | нет | да |
| `obj.hasOwnProperty("key")` | нет | не всегда |
| `obj.key !== undefined` | неточно | зависит от значения |

## Базовая модель

Ключ свойства в JavaScript является строкой или символом. Перед проверкой другой примитивный ключ приводится к допустимому ключу свойства: например, число `1` становится строкой `"1"`. Правый операнд `in` должен быть объектом; `"x" in null` и `"x" in "text"` приводят к `TypeError`.

Существование, принадлежность и перечисляемость - независимые свойства:

1. `in` проверяет собственное или унаследованное свойство;
2. `Object.hasOwn` проверяет только собственное;
3. `Object.keys` возвращает собственные перечисляемые строковые ключи;
4. `Reflect.ownKeys` возвращает все собственные строковые и символьные ключи, включая неперечисляемые.

Поэтому один API нельзя выбирать только по краткости: сначала формулируют, какую именно характеристику свойства нужно проверить.

## Развернутый ответ

### `in`

`in` подходит, когда важно поведение объекта с учётом цепочки прототипов. Например, `"toString" in obj` обычно возвращает `true`, даже если сам объект не объявлял такое свойство. В TypeScript этот оператор также может сужать объединение типов, но во время выполнения следует обычной семантике JavaScript.

### `Object.hasOwn`

`Object.hasOwn` появился в ES2022 и работает с объектами без `Object.prototype` и с переопределённым `hasOwnProperty`. Он подходит для словарей, данных запроса или ответа и ситуаций, где унаследованное значение не должно считаться частью собственных данных.

Перед проверкой внешнего значения всё равно нужно убедиться, что оно является ненулевым объектом. `Object.hasOwn(null, "id")` бросает `TypeError`; метод проверяет свойство объекта, а не валидирует неизвестные данные целиком.

### Значение `undefined`

Объекты `{}` и `{ value: undefined }` ведут себя одинаково при чтении `obj.value`, но имеют разный набор свойств. Это влияет на проверку данных, объединение объектов, сериализацию и значения по умолчанию. Для параметра или деструктуризации значение `undefined` запускает значение по умолчанию, даже если свойство существует; `Object.hasOwn` позволяет отдельно различить эти случаи.

### Перечисление

`for...in` проходит перечисляемые строковые свойства по всей цепочке прототипов, поэтому для обработки собственных данных его фильтруют через `Object.hasOwn`. Символьные ключи в `for...in` и `Object.keys` не входят. Если нужны все собственные ключи независимо от `enumerable`, используют `Reflect.ownKeys`.

Приватные поля класса имеют отдельную проверку `#field in obj`; это специальный синтаксис и не означает обычное строковое свойство `"#field"`.

## Пример

```js
const parent = { inherited: true };
const obj = Object.create(parent);

obj.own = undefined;

console.log("inherited" in obj); // true
console.log(Object.hasOwn(obj, "inherited")); // false

console.log("own" in obj); // true
console.log(Object.hasOwn(obj, "own")); // true
console.log(obj.own !== undefined); // false
```

Проверка неизвестного значения:

```js
function getOwnValue(value, key) {
  if (typeof value !== "object" || value === null) {
    return null;
  }

  if (!Object.hasOwn(value, key)) {
    return null;
  }

  return value[key];
}
```

## Где применяется во frontend

| Задача | API | Причина |
| --- | --- | --- |
| Проверить поле внешних данных | `Object.hasOwn` после проверки объекта | унаследованный ключ не считается собственными данными |
| Проверить доступный метод | `in` | поведение может находиться в цепочке прототипов |
| Получить обычные сериализуемые ключи | `Object.keys` | только собственные перечисляемые строковые ключи |
| Инспектировать все собственные ключи | `Reflect.ownKeys` | включает символы и неперечисляемые ключи |

## Ключевые уточнения

- `in` проверяет всю цепочку прототипов, а `Object.hasOwn` - только сам объект.
- Значение `undefined` не доказывает отсутствие свойства.
- `Object.hasOwn` безопаснее вызова `obj.hasOwnProperty` на объекте неизвестного происхождения.
- Принадлежность объекту и перечисляемость - разные характеристики свойства.
- `for...in` включает унаследованные перечисляемые строковые ключи и не перечисляет символы.
