## Быстрый ответ

`var`, `let` и `const` создают привязки имён, но отличаются областью видимости, моментом инициализации и возможностью повторного присваивания. Область видимости `var` ограничена функцией (function scope); переменную можно повторно объявить в той же области, и до выполнения строки объявления она содержит `undefined`. `let` и `const` имеют блочную область видимости (block scope) и находятся в temporal dead zone (TDZ) до инициализации.

`let` разрешает повторное присваивание, а `const` запрещает изменить саму привязку и требует начальное значение при объявлении. При этом `const` не делает объект неизменяемым: его свойства можно менять, пока это разрешает сам объект.

В новом коде `const` используют по умолчанию, `let` - когда привязку действительно нужно переназначать. `var` в основном встречается в старом коде; область видимости на уровне функции и ранняя инициализация делают границы значения менее очевидными.

## Ключевая схема

| Свойство | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | функция | блок | блок |
| До объявления | `undefined` | TDZ / `ReferenceError` | TDZ / `ReferenceError` |
| Повторное объявление | можно | нельзя | нельзя |
| Повторное присваивание | можно | можно | нельзя |
| Начальное значение при объявлении | не обязательно | не обязательно | обязательно |
| Привязка на итерацию `for` | одна общая | новая для каждой итерации | зависит от формы цикла |

## Базовая модель

Объявление создаёт привязку между именем и значением внутри определённой области видимости. Полезно различать три события: привязка создана, привязка инициализирована, в неё присвоено значение. У `var` создание и инициализация значением `undefined` происходят при подготовке области; присваивание начального значения выполняется позже, когда выполнение доходит до объявления. У `let` и `const` привязка сначала остаётся неинициализированной, поэтому чтение в TDZ завершается `ReferenceError`.

Блочная область видимости ограничена ближайшим блоком `{}`, включая `if`, `for` и `try`. Область видимости функции ограничена её телом. Поэтому `var` внутри блока остаётся доступен до конца функции, а `let` и `const` - нет.

## Развернутый ответ

### Область видимости функции и блока

```js
function example() {
  if (true) {
    var oldValue = "var";
    let blockValue = "let";
  }

  console.log(oldValue); // var
  console.log(blockValue); // ReferenceError
}
```

`oldValue` существует во всей функции, а `blockValue` - только внутри `if`. Это различие уменьшает риск случайно использовать временную переменную за пределами блока.

### TDZ и shadowing

TDZ начинается при входе в область видимости и заканчивается, когда выполнение достигает объявления. Внутренняя привязка уже скрывает внешнее одноимённое значение, но ещё недоступна:

```js
const value = "outer";

{
  console.log(value); // ReferenceError, а не "outer"
  const value = "inner";
}
```

Это защищает от чтения переменной до того, как программа установила её предполагаемое начальное значение.

### `const` и изменяемый объект

```js
const user = { name: "Ann" };

user.name = "Kate"; // объект изменяется
user = {}; // TypeError: привязку переназначить нельзя
```

`Object.freeze(user)` запрещает изменить собственные свойства объекта на первом уровне, но не делает автоматически неизменяемым всё дерево вложенных объектов.

### Привязки в цикле

Для `for (let ...)` JavaScript создаёт новую привязку на каждой итерации. Замыкание каждой callback-функции получает своё значение. `var` использует одну общую привязку на уровне функции, поэтому все callback-функции читают её итоговое значение после завершения цикла.

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0, 1, 2
```

### Верхний уровень скрипта и модуля

В классическом браузерном скрипте `var` на верхнем уровне создаёт свойство глобального объекта `window`. Верхнеуровневые `let` и `const` создают глобальные лексические привязки, но не свойства `window`. В ES module все объявления принадлежат области модуля и также не становятся свойствами глобального объекта.

## Где применяется во frontend

| Ситуация | Выбор | Причина |
| --- | --- | --- |
| Значение не переназначается | `const` | сразу показывает стабильность привязки |
| Счётчик или значение меняется по шагам | `let` | требуется повторное присваивание |
| Временная переменная внутри блока | `const`/`let` | блочная область не выпускает имя наружу |
| Разбор старого кода | знание `var` | область функции и `undefined` до объявления меняют поведение |

## Ключевые уточнения

- `const` запрещает переназначить привязку, но не делает объект неизменяемым.
- `let` и `const` создаются при входе в область, но остаются недоступны в TDZ до инициализации.
- `var` имеет область видимости функции и инициализируется `undefined` до выполнения своей строки.
- `for (let ...)` создаёт отдельную привязку для каждой итерации, что важно для замыканий.
- Поведение верхнеуровневых объявлений зависит от среды: классический скрипт и ES module создают разные глобальные привязки.
