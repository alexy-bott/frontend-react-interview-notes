## Быстрый ответ

`Proxy` создаёт объект-обёртку, который перехватывает фундаментальные операции над целевым объектом (`target`): чтение и запись свойств, `in`, перечисление, вызов функции, `new` и другие. Поведение задаётся ловушками (`traps`) объекта-обработчика (`handler`).

`Reflect` предоставляет функции для тех же внутренних операций с единообразным контрактом возврата. Внутри ловушки его используют, чтобы выполнить стандартное поведение целевого объекта без ручного воспроизведения правил прототипов, объекта-получателя и дескрипторов.

Proxy лежит в основе некоторых реактивных систем, обёрток для проверки данных и виртуализации объектов. Но он не наблюдает вложенные объекты автоматически, меняет идентичность, усложняет отладку и обязан соблюдать инварианты языка.

Proxy не заменяет обычный предметный API. Если требования можно выразить методом или явной функцией без неявного перехвата каждого доступа к свойству, такой код обычно проще поддерживать.

## Ключевая схема

```text
операция вызывающего кода
→ Proxy
→ соответствующая ловушка handler
→ custom logic
→ стандартная операция Reflect.* над target
→ result caller
```

```js
const proxy = new Proxy(target, {
  get(target, property, receiver) {},
  set(target, property, value, receiver) {},
  has(target, property) {},
  ownKeys(target) {},
});
```

## `get` и объект-получатель

```js
const target = {
  firstName: "Ada",
  lastName: "Lovelace",

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },
};

const proxy = new Proxy(target, {
  get(target, property, receiver) {
    console.log("read", property);
    return Reflect.get(target, property, receiver);
  },
});
```

`receiver` - объект, через который началось чтение, часто сам Proxy или дочерний объект. `Reflect.get(target, property, receiver)` сохраняет правильный `this` для унаследованного геттера.

Простой `target[property]` вызвал бы геттер с `this === target` и мог бы обойти перехват Proxy для внутренних чтений вроде `this.firstName`.

Ловушка срабатывает для любого ключа свойства, включая символы. Логирование должно уметь обрабатывать их и не предполагать, что ключ всегда является строкой.

## `set`

```js
const proxy = new Proxy({}, {
  set(target, property, value, receiver) {
    if (property === "age" && value < 0) {
      throw new RangeError("age must be non-negative");
    }

    return Reflect.set(target, property, value, receiver);
  },
});
```

Ловушка `set` должна вернуть логический признак успеха. В strict mode значение `false` приводит к `TypeError` при присваивании.

Проверка через Proxy охватывает только операции, проходящие через этот Proxy. Код с прямой ссылкой на `target` может изменить его без ловушек, а вложенный объект также не перехватывается автоматически.

```js
const target = { profile: { name: "Ann" } };
const proxy = new Proxy(target, handler);

proxy.profile.name = "Grace";
```

Первое чтение `profile` перехватывается, но запись `name` происходит на обычном вложенном объекте. Глубокая реактивность создаёт Proxy рекурсивно и обычно кэширует соответствие `target → proxy`, чтобы сохранять идентичность обёртки.

## Основные ловушки

| Операция | Ловушка | Reflect |
| --- | --- | --- |
| `proxy[key]` | `get` | `Reflect.get` |
| `proxy[key] = value` | `set` | `Reflect.set` |
| `key in proxy` | `has` | `Reflect.has` |
| `delete proxy[key]` | `deleteProperty` | `Reflect.deleteProperty` |
| `Object.keys(proxy)` и чтение собственных ключей | `ownKeys` + дескрипторы | `Reflect.ownKeys` |
| `Object.defineProperty` | `defineProperty` | `Reflect.defineProperty` |
| `Object.getPrototypeOf` | `getPrototypeOf` | `Reflect.getPrototypeOf` |
| `fn(...args)` | `apply` | `Reflect.apply` |
| `new Fn(...args)` | `construct` | `Reflect.construct` |

Перечисление часто задействует несколько операций. `Object.keys(proxy)` получает собственные ключи, затем проверяет дескрипторы и оставляет перечисляемые строковые свойства. Одна ловушка `ownKeys` не определяет весь результат.

## Почему `Reflect`

Методы `Reflect` соответствуют внутренним операциям над объектами и явно принимают целевой объект:

```js
Reflect.get(object, key, receiver);
Reflect.set(object, key, value, receiver);
Reflect.has(object, key);
Reflect.ownKeys(object);
```

У многих методов boolean result вместо исключения для обычного отказа:

```js
Reflect.defineProperty(object, "id", descriptor); // true/false
Object.defineProperty(object, "id", descriptor);  // object или исключение
```

`Reflect.ownKeys` возвращает все собственные строковые и символьные ключи, включая неперечисляемые. Этим он отличается от `Object.keys`.

`Reflect` полезен и без Proxy, но особенно удобен как корректное стандартное продолжение ловушки.

## Инварианты

Proxy не может сообщать произвольные сведения, нарушающие жёсткие ограничения целевого объекта. Например, `get` не может вернуть другое значение для собственного свойства данных с `writable: false` и `configurable: false`, а `ownKeys` не может скрыть неконфигурируемый ключ.

```js
const target = {};

Object.defineProperty(target, "id", {
  value: 1,
  writable: false,
  configurable: false,
});

const proxy = new Proxy(target, {
  get() {
    return 2;
  },
});

proxy.id; // TypeError: инвариант нарушен
```

Инварианты сохраняют смысл дескрипторов и нерасширяемых объектов даже при перехвате. Чем больше ловушек реализовано вручную, тем выше риск противоречия между ними.

## Идентичность и исходный объект

```js
proxy !== target; // true
```

`Map` и `Set` считают исходный объект и Proxy разными ключами. Если одна часть приложения хранит исходный `target`, а другая - Proxy, поиск и мемоизация могут расходиться.

Поэтому реактивная библиотека обычно предоставляет единый способ создания обёрток и кэширует соответствие в `WeakMap`. Потребитель не должен случайно смешивать исходные объекты и их Proxy.

Сравнение `===` не перехватывается ловушкой. Proxy не может сделать себя строго равным `target`.

## Приватные поля и внутренние слоты

Некоторые встроенные методы требуют объект-получатель с определёнными внутренними слотами. Proxy не получает внутренние слоты `target` автоматически:

```js
const map = new Map();
const proxy = new Proxy(map, {});

// proxy.set("key", "value") может бросить TypeError,
// потому что метод получает proxy без [[MapData]].
```

Похожая проблема возникает с приватными полями класса: метод проверяет внутреннюю принадлежность объекта-получателя классу, а Proxy не является исходным экземпляром.

Иногда ловушка `get` привязывает методы к `target`, но это меняет идентичность методов и семантику `this`. Полностью прозрачного Proxy для любого объекта не существует.

## `Proxy.revocable`

```js
const { proxy, revoke } = Proxy.revocable(target, handler);

usePlugin(proxy);
revoke();
```

После `revoke()` почти любая операция с Proxy выбрасывает `TypeError`. Это подходит для временно выданной возможности или жизненного цикла плагина, если потребитель не должен использовать объект после закрытия.

Отзыв Proxy не откатывает уже выполненные изменения `target` и не удаляет копии данных, которые потребитель успел получить.

## Где применяется во frontend

- Реактивная система отслеживает чтение и запись свойств и связывает их с эффектами.
- Проверяющая обёртка контролирует присваивания, если все записи гарантированно проходят через Proxy.
- API-фасад виртуализирует большой объект или ленивое получение свойств.
- `Proxy.revocable` ограничивает жизненный цикл выданного объекта.
- Тестовый дублёр наблюдает операции, хотя явный mock API часто проще.

## Границы выбора

Proxy оправдан, когда нужно перехватить открытый набор операций со свойствами, который нельзя заранее выразить методами. Для известной команды `setUserName(name)` явный метод понятнее ловушки `set` для любого ключа.

Proxy добавляет накладные расходы во время выполнения, усложняет стеки ошибок, идентичность и совместимость со встроенными объектами и приватными полями. Влияние на производительность проверяют измерением в конкретном часто выполняемом участке кода.

Глубокий Proxy требует рекурсивного обёртывания, обработки циклов и кэша идентичности. Обернуть только корневой объект недостаточно для полной наблюдаемости вложенного графа.

## Ключевые уточнения

- Proxy перехватывает операции над обёрткой, но исходный `target` остаётся отдельной ссылкой.
- `Reflect.*` сохраняет стандартную семантику и объект-получатель лучше ручного `target[key]` внутри ловушек.
- Ловушка `set` возвращает `boolean`, а присваивание в strict mode превращает `false` в `TypeError`.
- Proxy обязан соблюдать инварианты неконфигурируемого и нерасширяемого `target`.
- Вложенные объекты не становятся Proxy автоматически.
- Proxy меняет идентичность и не может перехватить `===`.
- Приватные поля и внутренние слоты встроенных объектов мешают полной прозрачности обёртки.
- Явный API предпочтительнее, если набор операций известен и не требует метапрограммирования.
