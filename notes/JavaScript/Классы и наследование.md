## Быстрый ответ

`class` - синтаксис JavaScript для создания конструктора и общего API экземпляров через прототип. Методы экземпляра находятся в `ClassName.prototype`, публичные поля создаются как собственные свойства каждого экземпляра, а статические члены принадлежат самому классу-конструктору.

`new` создаёт объект, связывает его `[[Prototype]]` с `ClassName.prototype`, вызывает конструктор с новым `this` и обычно возвращает этот объект. В производном классе `super()` должен выполниться до использования `this`, потому что базовый конструктор создаёт и инициализирует объект-получатель.

`class` использует прототипное наследование, но не является только косметической заменой функции-конструктора. Тело класса всегда выполняется в strict mode, объявление класса находится в TDZ, constructor нельзя вызвать без `new`, методы неперечисляемы, а доступ к приватным полям проходит внутреннюю проверку принадлежности классу (`private brand`).

Наследование подходит отношению «является» с устойчивым общим контрактом. Для сборки независимых возможностей во frontend чаще проще композиция, потому что она меньше связывает жизненные циклы и внутреннее состояние классов.

## Ключевая схема

```text
объект класса-конструктора User
├─ статические члены
└─ prototype
   ├─ constructor → User
   ├─ login()
   └─ logout()

экземпляр user
├─ собственные публичные и приватные поля
└─ [[Prototype]] → User.prototype
```

```js
class User {
  role = "user";

  constructor(name) {
    this.name = name;
  }

  greet() {
    return `Hello, ${this.name}`;
  }

  static createGuest() {
    return new User("Guest");
  }
}
```

## Что делает `new`

Упрощённая модель для базового класса или функции-конструктора:

1. Создать новый объект.
2. Установить его `[[Prototype]]` в `Constructor.prototype`.
3. Вызвать конструктор с новым объектом как `this`.
4. Если конструктор явно вернул объект, использовать его; иначе вернуть созданный объект.

```js
const user = new User("Ann");

Object.getPrototypeOf(user) === User.prototype; // true
user.greet(); // "Hello, Ann"
```

Конструктор класса нельзя вызвать как `User("Ann")`: это выбросит `TypeError`. Обычная функция-конструктор технически вызывается без `new`, хотя такой вызов часто является ошибкой.

Конструктор базового класса может явно вернуть другой объект и заменить созданный экземпляр. Возврат примитива игнорируется. Такое поведение редко полезно: конструктор с неожиданной идентичностью результата усложняет наследование и `instanceof`.

## Методы и поля

Объявление метода создаёт одну функцию в прототипе, общую для экземпляров:

```js
User.prototype.greet === new User("A").greet; // true
```

Публичное поле создаётся заново на каждом экземпляре:

```js
class Counter {
  count = 0;
}
```

Поле со стрелочной функцией также является собственным свойством с отдельной функцией для каждого экземпляра:

```js
class ButtonController {
  handleClick = () => {
    this.submit();
  };
}
```

Поле со стрелочной функцией сохраняет лексический `this` при передаче callback-функции, но создаёт отдельный объект функции для каждого экземпляра и не находится в прототипе. Обычный метод экономнее и легче переопределяется; объект-получатель можно сохранить через обёртку или `bind` там, где callback действительно нужен.

Методы класса являются неперечисляемыми, а публичные поля обычно создаются как перечисляемые собственные свойства.

## `extends` и две цепочки прототипов

```js
class Admin extends User {
  constructor(name, permissions) {
    super(name);
    this.permissions = permissions;
  }

  greet() {
    return `${super.greet()} (admin)`;
  }
}
```

Inheritance строит две связи:

```text
Admin.prototype.[[Prototype]] → User.prototype
Admin.[[Prototype]] → User
```

Первая даёт методы экземпляра, вторая позволяет наследовать статические члены класса.

Конструктор производного класса не получает `this` до `super()`. `super(name)` вызывает базовый конструктор, который создаёт и инициализирует объект-получатель. После этого поля производного класса и оставшееся тело конструктора могут обращаться к `this`.

Если производный класс не объявляет constructor, JavaScript предоставляет эквивалент `constructor(...args) { super(...args); }`.

## `super`

`super.method()` ищет метод начиная с прототипа базового класса, но вызывает его с текущим `this`:

```js
class Admin extends User {
  greet() {
    return super.greet().toUpperCase();
  }
}
```

Поэтому базовый метод работает с состоянием конкретного экземпляра `Admin`. `super` не является обычной переменной с объектным значением; его поведение связано с местом объявления метода и его внутренним `[[HomeObject]]`.

В статическом методе `super.method()` обращается к базовому классу-конструктору, а не к `Base.prototype`.

## Порядок инициализации полей

В базовом классе поля экземпляра инициализируются перед выполнением инструкций тела конструктора. В производном классе собственные поля инициализируются сразу после успешного `super()` и до следующих инструкций конструктора.

Это влияет на переопределяемые методы:

```js
class Base {
  constructor() {
    this.initialize();
  }

  initialize() {}
}

class Derived extends Base {
  value = 42;

  initialize() {
    console.log(this.value); // undefined во время base constructor
  }
}
```

`Base` вызывает переопределённый метод до инициализации полей `Derived`. Поэтому конструктору базового класса не следует вызывать переопределяемый метод, который зависит от полностью инициализированного состояния производного класса.

## Статические члены

Статический метод или поле принадлежит самому классу-конструктору:

```js
class User {
  static defaultRole = "user";

  static fromJSON(value) {
    return new User(value.name);
  }
}

User.fromJSON({ name: "Ann" });
```

Экземпляр не получает статический член через свою цепочку прототипов:

```js
const user = new User("Ann");
user.fromJSON; // undefined
```

Статическая фабрика удобна для именованного способа создания объекта. Если создание требует внешних зависимостей или асинхронного ввода-вывода, отдельную функцию-фабрику или сервис часто проще тестировать; кроме того, класс не связывается с инфраструктурой.

## Приватные поля

```js
class Session {
  #token;

  constructor(token) {
    this.#token = token;
  }

  get maskedToken() {
    return `${this.#token.slice(0, 4)}...`;
  }
}
```

`#token` - не строковое свойство с ключом `"#token"`. При доступе движок проверяет внутреннюю принадлежность объекта тому классу, где объявлено поле. Сам синтаксис `#token` разрешён только внутри тела этого класса.

```js
Object.keys(new Session("secret")); // приватное поле не перечисляется
```

`Proxy` или объект с похожей цепочкой прототипов не получает доступ к приватному полю автоматически. Извлечённый метод, использующий `#field`, выбросит ошибку при вызове с чужим объектом-получателем.

Приватные поля с `#` обеспечивают инкапсуляцию во время выполнения. Модификатор TypeScript `private` без `#` в зависимости от настроек компиляции может быть только проверкой на этапе разработки.

## Getters и setters

```js
class Rectangle {
  constructor(width, height) {
    this.width = width;
    this.height = height;
  }

  get area() {
    return this.width * this.height;
  }
}
```

Getter или setter класса размещается в прототипе и является неперечисляемым. Getter подходит для недорогого вычисляемого свойства. Асинхронную операцию или команду лучше выражать методом, чтобы стоимость и возможный побочный эффект были видны вызывающему коду.

## `instanceof`

Обычный `value instanceof Constructor` проверяет, встречается ли `Constructor.prototype` в цепочке прототипов значения.

```js
const admin = new Admin("Ann", []);

admin instanceof Admin; // true
admin instanceof User;  // true
```

Это не проверка структуры данных. Обычный объект с теми же свойствами вернёт `false`, а объект с вручную установленным прототипом может вернуть `true` без вызова конструктора.

`instanceof` может давать неожиданный результат между разными глобальными окружениями: например, у iframe собственный конструктор `Array`. Массив проверяют через `Array.isArray`, а для прикладного контракта часто надёжнее явный признак типа или проверка структуры.

Конструктор может переопределить `Symbol.hasInstance`, поэтому `instanceof` является настраиваемым протоколом, а не абсолютной гарантией происхождения объекта.

## Inheritance или composition

Наследование удобно, когда подтип действительно соблюдает контракт базового класса и может безопасно использоваться вместо него. Глубокая иерархия создаёт неявную связанность: изменение защищённого поведения базового класса влияет на потомков.

Composition передаёт отдельные возможности явно:

```js
function createUserService({ api, cache, logger }) {
  return {
    async load(id) {
      const cached = cache.get(id);
      if (cached) return cached;

      const user = await api.loadUser(id);
      cache.set(id, user);
      logger.info("user loaded", { id });
      return user;
    },
  };
}
```

Зависимости видны, их легко заменить в тесте, а поведение не зависит от хрупкого порядка конструкторов. Классы остаются полезны для объектов с состоянием и устойчивым жизненным циклом: parser, соединение, модель редактора или предметная сущность.

## Где применяется во frontend

- SDK и браузерные API предоставляют экземпляры с методами в прототипе.
- Error subclasses несут `name`, `code`, `cause` и domain context.
- Модель с состоянием скрывает инварианты и жизненный цикл за методами.
- Статическая фабрика создаёт экземпляр из конкретного формата без перегрузки конструктора.
- Композиция собирает API, кэш и logger без глубокой иерархии классов.

## Ключевые уточнения

- Методы экземпляра находятся в прототипе, поля - в каждом экземпляре, статические члены - в классе-конструкторе.
- `class` использует цепочку прототипов, но добавляет strict mode, TDZ, приватные поля и запрет вызова без `new`.
- Производный класс должен вызвать `super()` до обращения к `this`.
- Базовый конструктор может вызвать переопределённый метод до инициализации полей производного класса, поэтому такой дизайн опасен.
- Поле со стрелочной функцией сохраняет `this`, но создаёт отдельную функцию для каждого экземпляра.
- Приватное поле не является обычным свойством и доступно только объекту с внутренней принадлежностью соответствующему классу.
- `instanceof` проверяет цепочку прототипов, а не форму объекта и не всегда надёжен между разными глобальными окружениями.
- Composition предпочтительнее, когда нужны независимые возможности, а не устойчивое отношение subtype.
