## Быстрый ответ

Комбинаторы Promise - статические методы, которые принимают итерируемый набор значений, Promise или thenable-объектов и возвращают один Promise по выбранному правилу объединения результатов.

- `Promise.all` нужен, когда обязательны все результаты: успешные значения возвращаются в порядке входа, а первое отклонение завершает общий Promise ошибкой.
- `Promise.allSettled` ждёт завершения каждого элемента и возвращает массив `{ status, value | reason }`, поэтому подходит для независимых операций и частичного успеха.
- `Promise.race` принимает первый завершившийся результат - успешный или ошибочный.
- `Promise.any` принимает первый успешный результат, а если отклонены все элементы, возвращает `AggregateError`.

Комбинаторы координируют результаты, но не запускают отложенную работу, не ограничивают количество одновременных операций и не отменяют проигравшие операции. Если Promise от `fetch` созданы до `Promise.all`, запросы уже запущены. Поведение fail-fast означает только раннее отклонение общего Promise.

## Ключевая схема

| Метод | Когда выполняется успешно | Когда отклоняется | Порядок результата | Пустой набор |
| --- | --- | --- | --- | --- |
| `Promise.all` | успешны все | при первом отклонении | порядок входа | успешно с `[]` |
| `Promise.allSettled` | после завершения всех входных элементов | отклонение элемента становится записью результата | порядок входа | fulfilled с `[]` |
| `Promise.race` | первым завершился успех | первой завершилась ошибка | один результат | остаётся `pending` |
| `Promise.any` | первый успешный результат | все отклонены → `AggregateError` | одно значение | отклоняется с `AggregateError` |

## Базовая модель

Каждый комбинатор синхронно получает итератор и проходит его элементы. Обычные значения нормализуются через `Promise.resolve` и ведут себя как успешно выполненные Promise. Thenable - объект с методом `then` - обрабатывается по обычной процедуре разрешения Promise.

Обработчики прикрепляются ко всем входным элементам. Быстрое завершение итогового Promise не удаляет их и не останавливает исходные операции. Поэтому раннее отклонение `Promise.all` не отменяет и не откатывает остальные запросы.

Для `all` и `allSettled` индекс результата привязан к позиции элемента во входном наборе. Операции могут завершиться в любом порядке, но массив результатов сохраняет исходный порядок.

## Развернутый ответ

### `Promise.all`

`Promise.all` подходит, когда без любого элемента общий результат неполон: например, экрану одновременно нужны профиль, права доступа и настройки. Общий Promise выполняется успешно только после всех входных Promise. Если один из них отклоняется, общий Promise сразу отклоняется с той же причиной.

```js
const [profile, permissions] = await Promise.all([
  loadProfile(),
  loadPermissions(),
]);
```

Операции запускаются при вызове функций, ещё до ожидания общего результата. Если `loadProfile()` отклонится, `loadPermissions()` продолжит работу, если её API не получило отдельный сигнал отмены.

### `Promise.allSettled`

`Promise.allSettled` нужен, когда каждая операция имеет самостоятельную ценность и интерфейс должен показать полный отчёт. Ошибка отдельного Promise превращается в элемент `{ status: "rejected", reason }`, а не в отклонение общего результата.

```js
const results = await Promise.allSettled([
  saveProfile(),
  uploadAvatar(),
]);

for (const result of results) {
  if (result.status === "fulfilled") {
    console.log(result.value);
  } else {
    console.error(result.reason);
  }
}
```

Отклонение входного Promise не отклоняет общий результат: оно становится записью `{ status: "rejected", reason }`. Итоговый Promise может отклониться из-за ошибки при получении или обходе самого итерируемого объекта, но это отдельный редкий случай.

### `Promise.race`

`Promise.race` принимает результат первого завершившегося Promise. Он не ищет первый успех: быстрое отклонение победит более позднее успешное выполнение.

Тайм-аут часто моделируют как гонку операции и Promise-таймера, но проигравшая работа продолжит выполняться. Для сетевого запроса тайм-аут должен также вызвать `AbortController.abort()`, иначе запрос продолжит потреблять ресурсы и может завершиться после того, как интерфейс уже показал ошибку времени ожидания.

Пустой `Promise.race([])` навсегда остаётся в состоянии `pending`, потому что ни один входной элемент не может определить результат.

### `Promise.any`

`Promise.any` игнорирует отдельные отклонения и ждёт первый успешный результат. Это подходит для нескольких взаимозаменяемых источников. Если отклонены все элементы, причиной становится `AggregateError`, а его поле `errors` содержит отдельные ошибки в порядке входа.

Параллельный запрос к нескольким копиям backend может увеличить нагрузку или продублировать побочные эффекты. `any` уместен для безопасных взаимозаменяемых операций чтения, но не делает операции изменения данных безопасными.

### Пустой входной набор

`Promise.all([])` и `Promise.allSettled([])` возвращают уже успешно выполненный Promise, а `Promise.any([])` - уже отклонённый. Но обработчики `then` и `catch` всё равно выполняются как микрозадачи, а не внутри текущего стека вызовов.

```js
Promise.all([]).then(() => console.log("microtask"));
console.log("sync");

// sync
// microtask
```

### Ограничение одновременных операций

Комбинатор не ограничивает количество одновременно выполняющихся операций:

```js
const requests = urls.map((url) => fetch(url));
const responses = await Promise.all(requests);
```

`map` синхронно вызывает `fetch` для каждого URL до вызова `Promise.all`. Для сотен элементов это может исчерпать доступные сетевые соединения и нагрузить backend или память. Число одновременных операций ограничивают очередью, пулом, batch API или библиотекой с явным лимитом.

Последовательный `for...of` с `await` выполняет по одной операции за раз. Это правильно для зависимых шагов, но медленнее для независимых. Выбор определяется зависимостями, допустимой нагрузкой и обработкой ошибок, а не правилом «параллельно всегда лучше».

## Пример

```js
const delay = (ms, value, shouldReject = false) =>
  new Promise((resolve, reject) => {
    setTimeout(() => {
      if (shouldReject) {
        reject(value);
      } else {
        resolve(value);
      }
    }, ms);
  });

async function demonstrate() {
  const all = await Promise.all([
    delay(50, "first input"),
    delay(10, "second input"),
  ]);
  console.log(all); // ["first input", "second input"]

  const report = await Promise.allSettled([
    delay(10, "ok"),
    delay(20, new Error("failed"), true),
  ]);
  console.log(report[1].status); // rejected

  const value = await Promise.any([
    delay(5, new Error("fast failure"), true),
    delay(30, "first success"),
  ]);
  console.log(value); // first success
}
```

`Promise.all` сохраняет входной порядок, несмотря на более быстрое завершение второго элемента. `allSettled` возвращает обе записи, а `any` игнорирует первое отклонение и ждёт успешный результат.

## Где применяется во frontend

| Требование сценария | Метод | Существенная граница |
| --- | --- | --- |
| Все независимые данные обязательны | `Promise.all` | один rejection завершает общий результат, но не отменяет остальные операции |
| Нужен отчёт по каждому действию | `Promise.allSettled` | вызывающий код сам интерпретирует каждый `status` |
| Нужен первый результат | `Promise.race` | быстрое отклонение также выигрывает |
| Нужен первый успешный результат чтения | `Promise.any` | все ошибки собираются в `AggregateError` |
| Сотни одновременных операций | пул или очередь поверх Promise | комбинатор не ограничивает параллелизм |

## Ключевые уточнения

- `all` и `allSettled` возвращают результаты в порядке входа, а не завершения.
- `race` принимает первый завершившийся результат, а `any` - первый успешный.
- Ранний результат комбинатора не отменяет и не откатывает исходные операции.
- Обычные значения и thenable-объекты нормализуются по процедуре разрешения Promise.
- Количество одновременно выполняющихся операций определяется моментом их запуска; `Promise.all` не является планировщиком или пулом.
