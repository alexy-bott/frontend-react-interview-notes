## Быстрый ответ

Autoboxing - учебное название преобразования примитива в объектную форму при доступе к его свойствам. Например, для `"hello".toUpperCase()` JavaScript получает доступ к поведению `String.prototype`, вызывает метод со строковым примитивом как значением `this`, а результат снова остаётся примитивом.

Спецификация описывает это через абстрактную операцию `ToObject`. Это не означает, что движок обязан физически выделять новый объект-обёртку при каждом вызове: реализация может оптимизировать операцию, сохраняя наблюдаемое поведение языка.

Объектные обёртки существуют для `string`, `number`, `boolean`, `bigint` и `symbol`. `null` и `undefined` преобразовать в объект нельзя, поэтому доступ к их свойствам без optional chaining приводит к `TypeError`. Создавать обёртки вручную через `new String("x")` или `new Boolean(false)` почти никогда не нужно: это объекты со своей идентичностью, и в логическом контексте они всегда являются truthy.

## Ключевая схема

| Значение | Что происходит при доступе к методу |
| --- | --- |
| `"hi".toUpperCase()` | используется объектное представление `String` |
| `(42).toFixed(2)` | используется объектное представление `Number` |
| `true.valueOf()` | используется объектное представление `Boolean` |
| `null.toString()` | возникает `TypeError` |
| `undefined.toString()` | возникает `TypeError` |

## Базовая модель

Примитив не хранит собственные пользовательские свойства и не становится постоянным объектом после вызова метода. При доступе к свойству JavaScript использует объектное представление значения, ищет свойство по соответствующей цепочке прототипов и затем читает найденное значение.

Для строк объектное представление также предоставляет индексные свойства и `length`. При этом строка остаётся неизменяемой: `text[0] = "H"` не изменяет существующее значение, а `toUpperCase()` возвращает новую строку.

Объект-обёртка и примитив различаются по типу, сравнению и преобразованию к `boolean`. `typeof "x"` возвращает `"string"`, а `typeof new String("x")` - `"object"`; два разных объекта-обёртки не равны через `===`, даже если содержат одинаковый примитив.

## Развернутый ответ

### Откуда берутся методы

Методы `String.prototype`, `Number.prototype` и других встроенных прототипов являются обычными функциями. Доступ к свойству примитива позволяет найти эти методы, а вызов передаёт исходное значение как `this`. Многие методы затем проверяют, совместимо ли значение-получатель с ожидаемым типом.

`String`, `Number` и `Boolean` ведут себя по-разному с `new` и без него. `String(123)` явно возвращает примитив `"123"`, а `new String(123)` создаёт объект-обёртку. `Symbol` и `BigInt` можно вызывать для создания примитивов, но нельзя вызывать через `new`.

### Запись свойства

Запись пользовательского свойства в примитив не создаёт постоянное состояние. В скрипте без strict mode такая запись обычно игнорируется, а в strict mode приводит к `TypeError`. Поэтому примитив нельзя использовать как контейнер для дополнительных полей.

### `null`, `undefined` и optional chaining

Операция `ToObject(null)` или `ToObject(undefined)` выбрасывает `TypeError`. Optional chaining `value?.method()` не создаёт объектную обёртку для отсутствующего значения: он останавливает цепочку и возвращает `undefined`. Если значение существует, выполняется обычный доступ к свойству.

### Почему ручные wrappers мешают

Любой объект является truthy, включая `new Boolean(false)`. Обёртка сравнивается по идентичности и может не пройти проверку API, ожидающую примитив. Получить внутреннее примитивное значение можно через `valueOf()`, но чаще правильнее вообще не создавать обёртку.

## Пример

```js
const text = "hello";

console.log(text.toUpperCase()); // "HELLO"
console.log(text); // "hello": исходная строка не изменилась
console.log(typeof text); // "string"
```

```js
const value = new Boolean(false);

if (value) {
  console.log("wrapper object is truthy");
}

console.log(value === false); // false
console.log(value.valueOf() === false); // true
```

## Где применяется во frontend

Autoboxing объясняет, почему у примитивов доступны методы, почему строку нельзя изменить по индексу и почему созданные вручную объекты-обёртки ведут себя иначе в `typeof`, `===` и `if`. В прикладном коде обычно используют примитивы и явные функции преобразования `String(value)`, `Number(value)`, `Boolean(value)` без `new`.

## Ключевые уточнения

- `ToObject` является спецификационной моделью; движок не обязан физически создавать обёртку при каждом доступе к свойству.
- Вызов метода не превращает примитив в постоянный объект и не делает его изменяемым.
- `null` и `undefined` не имеют объектной формы для доступа к свойствам.
- `new String`, `new Number` и `new Boolean` создают объекты, а вызов этих функций без `new` возвращает примитив.
- Объект-обёртка всегда truthy и сравнивается по идентичности, поэтому `new Boolean(false)` не ведёт себя как `false`.
