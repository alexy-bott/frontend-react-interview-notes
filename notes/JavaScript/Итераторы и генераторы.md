## Быстрый ответ

Итерируемый объект (`iterable`) предоставляет метод `[Symbol.iterator]()` и тем самым объясняет JavaScript, как последовательно получать значения. Метод возвращает итератор (`iterator`) - объект с методом `next()`, который выдаёт `{ value, done }`.

Этот протокол используют `for...of`, spread, деструктуризация, `Array.from`, `Set`, `Map` и комбинаторы Promise. Обычный объект не является итерируемым автоматически, потому что для его свойств нет единственного очевидного порядка и формы выдаваемого значения.

Функция-генератор `function*` упрощает создание итератора. Её вызов не выполняет тело сразу, а возвращает объект-генератор. Каждый `next()` продолжает выполнение до следующего `yield`, поэтому значения можно вычислять лениво, не создавая весь массив заранее.

Асинхронный итерируемый объект использует `Symbol.asyncIterator`, а его `next()` возвращает Promise. Потребитель обходит такую последовательность через `for await...of`.

## Ключевая схема

```text
iterable
└─ [Symbol.iterator]()
   └─ iterator
      ├─ next() → { value, done: false }
      ├─ next() → { value, done: false }
      └─ next() → { value, done: true }
```

| Сущность | Обязательный контракт |
| --- | --- |
| Итерируемый объект | `[Symbol.iterator]()` возвращает итератор |
| Итератор | `next()` возвращает результат итерации |
| Результат итерации | объект с `done` и необязательным `value` |
| Асинхронный итерируемый объект | `[Symbol.asyncIterator]()` возвращает асинхронный итератор |
| Асинхронный итератор | `next()` возвращает Promise с результатом итерации |

## Итерируемый объект и итератор

У итерируемого объекта можно запросить новый итератор. Итератор хранит текущее положение конкретного обхода.

```js
const values = ["a", "b"];
const iterator = values[Symbol.iterator]();

console.log(iterator.next()); // { value: "a", done: false }
console.log(iterator.next()); // { value: "b", done: false }
console.log(iterator.next()); // { value: undefined, done: true }
```

Массив является итерируемым объектом и при каждом вызове `[Symbol.iterator]()` создаёт новый независимый итератор:

```js
const first = values[Symbol.iterator]();
const second = values[Symbol.iterator]();

first.next();  // "a"
second.next(); // тоже "a"
```

Многие итераторы сами являются итерируемыми и возвращают `this` из `[Symbol.iterator]()`. Такой объект обычно одноразовый: повторный `for...of` продолжит с текущей позиции, а не начнёт заново.

## Что использует протокол итерации

```js
for (const value of iterable) {}

const copy = [...iterable];
const [first, second] = iterable;
const array = Array.from(iterable);
const set = new Set(iterable);
await Promise.all(iterableOfPromises);
```

Все эти операции получают итератор и вызывают `next()` до `done: true` либо до досрочного завершения потребителя.

`for...in` использует другую модель: перечисляет строковые свойства объекта с `enumerable: true`, включая унаследованные. Для значений итерируемого объекта используют `for...of`.

```js
const values = ["a", "b"];

for (const key in values) {
  console.log(key); // "0", "1"
}

for (const value of values) {
  console.log(value); // "a", "b"
}
```

## Почему обычный объект не итерируется автоматически

```js
const user = { id: 1, name: "Ann" };

// for (const value of user) {} // TypeError
```

Неочевидно, что должен выдавать обход: ключи, значения или пары. Выбор делают явно:

```js
for (const key of Object.keys(user)) {}
for (const value of Object.values(user)) {}
for (const [key, value] of Object.entries(user)) {}
```

Собственный протокол итерации оправдан, если у предметной сущности есть один естественный порядок значений. Добавлять `[Symbol.iterator]` только ради необычного синтаксиса не стоит.

## Пользовательский итерируемый объект

```js
function createRange(start, end) {
  return {
    [Symbol.iterator]() {
      let current = start;

      return {
        next() {
          if (current <= end) {
            return {
              value: current++,
              done: false,
            };
          }

          return {
            value: undefined,
            done: true,
          };
        },
      };
    },
  };
}

console.log([...createRange(2, 4)]); // [2, 3, 4]
```

Состояние `current` принадлежит конкретному итератору, поэтому два одновременных обхода не мешают друг другу.

## Функция-генератор

Функция-генератор обозначается `function*`, а точки приостановки - `yield`:

```js
function* range(start, end) {
  for (let value = start; value <= end; value += 1) {
    yield value;
  }
}

const iterator = range(2, 4);

iterator.next(); // { value: 2, done: false }
iterator.next(); // { value: 3, done: false }
```

Вызов `range()` только создаёт объект-генератор. Тело начинает выполняться при первом `next()` и останавливается на `yield`. Локальные привязки и позиция выполнения сохраняются между продолжениями.

Объект-генератор одновременно является итератором и итерируемым объектом:

```js
console.log(iterator[Symbol.iterator]() === iterator); // true
```

Это делает его удобным для `for...of`, но обход одноразовый.

## Значение `yield` и `next(value)`

Выражение `yield` отдаёт значение наружу и приостанавливает генератор. Аргумент следующего `next(value)` становится результатом приостановленного `yield` внутри генератора:

```js
function* conversation() {
  const answer = yield "question";
  return `received: ${answer}`;
}

const iterator = conversation();

iterator.next();       // { value: "question", done: false }
iterator.next("yes"); // { value: "received: yes", done: true }
```

Аргумент первого `next()` передать в ещё не начатый `yield` некуда, поэтому он игнорируется.

Значение `return` появляется в финальном результате итерации с `done: true`, но обычный `for...of` и spread его не включают.

## `yield*`

`yield* iterable` делегирует часть последовательности другому итерируемому объекту:

```js
function* menu() {
  yield "home";
  yield* ["catalog", "profile"];
  yield "logout";
}

console.log([...menu()]);
// ["home", "catalog", "profile", "logout"]
```

Это позволяет собирать цепочку из небольших генераторов без ручного цикла.

## Ленивость

Массив заранее хранит все элементы. Генератор вычисляет следующий элемент по запросу:

```js
function* naturalNumbers() {
  let value = 1;

  while (true) {
    yield value++;
  }
}
```

Бесконечная последовательность безопасна только при конечном потреблении:

```js
const numbers = naturalNumbers();
numbers.next(); // 1
numbers.next(); // 2
```

`[...naturalNumbers()]` никогда не завершится и будет расходовать память. Ленивость переносит контроль потребления на caller, но не создаёт лимит автоматически.

Генераторы полезны для больших данных, обхода дерева и потоковой обработки. Для небольшой готовой коллекции массив обычно проще и предоставляет больше методов.

## Досрочное завершение и освобождение ресурсов

Если `for...of` завершается через `break`, `throw` или `return`, он вызывает `iterator.return()`, если метод существует. Генератор использует это для выполнения `finally`:

```js
function* readRows() {
  try {
    yield* rows;
  } finally {
    closeCursor();
  }
}

for (const row of readRows()) {
  if (row.id === targetId) {
    break;
  }
}
```

Освобождение ресурсов должно быть идемпотентным и не зависеть только от сборщика мусора. Пользовательский итератор, владеющий ресурсом, реализует `return()` явно.

## Асинхронная итерация и async generator

Асинхронный итератор возвращает Promise для каждого результата итерации. `for await...of` ожидает эти результаты по одному:

```js
async function* pages() {
  let cursor;

  do {
    const page = await loadPage(cursor);
    yield page.items;
    cursor = page.nextCursor;
  } while (cursor);
}

for await (const items of pages()) {
  renderPage(items);
}
```

Это модель последовательного запроса данных: следующая страница загружается по мере продолжения обхода. Async generator сам по себе не делает операции параллельными.

`for await...of` также принимает обычный синхронный итерируемый объект и ожидает выдаваемые значения, но для массива без Promise обычно яснее `for...of`.

Отмена должна передаваться отдельно, например через `AbortSignal`, а досрочный `break` должен позволить итератору освободить ресурсы.

## Где применяется во frontend

- `for...of` обходит массивы, Set, ключи и значения Map и DOM-коллекции по протоколу итерации.
- Генератор лениво обходит дерево или формирует последовательность без промежуточного массива.
- Async generator представляет курсорную пагинацию или части `ReadableStream` как последовательность.
- Пользовательский итерируемый объект задаёт один естественный обход предметной коллекции.
- `iterator.return()` освобождает курсор, подписку или reader при досрочном выходе.

## Ключевые уточнения

- Итерируемый объект создаёт итератор, а итератор хранит состояние конкретного обхода.
- `for...of` читает значения по протоколу итерации; `for...in` перечисляет строковые ключи.
- Обычный объект не итерируется автоматически, потому что форму обхода нужно явно выбрать через keys, values или entries.
- Вызов функции-генератора не выполняет тело; работу продвигают `next()` и потребители протокола.
- Генератор вычисляет значения лениво и обычно одноразов, но сам не ограничивает бесконечное потребление.
- `break` может вызвать `iterator.return()` и запустить освобождение ресурсов.
- Асинхронный итерируемый объект возвращает Promise с результатами итерации и обходится через `for await...of`.
