## Быстрый ответ

Строка JavaScript - неизменяемая последовательность 16-битных кодовых единиц UTF-16 (`code units`). Свойство `length` и индекс `string[i]` считают кодовые единицы, а не обязательно кодовые точки Unicode (`code points`) и тем более не видимые пользователю символы, или графемные кластеры (`grapheme clusters`).

Символы за пределами Basic Multilingual Plane кодируются суррогатной парой (`surrogate pair`) и имеют `length === 2`. `for...of` и `Array.from` обходят кодовые точки, но один видимый emoji может состоять из нескольких кодовых точек, соединённых селектором варианта, комбинируемым знаком или соединителем нулевой ширины.

Для пользовательского текста длину и обрезку по графемам выполняют через `Intl.Segmenter` или проверенную Unicode-библиотеку. Для байтов в сети или файле используют `TextEncoder` и `TextDecoder`; строка сама по себе не является массивом байтов UTF-8.

## Ключевая схема

```text
кодовая единица UTF-16 → string.length, charCodeAt, index/slice
кодовая точка Unicode  → for...of, codePointAt, fromCodePoint
графемный кластер      → видимый пользователю символ, Intl.Segmenter
закодированные байты   → UTF-8 или другая кодировка, TextEncoder/TextDecoder
```

```js
"A".length;  // 1 кодовая единица
"😀".length; // 2 кодовые единицы, 1 кодовая точка, 1 графема
```

## Immutability

Строковый примитив нельзя изменить по индексу:

```js
let value = "cat";
value[0] = "b";
console.log(value); // "cat"

value = "b" + value.slice(1); // новая строка "bat"
```

Методы строк возвращают новое значение. Переменная может быть переназначена, но исходная строка остаётся неизменяемой.

## Кодовые единицы и суррогатные пары

UTF-16 представляет часть кодовых точек одной кодовой единицей, а значения выше `U+FFFF` - парой суррогатов:

```js
const emoji = "😀";

emoji.length;        // 2
emoji[0];             // первая половина суррогатной пары
emoji.charCodeAt(0);  // кодовая единица
emoji.codePointAt(0); // полная кодовая точка 0x1F600
```

`slice(0, 1)` может разрезать суррогатную пару и создать некорректную последовательность для отображения или кодирования. Для обхода по кодовым точкам:

```js
[..."A😀B"]; // ["A", "😀", "B"]
```

Spread использует строковый итератор и не делит корректную суррогатную пару.

## Графемные кластеры

Пользователь воспринимает не кодовые точки, а графемные кластеры. Буква с комбинируемым знаком и сложный emoji могут состоять из нескольких кодовых точек:

```js
const family = "👨‍👩‍👧‍👦";

family.length; // много кодовых единиц UTF-16
[...family].length; // несколько кодовых точек
// визуально одна графема
```

Сегментация:

```js
const segmenter = new Intl.Segmenter("ru", {
  granularity: "grapheme",
});

const graphemes = [...segmenter.segment(text)].map(
  ({ segment }) => segment,
);
```

Это нужно для счётчика символов, навигации курсора и безопасной визуальной обрезки. Требование продукта должно определить, что ограничивается: байты, кодовые точки или графемы. Это разные метрики.

## Нормализация Unicode

Один и тот же визуальный текст может иметь разные последовательности кодовых точек:

```js
const composed = "é";       // U+00E9
const decomposed = "e\u0301"; // U+0065 + combining mark

composed === decomposed; // false
composed.normalize("NFC") === decomposed.normalize("NFC"); // true
```

Нормализация полезна для поиска, дедупликации и правил идентификаторов, если предметная область считает формы эквивалентными. Она не выполняет регистровое преобразование с учётом языка и не устраняет визуально похожие символы из разных систем письма.

Для чувствительных к безопасности идентификаторов нужны отдельные правила для похожих Unicode-символов и согласованная нормализация на backend; одного `.normalize()` недостаточно.

## Case conversion и сравнение

```js
value.toLowerCase();
value.toLocaleLowerCase("tr");
```

Правила регистра зависят от локали. Для пользовательской сортировки используют `Intl.Collator` или `localeCompare`, а не простой `<`, который сравнивает кодовые единицы UTF-16:

```js
const collator = new Intl.Collator("ru", {
  sensitivity: "base",
});

names.toSorted(collator.compare);
```

Сравнение с учётом локали подходит для порядка отображения, но ключ хранилища или кэша должен формироваться по явно выбранным правилам канонизации. Результат сортировки может зависеть от локали и параметров.

## Строка и байты

JavaScript предоставляет строковую абстракцию, а сетевой или файловый протокол использует байты в конкретной кодировке. Для UTF-8:

```js
const encoder = new TextEncoder();
const bytes = encoder.encode("Привет"); // Uint8Array с байтами UTF-8

const decoder = new TextDecoder("utf-8");
const text = decoder.decode(bytes);
```

Длина в байтах не равна `string.length`:

```js
new TextEncoder().encode("😀").byteLength; // 4 байта UTF-8
"😀".length; // 2 кодовые единицы UTF-16
```

Это важно для ограничений протокола, размера загрузки, входных данных криптографии и бинарного формата.

`btoa` и `atob` исторически работают с бинарными строками и байтами и не принимают произвольный Unicode-текст напрямую без предварительного кодирования.

## Template literals

```js
const message = `Hello, ${user.name}`;
```

Интерполяция преобразует выражение в строку. Шаблонный литерал не экранирует HTML или SQL автоматически: безопасная обработка зависит от места назначения. React экранирует текстовую интерполяцию, а `innerHTML` и `dangerouslySetInnerHTML` требуют отдельной политики очистки.

Tagged template получает исходные и обработанные сегменты строки и подставленные значения. Он может реализовать экранирование для конкретной задачи, но безопасность зависит от реализации функции-тега.

## Поиск и обрезка

`includes`, `startsWith` и `indexOf` ищут последовательности кодовых единиц и не выполняют нормализацию или сравнение с учётом локали автоматически.

```js
"JavaScript".includes("Script"); // true
```

Для пользовательского поиска без учёта регистра обычно нормализуют обе стороны по согласованным правилам или применяют `Intl.Collator`. Простого `toLowerCase()` может быть недостаточно для всех локалей.

Регулярное выражение без Unicode-флага может работать с отдельными половинами суррогатной пары; для Unicode-шаблонов используют современную семантику флагов `u` или `v` согласно задаче.

## Где применяется во frontend

- Счётчик символов считает графемы, если ограничение сформулировано для пользователя.
- Поиск нормализует текст и использует правила локали, согласованные с backend.
- Сетевой протокол кодирует строку в байты UTF-8 через `TextEncoder`.
- Для сортировки имён используют `Intl.Collator`, а не стандартное строковое сравнение `Array.prototype.sort`.
- UI не обрезает строку по произвольному индексу кодовой единицы внутри emoji.
- HTML экранируется по контексту независимо от использования шаблонного литерала.

## Ключевые уточнения

- Длина строки считает кодовые единицы UTF-16, а не гарантированные видимые символы.
- `for...of` правильно обходит суррогатные пары на уровне кодовых точек, но не объединяет все графемные кластеры.
- `Intl.Segmenter` нужен, когда продукт оперирует пользовательскими символами.
- Одинаково выглядящие строки могут различаться формой нормализации Unicode.
- Строка и байты UTF-8 являются разными уровнями; длину в байтах вычисляют после кодирования.
- Преобразование регистра и сортировка с учётом локали требуют `Intl`, а обычное сравнение не знает языка пользователя.
- Template literal не предоставляет автоматическое escaping для произвольного sink.
