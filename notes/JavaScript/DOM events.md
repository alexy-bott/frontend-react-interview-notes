## Быстрый ответ

DOM-события - механизм браузера для уведомления JavaScript о действиях пользователя и изменениях в среде: клике, вводе, отправке формы, загрузке ресурса. Браузер создаёт объект события и синхронно передаёт его обработчикам по заранее построенному пути в DOM-дереве.

Распространение состоит из трёх фаз: перехват (`capture`) идёт от корня к целевому узлу, затем событие достигает цели (`target`), после чего всплытие (`bubble`) возвращает его к предкам. Большинство обработчиков `addEventListener` работают на фазе всплытия; перехват включают через `{ capture: true }`.

`event.target` показывает исходную цель события, а `event.currentTarget` - объект, чей обработчик выполняется сейчас. На всплытии основано делегирование: один обработчик контейнера может обслуживать множество дочерних элементов, включая добавленные позже.

## Ключевая схема

```text
браузер получает ввод
→ определяет цель события
→ строит путь распространения
→ capture: Window → Document → ... → родитель
→ target: целевой узел
→ bubble: родитель → ... → Document → Window
→ браузер может выполнить действие по умолчанию, если оно не отменено
```

Не каждое событие всплывает и не у каждого есть отменяемое действие по умолчанию. Это свойства конкретного типа события, доступные через `event.bubbles` и `event.cancelable`.

## Откуда берётся событие

DOM и события принадлежат браузерной среде, а не самому языку ECMAScript. Источником может быть пользовательский ввод, таймер, сетевой ресурс, изменение состояния документа или вызов `dispatchEvent()` из JavaScript.

Для события браузер определяет `target` и строит путь до предков. Затем один процесс отправки (`dispatch`) синхронно обходит обработчики. Если обработчик выполняет долгий код, следующие обработчики, рендеринг и другие задачи ждут освобождения основного потока.

Событие от пользовательского ввода обычно обрабатывается внутри задачи event loop. Callbacks Promise, добавленные обработчиком в очередь микрозадач, выполнятся после завершения текущего синхронного кода и всей отправки события, а не между соседними строками обработчика.

## Фазы распространения

```js
const parent = document.querySelector("#parent");
const button = document.querySelector("#save");

parent.addEventListener(
  "click",
  () => console.log("parent capture"),
  { capture: true },
);

button.addEventListener("click", () => console.log("button"));
parent.addEventListener("click", () => console.log("parent bubble"));
```

При клике по кнопке порядок будет таким:

```text
parent capture
button
parent bubble
```

На целевом узле сначала выполняются обработчики, зарегистрированные для capture, затем обычные обработчики. После этого событие продолжает всплытие, если его тип поддерживает всплытие и распространение не остановлено.

## `target`, `currentTarget` и `this`

| Свойство | Что означает |
| --- | --- |
| `event.target` | объект, на котором событие возникло с точки зрения текущего дерева |
| `event.currentTarget` | объект, обработчик которого сейчас выполняется |
| `event.eventPhase` | текущая фаза: перехват, цель или всплытие |
| `event.composedPath()` | фактический путь распространения с учётом Shadow DOM |

У обычного обработчика-функции `this` равен `currentTarget`. У стрелочной функции собственного `this` нет, поэтому для ясности лучше читать `event.currentTarget` явно.

`currentTarget` имеет значение только во время выполнения обработчика. Если сохранить объект события и прочитать свойство позже, оно будет `null`.

## Что происходит при клике на кнопку

Для мыши или указателя типичная последовательность выглядит так:

```text
pointerdown → mousedown → возможная смена focus
→ pointerup → mouseup → click
→ действие кнопки по умолчанию
```

Каждый элемент последовательности - отдельное событие со своим dispatch. Точный набор и порядок могут зависеть от устройства, браузера, отменённых действий и того, оставался ли указатель на допустимой цели.

Перед отправкой события браузер выполняет hit testing: по координатам и layout определяет элемент, в который попал указатель. Затем строится путь распространения и синхронно вызываются обработчики.

После `click` браузер может выполнить действие элемента по умолчанию. Например, `<button type="submit">` запускает отправку связанной формы, а ссылка начинает навигацию. `preventDefault()` отменяет это действие, если событие допускает отмену, но не останавливает остальные обработчики и всплытие.

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();
  saveForm(new FormData(event.currentTarget));
});
```

Для формы правильнее обрабатывать `submit`, а не только `click` кнопки: submit может быть вызван клавишей Enter, другой submit-кнопкой или программным API.

## Управление событием

| Метод | Результат |
| --- | --- |
| `preventDefault()` | отменяет действие браузера по умолчанию, если `cancelable === true` |
| `stopPropagation()` | запрещает переход к следующим узлам пути |
| `stopImmediatePropagation()` | дополнительно останавливает оставшиеся обработчики на текущем узле |

`stopPropagation()` не отменяет переход по ссылке или submit формы. `preventDefault()` не останавливает всплытие. Эти методы решают разные задачи.

Остановка распространения нужна редко. Она может помешать обработчику верхнего уровня, аналитике, глобальному сочетанию клавиш или механизму закрытия overlay. Сначала лучше разделить обработчики по цели и состоянию, а распространение останавливать только при реальном конфликте поведения.

В passive-обработчике вызов `preventDefault()` не сработает. Настройка `{ passive: true }` обещает браузеру, что обработчик не будет отменять действие; это важно прежде всего для событий, влияющих на прокрутку.

## Делегирование событий

Делегирование переносит обработчик с множества дочерних элементов на их общего предка. На фазе всплытия контейнер получает событие и определяет подходящего потомка через `closest()`.

```js
const list = document.querySelector("#users");

list.addEventListener("click", (event) => {
  if (!(event.target instanceof Element)) {
    return;
  }

  const button = event.target.closest("button[data-user-id]");

  if (!button || !list.contains(button)) {
    return;
  }

  selectUser(button.dataset.userId);
});
```

Проверка типа нужна потому, что `target` имеет тип `EventTarget`, а не обязательно `Element`. `closest()` учитывает клик по вложенной иконке или тексту внутри кнопки. Проверка границы контейнера не даёт случайно обработать найденный элемент за пределами делегируемой области.

Делегирование особенно полезно для динамических списков и таблиц: новый дочерний элемент сразу обслуживается существующим обработчиком. Оно не обязательно быстрее в каждом случае; главный выигрыш - единая логика и простой жизненный цикл слушателя.

## События, которые ведут себя иначе

`focus` и `blur` не всплывают; для делегирования обычно используют `focusin` и `focusout`. `mouseenter` и `mouseleave` тоже не всплывают; иногда их заменяют на `mouseover` и `mouseout`, но тогда нужно учитывать переходы между потомками через `relatedTarget`.

`scroll` обычно слушают на конкретном прокручиваемом элементе. Для наблюдения за попаданием элемента в область просмотра (`viewport`) вместо частого `scroll`-обработчика часто лучше подходит `IntersectionObserver`.

Выбор замены должен опираться на семантику события, а не только на способность всплывать: `mouseover` генерируется при переходах между дочерними элементами, а `mouseenter` - нет.

## Жизненный цикл обработчика

`addEventListener` поддерживает несколько полезных настроек:

| Настройка | Назначение |
| --- | --- |
| `capture` | выполнять обработчик на фазе перехвата |
| `once` | автоматически удалить после первого выполнения |
| `passive` | обещать отсутствие `preventDefault()` |
| `signal` | удалить слушатель при отмене `AbortSignal` |

Для `removeEventListener` нужна та же функция и то же значение `capture`, что при добавлении. Анонимную функцию, созданную заново, удалить таким способом нельзя. `AbortSignal` удобен, когда несколько слушателей принадлежат одному жизненному циклу:

```js
const controller = new AbortController();

window.addEventListener("resize", onResize, {
  signal: controller.signal,
});

document.addEventListener("keydown", onKeyDown, {
  signal: controller.signal,
});

controller.abort();
```

## Shadow DOM

При переходе через границу Shadow DOM браузер может изменить видимый `event.target`, чтобы скрыть внутреннее устройство компонента. Это называется retargeting (переназначением цели). `event.composedPath()` показывает путь точнее, а свойство `composed` определяет, может ли событие пересечь границу Shadow DOM.

Для обычной вёрстки достаточно `target` и `closest()`. `composedPath()` становится важен в Web Components и компонентах с Shadow DOM, где визуально вложенный элемент не обязательно виден внешнему обработчику как исходная цель.

## Где применяется во frontend

- Делегирование обслуживает строки таблицы или пункты меню одним обработчиком и автоматически охватывает новые элементы.
- Обработка `submit` с `preventDefault()` сохраняет семантику формы для мыши, клавиатуры и программного вызова.
- Фаза capture позволяет перехватить событие до дочернего компонента, например для инфраструктурного логирования, но требует осторожности.
- `AbortSignal` связывает удаление нескольких слушателей с закрытием экрана или виджета.
- `composedPath()` помогает диагностировать события в компонентах с Shadow DOM.

## Ключевые уточнения

- Одна отправка события вызывает обработчики синхронно; event loop планирует задачу, внутри которой происходит эта отправка.
- `target` обозначает цель события, `currentTarget` - текущий узел с обработчиком.
- `preventDefault()` отменяет действие по умолчанию, а `stopPropagation()` и `stopImmediatePropagation()` управляют дальнейшим распространением.
- Делегирование работает благодаря всплытию и требует проверки подходящего потомка и границы контейнера.
- Не все события всплывают, отменяются или пересекают Shadow DOM.
- `stopImmediatePropagation()` сильнее `stopPropagation()`: он останавливает и другие обработчики текущего узла.
- Клик - не единственный путь активации элемента; семантическое событие `submit` или `change` часто надёжнее обработки одной мыши.
