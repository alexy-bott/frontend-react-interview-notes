## Быстрый ответ

Чистая функция (`pure function`) при одинаковых входных данных даёт одинаковый результат и не создаёт наблюдаемых побочных эффектов. Она не меняет аргументы или внешнее состояние, не обращается к DOM, сети и хранилищу и не получает скрытые данные из времени, случайности или изменяемого глобального состояния.

Такую функцию можно заменить её результатом без изменения поведения программы; это свойство называют ссылочной прозрачностью (`referential transparency`). Благодаря ему функцию проще тестировать, повторять, кэшировать, выполнять в другом порядке и использовать в reducers, selectors, форматтерах и преобразованиях данных.

Чистота не запрещает любые локальные мутации. Функция может изменять созданный внутри неё массив, если этот массив не был доступен снаружи и наружу не наблюдается промежуточное состояние. Запрещена именно наблюдаемая мутация общих данных. API-запросы, логирование и DOM-операции остаются полезными эффектами, но их отделяют от чистых вычислений.

## Ключевая схема

| Критерий | Чистая функция | Функция с эффектами |
| --- | --- | --- |
| Одинаковый явный ввод | одинаковый результат | результат может зависеть от внешнего состояния |
| Общие данные | не читает изменяемое состояние и не мутирует его | может читать или изменять |
| Внешнее взаимодействие | отсутствует | сеть, DOM, хранилище, console |
| Повторный вызов | не меняет окружение | может создать новое наблюдаемое действие |
| Тест | аргументы → результат | требуется управлять окружением и эффектами |

## Базовая модель

У функции есть явные входы - параметры - и возможные скрытые входы: переменная модуля, текущее время, генератор случайных чисел, DOM или содержимое хранилища. Если скрытый ввод может меняться, одинакового списка аргументов недостаточно для предсказания результата.

Побочный эффект - наблюдаемое взаимодействие за пределами возвращаемого значения: мутация доступного снаружи объекта, запись в хранилище, сетевой запрос, изменение DOM, логирование, регистрация обработчика или таймера. Детерминированность сама по себе не гарантирует чистоту: функция может всегда возвращать `1`, но одновременно увеличивать глобальный счётчик.

Практичная архитектура делает эффекты явными на границе. Чистая часть вычисляет команду, данные запроса или новое состояние, а слой эффектов выполняет запрос, обновляет DOM или сохраняет данные. Это не удаляет эффекты из приложения, а локализует их.

## Развернутый ответ

### Мутация аргумента и локальная мутация

Мутация аргумента меняет общую объектную сущность, которую может видеть вызывающий код. Это побочный эффект, даже если функция дополнительно возвращает новый объект.

Локальная мутация только что созданного значения может оставаться внутренней реализацией:

```js
function squares(values) {
  const result = [];

  for (const value of values) {
    result.push(value * value);
  }

  return result;
}
```

`result` создан внутри вызова и не был доступен снаружи до возврата. Функция не изменяет `values` и при одинаковом массиве значений возвращает одинаковый результат.

### Скрытые входные данные

`Date.now()`, `Math.random()` и чтение изменяемого состояния модуля являются скрытыми входами. Их можно передать параметром или зависимостью, чтобы основное вычисление снова стало чистым и управляемым в тесте.

Замыкание не делает функцию нечистой автоматически. Замыкание над неизменяемой конфигурацией остаётся предсказуемым; чтение или изменение изменяемой привязки превращает её в скрытый вход или эффект.

### Reducers и рендеринг React

Reducer и тело React-компонента могут выполняться повторно, поэтому побочные эффекты внутри них способны дублироваться или происходить для результата, который не будет использован. Чистота позволяет React и инструментам управления состоянием безопасно повторять вычисление, сравнивать результаты и обнаруживать случайные мутации в development-режиме Strict Mode.

### Мемоизация

Мемоизация корректно переиспользует результат, если ключ кэша полностью описывает все значения, влияющие на вычисление. Для функции со скрытым изменяемым входом прежняя запись кэша может стать неверной. При этом чистота не означает, что мемоизация обязательно полезна: кэш требует памяти, сравнения ключей и инвалидации.

### Допустимые эффекты

Не каждая функция приложения должна быть чистой. Обработчик события закономерно отправляет запрос, функция аналитики записывает событие, а адаптер управляет браузерным API. Важно, чтобы эффект соответствовал назначению функции, находился на понятной границе и не прятался внутри функции, которая выглядит как обычное вычисление.

## Пример

Чистая функция:

```js
function addTodo(todos, title) {
  return [
    ...todos,
    {
      id: title.toLowerCase(),
      title,
    },
  ];
}
```

Нечистая функция:

```js
function addTodoMutating(todos, title) {
  todos.push({ title });
  localStorage.setItem("todos", JSON.stringify(todos));
  return todos;
}
```

Методы массивов без мутации также помогают сохранить входные данные:

```js
const sorted = items.toSorted((a, b) => a.name.localeCompare(b.name));
```

## Где применяется во frontend

| Ситуация | Чистая часть | Граница эффекта |
| --- | --- | --- |
| Обновление Redux | reducer вычисляет следующее состояние | middleware или thunk выполняет ввод-вывод |
| Форма | валидатор возвращает ошибки | обработчик `submit` отправляет запрос |
| React UI | компонент вычисляет JSX | Effect или обработчик синхронизируется с внешней системой |
| Аналитика | функция формирует данные события | адаптер отправляет событие |

## Ключевые уточнения

- Чистота требует и детерминированного результата, и отсутствия наблюдаемых побочных эффектов.
- Мутация локального объекта допустима, если он создан внутри вызова и не наблюдается снаружи во время изменения.
- Время, случайность и изменяемое состояние модуля являются скрытыми входами, если не переданы явно.
- Замыкание над неизменяемым значением может оставаться чистым; изменяемая привязка создаёт скрытую зависимость.
- Эффекты необходимы приложению, но их размещают на явных границах, а не внутри вычислительной функции.
