## Быстрый ответ

`Promise` - объект JavaScript, представляющий будущий результат операции. Сначала он находится в состоянии ожидания (`pending`), а затем один раз переходит либо в успешное состояние (`fulfilled`) со значением, либо в отклонённое (`rejected`) с причиной ошибки. Два конечных состояния вместе называют `settled`. Promise хранит результат, поэтому обработчики можно добавить как до, так и после завершения операции.

`then`, `catch` и `finally` всегда возвращают новый Promise. Обработчик может преобразовать значение, восстановиться после ошибки, выбросить новую ошибку или вернуть другой Promise. Поэтому цепочка Promise выражает последовательность зависимых асинхронных шагов без глубоко вложенных callbacks.

Обработчики не вызываются синхронно даже у уже завершённого Promise: они выполняются как микрозадачи после текущего JavaScript-кода. Promise не переносит вычисление в другой поток и не имеет состояния `cancelled`. Отменять нужно саму операцию через поддерживаемый ею механизм, например `AbortSignal` у `fetch`.

## Ключевая схема

```text
pending -> fulfilled(value)
        -> rejected(reason)

fulfilled/rejected = settled
```

```text
обработчик возвращает значение
-> next Promise fulfilled(value)

обработчик выбрасывает ошибку
-> next Promise rejected(error)

обработчик возвращает Promise/thenable
-> новый Promise принимает его будущий результат
```

## Базовая модель

Promise разделяет код, который создаёт результат, и код, который его использует. Производитель получает функции `resolve` и `reject`, а потребители регистрируют обработчики. Результат фиксируется один раз, но количество подписчиков не ограничено: каждый вызов `then` создаёт новый Promise.

Важно различать завершение (`settlement`) и принятие результата (`resolution`). `resolve(42)` успешно завершает Promise значением `42`. Но `resolve(otherPromise)` связывает его результат с `otherPromise`: повторный вызов `resolve` уже игнорируется, хотя внешне состояние может оставаться `pending`, пока `otherPromise` не завершится.

Promise описывает будущий результат, но не является самой операцией. Например, `fetch` запускает сетевой запрос и возвращает Promise. Отмена, прогресс, повтор и приоритет относятся к самой операции или к дополнительному слою абстракции.

## Развернутый ответ

### Executor выполняется синхронно

`new Promise(executor)` сразу вызывает executor - переданную конструктору функцию - в текущем стеке вызовов. Синхронный `throw` внутри executor превращается в отклонение Promise. Сам конструктор не делает код фоновым:

```js
console.log("A");

const promise = new Promise((resolve) => {
  console.log("B");
  resolve("value");
});

promise.then(() => console.log("D"));
console.log("C");
```

Результат: `A`, `B`, `C`, `D`. Executor выводит `B` синхронно, а обработчик `then` выполняется позже как микрозадача.

Ошибка, выброшенная позже в задаче таймера, уже не находится внутри синхронного вызова executor и не будет автоматически связана с этим Promise. Callback должен явно вызвать `reject` либо использовать API, который сам возвращает Promise.

### Принятие результата другого Promise

`resolve` принимает не только обычное значение. Если передан Promise или thenable - объект с вызываемым методом `then`, - выполняется процедура принятия его результата. Она защищает от повторных вызовов `resolve`/`reject` и от попытки разрешить Promise самим собой.

```js
const inner = new Promise((resolve) => {
  setTimeout(() => resolve("done"), 100);
});

const outer = new Promise((resolve) => {
  resolve(inner);
  resolve("ignored");
});

outer.then(console.log); // done
```

После `resolve(inner)` судьба `outer` зафиксирована, но успешное завершение произойдёт только вместе с `inner`. Поэтому `resolved` и `fulfilled` - не синонимы.

### `then` и цепочка

`then(onFulfilled, onRejected)` сразу возвращает новый Promise в состоянии `pending`. Когда исходный Promise завершается, подходящий обработчик ставится в очередь микрозадач. Его результат определяет состояние следующего Promise.

Если обработчик отсутствует, успешное значение проходит дальше без изменения, а ошибка передаётся до следующего подходящего обработчика. Поэтому один `catch` может обработать ошибки нескольких предыдущих шагов.

```js
loadUser()
  .then(normalizeUser)
  .then(renderUser)
  .catch(renderError);
```

Каждый шаг должен вернуть Promise или значение, если следующий шаг от него зависит. Забытый `return` превращает результат обработчика в `undefined`, а отдельно запущенный Promise перестаёт быть частью общей цепочки и её обработки ошибок.

### Ошибки и `catch`

`catch(onRejected)` эквивалентен `then(undefined, onRejected)`. Он получает причину отклонения исходного Promise и ошибки, выброшенные предыдущими обработчиками. Если `catch` возвращает обычное значение, следующий Promise становится успешно выполненным: цепочка восстановилась после ошибки. Чтобы ошибка продолжила распространяться, обработчик должен снова выполнить `throw` или вернуть отклонённый Promise.

Второй аргумент `then(onFulfilled, onRejected)` не ловит ошибку, выброшенную самим `onFulfilled`, потому что оба обработчика относятся к одному исходному Promise. Следующий `catch` поймает эту ошибку через Promise, возвращённый `then`.

### `finally`

`finally(callback)` не получает успешное значение или причину отклонения и обычно пропускает исходный результат дальше. Он подходит для общей очистки в обоих случаях: выключить индикатор загрузки, освободить ресурс, снять блокировку.

Если callback `finally` выбрасывает ошибку или возвращает отклонённый Promise, эта новая ошибка заменяет прежний результат. Возвращённое обычное значение игнорируется и не заменяет успешное значение цепочки.

### Микрозадачи и уже завершённый Promise

Регистрация `then` у уже успешно выполненного Promise всё равно не вызывает обработчик синхронно:

```js
const ready = Promise.resolve("ready");

ready.then(console.log);
console.log("sync");

// sync
// ready
```

Единая асинхронная семантика предотвращает ситуацию, когда один и тот же API иногда вызывает callback сразу, а иногда позже. Но длинная цепочка Promise всё равно выполняет JavaScript в основном потоке и может задержать рендеринг, если постоянно добавляет новые микрозадачи.

### Необработанное отклонение

Если отклонённый Promise вовремя не получает обработчик, браузер может создать событие `unhandledrejection`. Позднее добавление обработчика может породить `rejectionhandled`. Эти события полезны как последний уровень мониторинга, но не заменяют локальное восстановление сценария и понятное состояние ошибки в интерфейсе.

### Отмена

У Promise нет третьего состояния отмены. `AbortController.abort()` сообщает операции, что работу нужно прекратить. Если `fetch` получил этот сигнал, возвращённый Promise будет отклонён с соответствующей причиной. Сам Promise остаётся только контейнером результата операции.

## Пример

```js
function loadUser(id) {
  return fetch(`/api/users/${id}`)
    .then((response) => {
      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      return response.json();
    })
    .then((user) => ({
      id: user.id,
      name: user.name,
    }));
}

loadUser("42")
  .then((user) => {
    console.log("Loaded:", user.name);
  })
  .catch((error) => {
    console.error("Load failed", error);
    throw error;
  })
  .finally(() => {
    console.log("request finished");
  });
```

`loadUser` возвращает всю цепочку. Неуспешный HTTP-статус превращается в отклонение через `throw`, ошибка `response.json()` также попадёт в `catch`, а повторный `throw` продолжит распространение ошибки. `finally` выполнится при обоих исходах.

## Где применяется во frontend

| Ситуация | Роль Promise | Граница |
| --- | --- | --- |
| `fetch` | представляет будущий ответ или ошибку | HTTP 4xx/5xx нужно проверять отдельно |
| Последовательные преобразования | передаёт значение или ошибку по цепочке | каждый зависимый асинхронный шаг нужно вернуть |
| Параллельные запросы | объединяется статическим методом Promise | такой метод не отменяет операции автоматически |
| Обёртка callback API | даёт единый будущий результат | executor должен вызвать `resolve` или `reject` по контракту API |
| Отмена запроса | Promise отражает отклонение | саму работу отменяет `AbortSignal` |

## Ключевые уточнения

- Executor Promise выполняется синхронно; асинхронными могут быть запущенная им операция и последующие обработчики.
- `fulfilled` и `rejected` описывают конечное состояние, а `resolved` может означать принятие результата ещё ожидающего Promise.
- Каждый `then`, `catch` и `finally` возвращает новый Promise, состояние которого зависит от обработчика.
- Обработчики Promise всегда выполняются асинхронно как микрозадачи, даже после завершения исходного Promise.
- Promise не переносит вычисление в другой поток и не содержит встроенного состояния отмены.
