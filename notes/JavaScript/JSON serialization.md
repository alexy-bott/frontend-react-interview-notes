## Быстрый ответ

JSON - текстовый формат обмена данными, а не полная модель JavaScript-объекта. `JSON.stringify` сериализует поддерживаемую часть значения в строку, а `JSON.parse` разбирает JSON-текст и создаёт новые JavaScript-значения.

JSON поддерживает объекты, массивы, строки, числа, логические значения и `null`. Он не сохраняет `undefined`, функции, Symbol, BigInt, прототипы, дескрипторы свойств, Map/Set и идентичность объектов. Циклическая структура вызывает `TypeError`.

В объекте неподдерживаемые свойства пропускаются, а в массиве соответствующие элементы превращаются в `null`. `NaN` и бесконечности также сериализуются как `null`. `Date` обычно становится ISO-строкой через `toJSON()`.

Преобразование в JSON и обратно не является универсальной глубокой копией: оно теряет типы и данные. Ответ backend после `response.json()` остаётся недоверенным значением и требует проверки во время выполнения.

## Ключевая схема

```text
JavaScript-значение
→ JSON.stringify(value, replacer, space)
→ JSON text
→ JSON.parse(text, reviver)
→ новое JavaScript-значение
```

| JavaScript-значение | Результат в JSON |
| --- | --- |
| строка, конечное число, boolean, `null` | соответствующее значение JSON |
| обычный объект или массив | рекурсивная структура поддерживаемых значений |
| `undefined`, функция или Symbol в объекте | свойство пропускается |
| `undefined`, функция или Symbol в массиве | `null` |
| `NaN`, `Infinity`, `-Infinity` | `null` |
| `BigInt` | `TypeError` без явного правила сериализации |
| `Date` | ISO-строка через `toJSON` |
| `Map`, `Set` | обычно `{}` без функции `replacer` |
| цикл | `TypeError` |

## Синтаксис JSON и JavaScript-объект

Ключи объекта JSON всегда являются строками в двойных кавычках. Комментарии, завершающие запятые, `undefined`, одинарные кавычки и исполняемые выражения не допускаются.

```json
{
  "id": 42,
  "active": true,
  "tags": ["frontend", "javascript"],
  "meta": null
}
```

После разбора получается обычный JavaScript-объект или массив, но JSON-текст не содержит прототип класса или методы.

```js
const value = JSON.parse('{"id":42}');
Object.getPrototypeOf(value) === Object.prototype; // true
```

JSON не исполняет код как `eval`, но разобранные данные всё равно могут быть опасными при передаче в `innerHTML`, URL, SQL-запрос на backend или при объединении объектов без соответствующей проверки и экранирования.

## `JSON.stringify`

```js
const text = JSON.stringify({
  id: 42,
  active: true,
});
```

Для объекта рассматриваются собственные перечисляемые свойства со строковыми ключами. Символьные ключи игнорируются. Getter может быть вызван при чтении свойства, поэтому `JSON.stringify` способен выполнить пользовательский код.

Порядок собственных ключей следует стандартным правилам порядка свойств, но использовать обычную JSON-строку как канонический хэш не стоит. Логически эквивалентные источники могут иметь разный порядок, а пользовательский `toJSON` способен изменить представление.

Если значение верхнего уровня не поддерживается, результатом может быть `undefined`, а не JSON-строка:

```js
JSON.stringify(undefined); // undefined
JSON.stringify(() => {});  // undefined
```

## Разница между объектом и массивом

```js
JSON.stringify({ value: undefined }); // "{}"
JSON.stringify([undefined]);           // "[null]"
```

В объекте свойство можно пропустить без нарушения структуры. В массиве позиция должна сохраниться, поэтому неподдерживаемый элемент становится `null`.

```js
JSON.stringify({ value: NaN }); // '{"value":null}'
JSON.stringify([Infinity]);      // '[null]'
```

Это означает, что round trip не отличает исходный `NaN` от `null` без custom encoding.

## `toJSON`

Если значение предоставляет `toJSON(key)`, `JSON.stringify` сначала использует результат этого метода:

```js
const date = new Date("2026-01-01T00:00:00.000Z");
JSON.stringify({ date });
// '{"date":"2026-01-01T00:00:00.000Z"}'
```

После `JSON.parse` это обычная строка. Автоматического восстановления `Date` нет.

Пользовательский `toJSON` может исключить секретные данные или задать представление предметного типа, но также делает сериализацию менее очевидной. Для сетевого контракта часто понятнее отдельное преобразование в DTO, которое явно формирует отправляемую структуру.

## Функция `replacer`

Функция `replacer` получает ключ и значение на каждом шаге и может изменить или исключить значение:

```js
const text = JSON.stringify(user, (key, value) => {
  if (key === "password") {
    return undefined;
  }

  if (typeof value === "bigint") {
    return value.toString();
  }

  return value;
});
```

`BigInt` превращён в строку, но контракт должен объяснять это backend и коду разбора. Простое удаление `password` по списку запрещённых ключей не гарантирует, что секрет не находится под другим именем; для границы безопасности надёжнее DTO со списком явно разрешённых полей.

Массив `replacer` задаёт список имён свойств, которые разрешено включить:

```js
JSON.stringify(user, ["id", "name"]);
```

Параметр `space` форматирует результат для чтения, но увеличивает объём данных:

```js
JSON.stringify(value, null, 2);
```

## `JSON.parse` и функция `reviver`

```js
const value = JSON.parse(text);
```

Невалидный JSON выбрасывает `SyntaxError`, поэтому внешнюю строку разбирают внутри подходящей границы обработки ошибок текущего слоя.

Функция `reviver` вызывается снизу вверх после разбора и может преобразовать или удалить свойства:

```js
const value = JSON.parse(text, (key, value) => {
  if (key.endsWith("At") && typeof value === "string") {
    return new Date(value);
  }

  return value;
});
```

Возврат `undefined` удаляет свойство из результата. Универсальное правило «любой ключ, заканчивающийся на `At`, является Date» может испортить данные; `reviver` должен соответствовать известной схеме.

## Циклы и общая идентичность

```js
const object = {};
object.self = object;

JSON.stringify(object); // TypeError
```

Даже без цикла JSON не сохраняет общую идентичность вложенных объектов:

```js
const shared = { id: 1 };
const source = { first: shared, second: shared };
const clone = JSON.parse(JSON.stringify(source));

clone.first === clone.second; // false
```

Два свойства после разбора указывают на два независимых объекта. `structuredClone` сохраняет циклы и повторные ссылки для поддерживаемых типов, но не создаёт сетевой JSON.

## Числа и точность

JSON имеет один числовой синтаксис, а `JSON.parse` создаёт значения `Number`. Большое целое от backend может потерять точность уже во время разбора:

```json
{ "id": 9007199254740993 }
```

В JavaScript это значение нельзя точно представить как `Number`. Идентификаторы и денежные значения в минимальных единицах за пределами безопасного диапазона передают строками либо используют согласованный формат и специальный parser.

`BigInt` нельзя сериализовать по умолчанию, потому что контракт JSON не определяет, как получатель должен восстановить этот тип.

## JSON и HTTP

`response.json()` читает body и вызывает JSON parser. Он не проверяет TypeScript interface и не считает HTTP status успешным.

```js
const response = await fetch(url);

if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}

const data = await response.json();
const user = parseUser(data);
```

Это три разные проверки: транспорт и HTTP-статус, корректность синтаксиса JSON и соответствие данных ожидаемой схеме во время выполнения.

При отправке JSON задают `Content-Type: application/json` и явно сериализуют DTO. `Accept: application/json` сообщает серверу желаемый формат ответа.

## Security

`JSON.parse` не делает данные доверенными. Ключи вроде `__proto__`, `constructor` и `prototype` могут стать проблемой при небезопасном рекурсивном объединении с существующими объектами. Сам parser только создаёт данные; уязвимость возникает в последующей операции, которая небезопасно изменяет прототип или свойства целевого объекта.

Для объединения конфигурации используют проверенную схему, список разрешённых ключей и безопасную реализацию. Данные, попадающие в HTML, URL или другой интерпретирующий контекст, экранируют по правилам места назначения.

## Где применяется во frontend

- HTTP API сериализует DTO, а после разбора проверяет структуру данных во время выполнения.
- `localStorage` хранит строки, поэтому объект часто преобразуют в JSON и обратно с явной версией схемы.
- Логирование использует безопасную сериализацию, ограничение глубины и удаление секретных данных.
- `Date` и `BigInt` получают согласованное строковое представление в контракте.
- `structuredClone` выбирают для локальной глубокой копии поддерживаемых значений, а JSON - для текстового обмена.

## Ключевые уточнения

- JSON описывает ограниченный формат данных и не сохраняет полную семантику JavaScript-объекта.
- Неподдерживаемые свойства объекта пропускаются, а позиции массива заменяются на `null`.
- Getters и `toJSON` могут выполнить код во время `JSON.stringify`.
- `JSON.parse` не восстанавливает Date, Map, Set, экземпляр класса, повторные ссылки и дескрипторы.
- JSON round trip теряет данные и не является универсальным deep clone.
- `response.json()` разбирает синтаксис, но не проверяет успешность HTTP-ответа или схему данных.
- Большие целые числа могут потерять точность при преобразовании в `Number`.
- Разобранный объект остаётся недоверенным вводом для объединения объектов, HTML и других чувствительных операций.
