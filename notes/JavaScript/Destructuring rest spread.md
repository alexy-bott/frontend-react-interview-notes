## Быстрый ответ

Destructuring (деструктуризация) извлекает свойства объекта или значения итерируемого объекта по заданному шаблону. Результат можно записать в новые переменные или присвоить существующим. Rest собирает оставшиеся значения, а spread раскрывает значения или свойства в новом месте.

Один синтаксис `...` выполняет разные операции в зависимости от места. Rest находится в шаблоне деструктуризации или списке параметров и собирает остаток. Spread находится в литерале массива, литерале объекта или списке аргументов и раскрывает исходное значение.

Spread массива и объекта создаёт только поверхностную копию: вложенные объекты остаются общими. Spread объекта не сохраняет прототип и дескрипторы свойств; геттер исходного объекта выполняется, а в новом объекте создаётся обычное свойство с полученным значением.

Значение по умолчанию при деструктуризации используется только для `undefined`, но не для `null`, `0`, `false` или пустой строки.

## Ключевая схема

```js
const { id, name: displayName = "Unknown", ...meta } = user;
const [first, , third, ...rest] = iterable;

const arrayCopy = [...items];
const objectCopy = { ...user, active: true };
fn(...args);

function fn(required, ...restArgs) {}
```

| Форма | Откуда берутся данные | Результат |
| --- | --- | --- |
| Деструктуризация объекта | чтение свойств | переменные или присваивания |
| Деструктуризация массива | протокол итерации | переменные или присваивания |
| Rest объекта | оставшиеся собственные перечисляемые свойства | новый обычный объект |
| Rest массива | оставшиеся значения итератора | новый массив |
| Spread объекта | собственные перечисляемые свойства | свойства нового объекта |
| Spread массива или вызова | значения итерируемого объекта | элементы массива или аргументы |

## Деструктуризация объекта

```js
const user = {
  id: 42,
  profile: {
    name: "Ann",
  },
};

const {
  id,
  profile: { name },
} = user;
```

Шаблон слева повторяет путь чтения свойств. `profile: { name }` не создаёт переменную `profile`, а только использует это свойство для вложенного извлечения `name`.

Переименование отделяет имя свойства от имени локальной переменной:

```js
const { name: displayName } = user.profile;
```

При присваивании без объявления шаблон объекта заключают в скобки, иначе `{}` будет разобран как блок кода:

```js
let id;
({ id } = user);
```

## Значения по умолчанию

```js
const { theme = "light" } = settings;
```

Значение по умолчанию вычисляется, если свойство отсутствует или равно `undefined`:

```js
({ value = 10 } = { value: undefined }); // 10
({ value = 10 } = { value: null });      // null
({ value = 10 } = { value: 0 });         // 0
```

Выражение справа от `=` выполняется лениво:

```js
const { options = createDefaultOptions() } = config;
```

`createDefaultOptions` не вызывается, если свойство существует и не равно `undefined`.

Вложенный шаблон не делает родительское свойство необязательным:

```js
const { profile: { name } } = user;
// TypeError, если user.profile равно null или undefined.
```

Значение по умолчанию для родительского свойства защищает только от `undefined`:

```js
const { profile: { name } = {} } = user;
```

Если `profile` может быть `null`, сначала нормализуют контракт или используют optional chaining для чтения.

## Деструктуризация массива использует итератор

```js
const [first, second] = new Set(["a", "b"]);
```

Синтаксис называется деструктуризацией массива, но принимает любой итерируемый объект. Пропуск позиции всё равно продвигает итератор:

```js
const [first, , third] = [1, 2, 3];
```

Rest-элемент собирает оставшиеся значения итератора в новый массив:

```js
const [head, ...tail] = [1, 2, 3];
// head = 1, tail = [2, 3]
```

Если шаблону больше не нужны значения, итератор закрывается через метод `return()`, когда такой метод предусмотрен. Пользовательский итератор может использовать его для освобождения ресурса.

## Rest-свойства и rest-параметры

Rest объекта копирует оставшиеся собственные перечисляемые свойства со строковыми ключами и ключами типа `Symbol`. Уже извлечённые ключи в результат не входят:

```js
const { password, ...publicUser } = user;
```

Так можно сформировать объект для отображения, но операция не создаёт границу безопасности. Исходный `password` остаётся в памяти и может попасть в лог до или после деструктуризации. Для передачи данных наружу обычно надёжнее явно перечислить разрешённые поля, чем исключать запрещённые.

Rest-параметр собирает переданные функции аргументы в обычный массив:

```js
function sum(...numbers) {
  return numbers.reduce((total, value) => total + value, 0);
}
```

Rest-параметр должен быть последним и не может иметь значение по умолчанию. В отличие от устаревшего объекта `arguments`, он является массивом и содержит только оставшуюся часть аргументов.

## Spread массива

```js
const copy = [...source];
const merged = [...first, ...second];
const withItem = [...items, newItem];
```

Spread массива использует протокол итерации. Обычный объект без метода `[Symbol.iterator]` раскрыть в массив нельзя.

Копия остаётся поверхностной:

```js
const source = [{ id: 1 }];
const copy = [...source];

copy[0].id = 2;
console.log(source[0].id); // 2
```

Spread разреженного массива превращает пустые позиции в явные `undefined`, потому что итератор выдаёт значение для каждого индекса.

## Spread объекта

```js
const nextUser = {
  ...user,
  name: "Grace",
};
```

Свойства применяются слева направо: более позднее свойство с тем же ключом заменяет более раннее. Так выполняют неизменяемое поверхностное обновление объекта.

Spread объекта копирует собственные перечисляемые свойства. Он не переносит:

- прототип исходного объекта;
- неперечисляемые свойства;
- дескрипторы свойств;
- приватные поля класса;
- внутренние слоты встроенных объектов.

Геттер исходного объекта вызывается, а его результат становится обычным значением:

```js
const source = {
  get value() {
    return 42;
  },
};

const copy = { ...source };
// copy.value - обычное свойство данных со значением 42
```

## Spread при вызове функции

```js
const values = [10, 20];
Math.max(...values);
```

Spread при вызове передаёт значения итерируемого объекта как отдельные аргументы. Очень большой массив может превысить ограничение движка на количество аргументов. Например, максимум большой коллекции надёжнее искать обычным циклом или через `reduce`, а не через `Math.max(...values)`.

Метод нужно вызывать через объект, который станет его `this`:

```js
service.run(...args);
```

Если сначала извлечь метод из объекта, значение `this` всё равно может потеряться. Spread управляет только аргументами и не определяет контекст вызова.

## Где применяется во frontend

- Props и параметры функций извлекаются со значениями по умолчанию и понятными локальными именами.
- Rest-параметры позволяют функции принимать переменное количество аргументов без `arguments`.
- Spread объекта создаёт новое состояние с поверхностно обновлёнными свойствами.
- Spread массива добавляет элемент без изменения исходного массива.
- Деструктуризация кортежа показывает позиции элементов, но объект обычно понятнее для большого количества возвращаемых значений.
- Rest объекта исключает технические поля из объекта для отображения, но не обеспечивает очистку данных с точки зрения безопасности.

## Ключевые уточнения

- Деструктуризация объекта читает свойства, а деструктуризация массива использует протокол итерации.
- Значение по умолчанию применяется только к `undefined`; `null` не заменяется автоматически.
- Вложенный шаблон выбросит ошибку, если обязательное родительское свойство равно `null` или `undefined`.
- Rest собирает остаток, а spread раскрывает исходное значение: одинаковые `...` обозначают разные операции.
- Spread массива и объекта создаёт поверхностную копию и сохраняет ссылки на вложенные объекты.
- Spread объекта не сохраняет прототип и дескрипторы, а также выполняет геттеры исходного объекта.
- Spread аргументов не восстанавливает потерянный `this` и ограничен максимальным количеством аргументов движка.
