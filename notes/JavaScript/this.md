## Быстрый ответ

`this` - специальное значение текущего вызова. У обычной функции оно определяется формой вызова: `obj.fn()` передаёт `obj`, `fn.call(ctx)` и `fn.apply(ctx)` задают значение явно, `new Fn()` создаёт новый объект, а простой вызов `fn()` в strict mode получает `undefined`.

Стрелочная функция собственного `this` не создаёт и читает его из внешней лексической области. `call`, `apply` и `bind` не могут заменить это значение. Поэтому стрелка удобна во вложенной callback-функции, которая должна сохранить `this` внешнего метода, но не подходит как метод, получающий объект-получатель (`receiver`) от `obj.method()`.

Функция не хранит постоянную связь с объектом, из свойства которого её прочитали. После `const fn = obj.method` простой вызов `fn()` теряет объект-получатель. Для предсказания `this` нужно смотреть на конкретное выражение вызова, а не на место объявления обычной функции.

## Ключевая схема

| Вызов | Значение `this` |
| --- | --- |
| `fn()` | `undefined` в strict mode |
| `obj.fn()` | `obj` |
| `new Fn()` | новый экземпляр |
| `fn.call(ctx)` | `ctx` |
| `fn.apply(ctx)` | `ctx` |
| `fn.bind(ctx)` | новая функция с привязанным `ctx` |
| `() => this` | `this` из внешней области |

Приоритет для обычной функции удобно читать так: `new` → явная привязка `bind`/`call`/`apply` → вызов метода → простой вызов. У функции после `bind` вызов через `new` игнорирует привязанный `this`, но сохраняет заранее заданные аргументы.

## Базовая модель

Вызов метода состоит не только из функции, но и из ссылки вида `base.property`. Во время вызова объект `base` становится `this`. Если сначала получить само значение функции, эта связь теряется, и последующий простой вызов уже не знает об исходном объекте.

Strict mode важен для простого вызова: `this` остаётся `undefined`. В скрипте без strict mode `null` и `undefined` заменяются на `globalThis`, а примитив может быть обёрнут объектом. ES modules и тела классов выполняются в strict mode, поэтому современное объяснение обычно опирается на `undefined`.

Стрелочная функция использует `this` окружающего кода. Литерал объекта не создаёт отдельный `this`, поэтому стрелочное свойство объекта не получает сам объект автоматически.

## Развернутый ответ

### Потеря объекта-получателя

```js
const user = {
  name: "Ann",
  say() {
    return this.name;
  },
};

const say = user.say;

say(); // TypeError в strict mode при чтении this.name
```

API, принимающий callback-функцию, обычно вызывает её по своим правилам. Поэтому передача `button.addEventListener("click", user.say)` не сохраняет `user`; нужно передать `user.say.bind(user)` или обёртку `event => user.say(event)`.

### `call`, `apply`, `bind`

`call` и `apply` вызывают функцию сразу. `call` принимает аргументы по одному, `apply` - массивом. `bind` возвращает новую функцию с заранее привязанным контекстом и, при необходимости, частью аргументов.

```js
fn.call(user, 1, 2);
fn.apply(user, [1, 2]);

const bound = fn.bind(user, 1);
bound(2);
```

Повторный `bind` не заменяет уже привязанный `this`: новая функция может дополнительно закрепить аргументы, но объект-получатель останется от первого `bind`.

### Стрелочная функция

У стрелки нет собственного `this`, `arguments` и `prototype`. Она берёт `this` снаружи.

```js
const counter = {
  value: 1,

  later() {
    setTimeout(() => {
      console.log(this.value);
    }, 0);
  },
};

counter.later(); // 1
```

Стрелка создаётся во время вызова `counter.later()` и читает `this` этого вызова. Если отделить сам `later` и вызвать просто как функцию, внешнее `this` также будет потеряно.

### `new`

`new Fn()` создаёт объект, связывает его `[[Prototype]]` с `Fn.prototype` и вызывает функцию-конструктор с новым объектом как `this`. Если конструктор явно возвращает другой объект, он становится результатом; возврат примитива игнорируется.

### Обработчик DOM-события

DOM вызывает обычную функцию-обработчик с `this`, равным `event.currentTarget`. В стрелочной функции `this` остаётся лексическим. В прикладном коде `event.currentTarget` выражает намерение точнее и не зависит от выбранной формы callback-функции.

### Верхний уровень

В классическом браузерном скрипте верхнеуровневый `this === globalThis` (`window` в обычной странице). В ES module верхнеуровневый `this === undefined`. Это различие объясняет, почему стрелочная функция, созданная на верхнем уровне, может вести себя по-разному в старом скрипте и модуле.

## Пример

```js
"use strict";

const user = {
  name: "Ann",

  say(greeting) {
    console.log(`${greeting}, ${this.name}`);
  },
};

user.say("Hi"); // Hi, Ann

const looseSay = user.say;
looseSay.call({ name: "Kate" }, "Hello"); // Hello, Kate

const boundSay = user.say.bind(user, "Hey");
boundSay(); // Hey, Ann
```

Здесь первый вызов получает `this` от объекта слева от точки, второй задаёт контекст через `call`, третий использует заранее привязанную функцию.

## Где применяется во frontend

| Ситуация | Подход | Причина |
| --- | --- | --- |
| Передача метода как callback-функции | обёртка или `bind` | API не сохраняет исходный объект-получатель автоматически |
| Callback-функция внутри метода | стрелочная функция | использует `this` внешнего вызова метода |
| Переиспользование функции с разными объектами | `call`/`apply` | объект-получатель задаётся для конкретного вызова |
| DOM-обработчик | `event.currentTarget` | явно указывает элемент, на котором зарегистрирован обработчик |

## Ключевые уточнения

- У обычной функции `this` определяется выражением вызова, а не местом создания функции.
- Метод теряет объект-получатель, если функцию отделить от объекта и вызвать отдельно.
- Стрелочная функция не создаёт собственный `this`; `bind`, `call` и `apply` не перепривязывают его.
- `new` создаёт собственный объект-получатель и имеет приоритет над привязанным `this`.
- Верхнеуровневый `this` равен `globalThis` в классическом скрипте и `undefined` в ES module.
