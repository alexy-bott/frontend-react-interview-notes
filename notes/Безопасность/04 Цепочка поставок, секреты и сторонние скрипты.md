## Быстрый ответ

Supply chain security защищает путь кода от dependency и install script до CI, build artifact, CDN и runtime. Уязвимый или скомпрометированный пакет может выполниться при установке, сборке либо в browser; third-party script на странице обычно получает доступ к DOM и JS-доступным данным origin.

Lockfile фиксирует конкретный dependency graph и делает установку воспроизводимой, но не доказывает безопасность версий. Нужны review новых packages и обновлений, `npm ci`, SCA/audit известных уязвимостей, контроль install scripts, минимальные CI permissions и проверяемое происхождение artifacts.

В frontend bundle не бывает настоящих secrets. Значения `VITE_*`, `NEXT_PUBLIC_*`, `DefinePlugin` и всё, что клиентский код может получить во время build/runtime, доступны пользователю. Secrets остаются в server runtime или secret manager; browser получает только public identifiers и краткоживущие данные с ограниченными правами.

## Поверхность supply chain

```text
registry -> lockfile -> install scripts -> build tools -> CI
         -> artifact -> CDN/deploy -> third-party runtime code
```

| Этап | Риск | Контроль |
| --- | --- | --- |
| Выбор package | typosquatting, abandoned maintainer, лишние permissions | проверить owner, repository, releases, usage и alternatives |
| Dependency graph | vulnerable/transitive package | lockfile, SCA, SBOM, update policy |
| Install/build | malicious lifecycle script | review scripts, isolated CI, least privilege |
| Publish/deploy | stolen token, artifact substitution | OIDC/trusted publishing, approvals, provenance/signatures |
| Browser runtime | compromised analytics/chat/CDN | CSP, SRI, self-hosting, sandbox, vendor minimization |

SCA (Software Composition Analysis) сопоставляет dependencies с advisories. SBOM (Software Bill of Materials) — перечень компонентов и версий, который помогает быстро найти затронутые продукты.

## Dependencies и lockfile

`package.json` выражает допустимые ranges и scripts, а lockfile фиксирует разрешённые версии и integrity metadata всего дерева. В CI используют согласованный package manager/version и frozen install (`npm ci`, `pnpm --frozen-lockfile` или аналог), чтобы сборка не пересчитывала graph незаметно.

Lockfile защищает воспроизводимость, но может закрепить уязвимую версию. `npm audit` обнаруживает известные advisories и не находит malicious package без опубликованного сигнала, архитектурную уязвимость или опасное использование безопасной библиотеки. Report анализируют по достижимости кода, impact, fix и риску обновления; автоматический major update без review может сломать приложение.

При добавлении dependency проверяют необходимость, maintenance, release history, transitive graph, install scripts, bundle impact и разрешения. Для private packages защищают scope/registry configuration от dependency confusion.

## Secrets и public config

Минификация, обфускация и скрытый UI не защищают значение в client bundle. API key может быть публичным идентификатором, если provider ограничивает его origin, quota и разрешениями, но server secret не должен попадать в browser.

В Next.js переменная без `NEXT_PUBLIC_` может использоваться в server-only code, однако импорт server module в client boundary или ручная подстановка build tool требует отдельной проверки. После сборки artifact сканируют на известные secret patterns и проверяют, какие config values реально встроены.

Source maps облегчают диагностику и могут раскрыть исходные имена, структуру и комментарии, но секрет уже скомпрометирован, если был встроен в minified bundle. Распространённый вариант — не публиковать maps как общедоступные assets, а загружать их в error monitoring с контролем доступа.

## Third-party scripts и SRI

Analytics, tag manager, chat, maps и payment SDK выполняются в странице и могут читать DOM, ставить handlers и влиять на performance. Allowlist домена в CSP доверяет всему разрешённому коду этого источника, поэтому число vendors и их возможности минимизируют.

SRI (Subresource Integrity) заставляет browser сверить внешний `script` или stylesheet с ожидаемым cryptographic hash:

```html
<script
  src="https://cdn.example.com/widget@1.2.3/widget.min.js"
  integrity="sha384-..."
  crossorigin="anonymous"
></script>
```

Для cross-origin SRI resource server должен разрешить CORS. SRI подходит для versioned immutable file; динамически меняющийся tag manager нарушит hash. Если script не требует полного доступа к приложению, отдельный sandboxed iframe снижает полномочия лучше одной CSP.

## CI/CD и artifact

Pipeline получает доступ только к нужным secrets и environments. Untrusted fork/branch не должен читать production credentials. Долгоживущие publish tokens заменяют short-lived OIDC credentials там, где registry поддерживает trusted publishing; provenance связывает package с source и build workflow, но не доказывает отсутствие уязвимостей в коде.

Перед deploy проверяют именно произведённый artifact: tests/build, dependency inventory, secret scan, source maps, public env и digest. Promotion одного immutable artifact между environments уменьшает расхождение повторных сборок.

## Ключевые уточнения

- Lockfile фиксирует graph и integrity metadata, но не оценивает безопасность содержимого.
- Audit покрывает известные advisories и является одним из сигналов, а не сертификатом безопасности.
- Любое значение, доступное client JavaScript, считается публичным независимо от имени env variable.
- SRI проверяет неизменность конкретного external resource и требует CORS для cross-origin загрузки.
- CSP ограничивает third-party execution, но разрешённый vendor всё ещё имеет значительные права.
- Provenance подтверждает происхождение artifact, а review и tests оценивают его поведение.
