# Специфичность селекторов

## Быстрый ответ

Специфичность - это один из критериев каскада, который сравнивает селекторы конкурирующих CSS-объявлений. Её записывают тремя группами: ID; классы, атрибуты и псевдоклассы; теги и псевдоэлементы. Сравнение идёт слева направо, а при полном равенстве побеждает более позднее объявление.

Специфичность сравнивается только между объявлениями одного уровня каскада. `!important`, источник стилей и cascade layer могут решить конфликт раньше, поэтому правило с более специфичным селектором побеждает не всегда.

## Ключевая схема

| Группа | Пример | Вклад |
| --- | --- | --- |
| ID | `#app` | `1-0-0` |
| Класс, атрибут, псевдокласс | `.btn`, `[type]`, `:hover` | `0-1-0` |
| Тег, псевдоэлемент | `button`, `::before` | `0-0-1` |

```text
#app .button:hover  -> 1-2-0
.card button        -> 0-1-1
button              -> 0-0-1
```

## Базовая модель

Числа специфичности не складываются в одно десятичное число. Сначала сравнивается количество ID, затем классов, атрибутов и псевдоклассов, затем тегов и псевдоэлементов. Поэтому сколько угодно классов не превращаются в один ID.

Inline style, заданный атрибутом `style`, находится внутри авторских стилей, но имеет отдельный приоритет выше обычных правил селекторов. `!important` не является частью специфичности: сначала каскад отделяет важные объявления от обычных и только затем сравнивает их селекторы.

## Развернутый ответ

Специфичность помогает выбрать победителя среди правил одного уровня каскада. Если два правила находятся в разных layers, вопрос может решиться до сравнения селекторов. Если их специфичность одинакова, используется близость `@scope`, а затем порядок объявления.

`!important` поднимает объявление в отдельный уровень cascade. Если `!important`-объявлений несколько, между ними снова сравниваются origin, layers, specificity и порядок. Постоянное использование `!important` обычно означает, что архитектура селекторов или слоёв стала слишком хрупкой.

Псевдоклассы `:is()`, `:not()` и `:has()` сами не добавляют вес псевдокласса. В итог попадает специфичность наиболее весомого селектора из их списка аргументов. Поэтому один ID внутри списка способен повысить специфичность всего правила.

`:where()` всегда имеет нулевую специфичность вместе со своими аргументами. Это удобно для reset, базовых ограничений и библиотечных стилей, которые потребитель должен легко переопределить.

## Пример

```css
button {
  color: black;
}

.button {
  color: blue;
}

#submit {
  color: red;
}
```

Если элемент подходит под все три обычных правила и они находятся в одном layer, победит `#submit`: `1-0-0` выше `0-1-0` и `0-0-1`.

```css
:where(.dialog button) {
  color: black;
}

.button {
  color: royalblue;
}
```

У первого правила нулевая специфичность, поэтому `.button` легко его переопределяет независимо от длины селектора внутри `:where()`.

## Ключевые уточнения

- Специфичность сравнивается не первой: источник, важность и layer имеют более высокий приоритет.
- `!important` меняет важность объявления, а не прибавляет вес селектору.
- При равных остальных критериях побеждает более позднее объявление.
- `:is()`, `:not()` и `:has()` получают вес от самого специфичного аргумента.
- `:where()` и все его аргументы дают нулевую специфичность.
- Короткие селекторы и заранее определённые layers делают переопределение предсказуемее, чем наращивание веса.
