## Быстрый ответ

CSS-единицы связывают длину с разными опорными величинами. `px` обозначает CSS pixel, `rem` зависит от размера шрифта корневого элемента, `em` обычно - от размера шрифта текущего элемента, `%` - от контекста конкретного свойства, а viewport units - от размеров области просмотра.

Универсально лучшей единицы нет. Выбор должен выражать зависимость: `rem` подходит для размеров, связанных с общей типографикой, `em` - с локальным масштабом компонента, проценты - с containing block, viewport units - с экраном. `min()`, `max()` и `clamp()` объединяют относительное значение с явными границами.

## Ключевая схема

| Единица | От чего зависит | Типичный сценарий |
| --- | --- | --- |
| `px` | эталонный CSS pixel | тонкие линии, небольшие фиксированные детали |
| `rem` | `font-size` корневого элемента | типографика, общая шкала размеров |
| `em` | обычно `font-size` самого элемента | локальный масштаб компонента |
| `%` | определяется свойством | относительные ширины, смещения, размеры |
| `vw`, `vh` | default viewport size | размеры, связанные с viewport |
| `svh`, `lvh`, `dvh` | малая, большая и динамическая высота viewport | мобильный browser UI |
| `ch` | ширина символа `0` | ограничение длины строки |
| `clamp()` | min/preferred/max | fluid typography/layout |

## Базовая модель

Единица задаёт не назначение значения, а зависимость, по которой браузер его вычислит. Например, `2rem` изменится вместе с root font size, `50%` - вместе с базой процента конкретного свойства, а `50vw` - вместе с шириной viewport.

CSS pixel не обязан совпадать с физическим пикселем дисплея: браузер учитывает плотность экрана и масштабирование. Поэтому `1px` - логическая CSS-величина, которая может отображаться несколькими device pixels.

## Развернутый ответ

`rem` считается от `font-size` корневого элемента `html`. Если не переопределять его жёстко, размеры в `rem` следуют пользовательской настройке базового шрифта. `em` для большинства свойств считается от вычисленного `font-size` самого элемента, но `font-size` в `em` или `%` вычисляется относительно шрифта родителя. Поэтому вложенные изменения `font-size` могут накапливаться.

`px` уместен для тонких border, небольших визуальных деталей и нижних границ, которые не должны зависеть от шрифта. Но текст и интерактивные области, заданные только фиксированными значениями, нужно проверять при browser zoom, увеличенном default font size и переводе с более длинными строками.

`%` зависит от свойства. Процентный `width` обычно связан с шириной containing block; процентные padding и margin в современных спецификациях вычисляются от его inline size; проценты в `translate()` - от собственного reference box элемента. Поэтому «процент от родителя» не является общим правилом.

Viewport units имеют варианты small, large и dynamic. `svh` даёт устойчивый размер при раскрытом browser UI, `lvh` - при максимально скрытом UI, а `dvh` меняется вместе с доступной областью. Динамическая единица точнее заполняет экран, но её изменение во время прокрутки способно вызвать перерасчёт layout.

`clamp(min, preferred, max)` ограничивает preferred value снизу и сверху. Часто preferred value объединяет `rem` и viewport unit через `calc()`, чтобы значение плавно менялось, но не становилось слишком маленьким или большим.

## Пример

```css
.article {
  max-width: 70ch;
  padding: clamp(1rem, 2vw, 2rem);
}

.article__title {
  font-size: clamp(1.75rem, 4vw, 3rem);
  line-height: 1.1;
}

.screen {
  min-height: 100svh;
}
```

`70ch` задаёт приблизительное ограничение строки, а не гарантирует ровно 70 любых символов. `clamp()` удерживает отступы и заголовок в допустимом диапазоне. `100svh` выбирает стабильную минимальную высоту при видимом mobile browser UI; если секция должна всегда заполнять текущую область, можно осознанно выбрать `100dvh`.

## Ключевые уточнения

- `px` - CSS pixel, а не физический пиксель устройства.
- База `%` определяется конкретным свойством; её нужно проверять по документации.
- `em` в `font-size` зависит от родителя, а в большинстве остальных свойств - от вычисленного шрифта самого элемента.
- Unitless `line-height` наследуется как множитель и обычно лучше масштабируется вместе со шрифтом.
- `svh` стабилен относительно browser UI, `dvh` следует его текущему состоянию; выбор зависит от ожидаемого поведения.
- Относительные единицы не делают интерфейс автоматически адаптивным: нужны разумные min/max-ограничения и проверка контента.
