## Быстрый ответ

Type inference, или вывод типов, позволяет TypeScript определить тип без явной аннотации. Компилятор использует значение при инициализации, возвращаемые значения функции, аргументы вызова и контекст, в котором находится выражение.

При этом вывод не всегда сохраняет самое узкое значение. Изменяемая переменная `let status = "idle"` получает тип `string`, потому что позже в неё можно записать другую строку. Такое расширение литерального типа называется widening. У `const status = "idle"` значение менять нельзя, поэтому типом остаётся литерал `"idle"`.

Contextual typing, или контекстный вывод, работает в обратную сторону: ожидаемый тип места подсказывает тип выражению. Например, параметр inline-обработчика `button.addEventListener("click", event => ...)` получает тип события из сигнатуры `addEventListener`.

## Как TypeScript получает тип

У вывода типов есть несколько основных источников:

| Источник | Пример | Результат |
| --- | --- | --- |
| Инициализатор | `const count = 1` | литерал `1` |
| Изменяемая переменная | `let count = 1` | `number` |
| Возвращаемые значения | `return id` | тип результата функции |
| Аргументы generic-функции | `identity("text")` | `T` выводится как `string` |
| Ожидаемый тип | `const handler: MouseEventHandler = event => ...` | тип параметра берётся из контекста |
| Несколько вариантов | `Math.random() ? 1 : "x"` | `number | string` |

TypeScript ищет тип, совместимый со всеми возможными значениями выражения. Если функция возвращает число в одной ветке и строку в другой, результатом становится `number | string`. Если подходящий общий тип вывести нельзя или контекста недостаточно, может потребоваться явная аннотация.

## Widening: почему литерал становится общим типом

Литеральный тип описывает конкретное значение: не любую строку, а именно `"idle"`. TypeScript расширяет такой тип, когда значение считается изменяемым:

```ts
const fixedStatus = "idle";
// "idle"

let currentStatus = "idle";
// string

currentStatus = "loading";
```

То же относится к свойствам обычного объекта. Сам объект объявлен через `const`, но его поля всё ещё можно изменить, поэтому `role` выводится как `string`:

```ts
const user = { role: "admin" };
// { role: string }

user.role = "editor";
```

Если нужны неизменяемые литералы, используют `as const`. Если нужно проверить объект по контракту и сохранить точный вывод, используют `satisfies`.

## Контекстный вывод (contextual typing)

Контекст помогает TypeScript типизировать выражение до того, как разработчик добавит аннотации вручную:

```ts
const names = ["Ann", "Bob"];

names.map(name => name.toUpperCase());
// name: string — тип пришёл из string[].map

document.addEventListener("click", event => {
  console.log(event.clientX);
});
// event: MouseEvent — тип пришёл из overload addEventListener
```

Если вынести функцию из типизированного места, контекст может исчезнуть:

```ts
const handleClick = event => {
  // при noImplicitAny у event будет ошибка
};

document.addEventListener("click", handleClick);
```

Здесь параметру нужна аннотация либо заранее заданный тип всей функции.

## Когда писать тип явно

Аннотация полезна, когда она задаёт контракт, неочевидный из текущего значения:

- публичная функция или экспортируемый API;
- переменная позже получит значения разных вариантов;
- пустой массив или `null` не дают достаточно информации;
- нужно проверить, что реализация соответствует заранее выбранному контракту;
- вывод получился шире или уже, чем требует модель предметной области.

Избыточные аннотации дублируют очевидную информацию и могут ухудшить вывод. Например, `const name: string = "Ann"` обычно не точнее, чем `const name = "Ann"`.

## Ключевые уточнения

- Вывод типов не ослабляет TypeScript: выведенный тип проверяется так же, как написанный вручную.
- `const` запрещает переприсвоить переменную, но не делает вложенный объект неизменяемым.
- Widening отражает допустимые будущие изменения значения, а не случайную потерю точности.
- Контекстный вывод особенно важен для callbacks, JSX props, обработчиков событий и generic API.
- `as const`, `satisfies` и явная аннотация решают разные задачи; они не взаимозаменяемы.
