## Быстрый ответ

Union `A | B` означает, что значение соответствует одному из вариантов. До narrowing TypeScript разрешает только операции, безопасные для всех вариантов. Intersection `A & B` означает, что значение одновременно удовлетворяет требованиям `A` и `B`.

Discriminated union, или размеченное объединение, — это union объектных типов с общим литеральным полем, например `status` или `kind`. Проверяя это поле, код однозначно выбирает вариант и получает доступ к его данным.

Во frontend размеченные объединения особенно полезны для состояния запроса, reducer actions и вариантов props: они запрещают невозможные комбинации. Например, `data` существует только в `success`, а `error` — только в `error`.

## Union: один из вариантов

```ts
function normalizeId(id: string | number): string {
  if (typeof id === "number") {
    return id.toString();
  }

  return id.trim();
}
```

До проверки `typeof` нельзя вызвать ни `toFixed`, ни `trim`: каждое действие подходит только одному варианту. После проверки TypeScript использует анализ потока управления и сужает тип в соответствующей ветке.

Union не означает, что у значения одновременно есть поля всех участников. Он означает обратное: в конкретный момент существует один вариант, но до проверки неизвестно какой.

## Discriminated union: явная модель состояния

```ts
type AsyncState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };
```

Поле `status` является discriminant — общим признаком с разными литеральными значениями. Оно связывает статус с доступными данными:

```ts
function renderUsers(state: AsyncState<string[]>): string {
  switch (state.status) {
    case "idle":
      return "Запрос ещё не отправлен";
    case "loading":
      return "Загрузка";
    case "success":
      return state.data.join(", ");
    case "error":
      return state.error.message;
  }
}
```

Альтернатива с одним объектом и необязательными полями допускает бессмысленные состояния:

```ts
type WeakState<T> = {
  status: "idle" | "loading" | "success" | "error";
  data?: T;
  error?: Error;
};
```

Такой тип разрешает `status: "loading"` вместе с `data` и `error`. Discriminated union делает эти комбинации непредставимыми на уровне типов.

## Исчерпывающая обработка

Для важных unions полезно заставить компилятор проверять каждый вариант:

```ts
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${String(value)}`);
}

function getLabel(state: AsyncState<unknown>): string {
  switch (state.status) {
    case "idle":
      return "Ожидание";
    case "loading":
      return "Загрузка";
    case "success":
      return "Готово";
    case "error":
      return "Ошибка";
    default:
      return assertNever(state);
  }
}
```

После обработки всех вариантов `state` должен иметь тип `never`. Новый вариант union нарушит это условие и покажет места, требующие обновления.

## Intersection: одновременные требования

```ts
type WithId = { id: string };
type WithTimestamps = {
  createdAt: string;
  updatedAt: string;
};

type Entity = WithId & WithTimestamps;
```

`Entity` обязан содержать все поля обоих типов. Intersection удобен для композиции небольших объектных контрактов и результатов utility types.

Intersection не «склеивает» несовместимые варианты в рабочее значение. Если одно требование задаёт `status: "success"`, а другое `status: "error"`, тип такого поля становится `never`, потому что одна строка не может иметь два разных литеральных значения одновременно.

## Union или intersection

| Вопрос к модели | Конструкция |
| --- | --- |
| Значение находится в одном из нескольких состояний? | union `A | B` |
| Объект должен объединять несколько независимых контрактов? | intersection `A & B` |
| Варианты объекта отличаются по общему признаку? | discriminated union |
| Каждый новый вариант должен обновить обработчики? | union + exhaustive check |

Для расширения понятного объектного контракта `interface extends` иногда читается лучше, чем длинная цепочка intersections. Для вычисляемой композиции типов intersection гибче.

## Ключевые уточнения

- У обычного union доступны только общие безопасные операции до narrowing.
- Discriminant должен иметь литеральный тип, а не общий `string`, иначе связь вариантов теряется.
- Optional-поля уместны, когда поле действительно независимо может отсутствовать; они не заменяют взаимоисключающие состояния.
- Intersection объединяет требования, но не выполняет runtime-слияние объектов.
- Exhaustive check превращает добавление нового варианта в контролируемое изменение всей программы.
- Сужение статического union не подтверждает достоверность внешнего JSON; сначала нужна runtime validation.
