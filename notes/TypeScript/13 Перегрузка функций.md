# Перегрузка функций

## Быстрый ответ

Function overloads, или перегрузки функций, позволяют описать несколько публичных способов вызвать одну функцию. Сначала объявляют overload signatures — сигнатуры перегрузки без тела, затем одну implementation signature — сигнатуру реализации. Вызывающий код видит только перегрузки; внутренняя сигнатура нужна компилятору для проверки реализации.

Перегрузка полезна, когда есть конечный набор форм вызова и тип результата зависит от аргументов. Если результат одинаков для всех вариантов, проще union-параметр. Если связь выражается одним общим правилом, обычно лучше generic.

Реализация должна принять и корректно обработать каждый публичный вариант. Широкая сигнатура реализации не создаёт дополнительный разрешённый способ вызова.

## Как устроена перегрузка

```ts
function select(selector: string): Element | null;
function select(selectors: string[]): Array<Element | null>;

function select(
  selectorOrSelectors: string | string[]
): Element | null | Array<Element | null> {
  if (typeof selectorOrSelectors === "string") {
    return document.querySelector(selectorOrSelectors);
  }

  return selectorOrSelectors.map(selector =>
    document.querySelector(selector)
  );
}

const button = select("button");
// Element | null

const fields = select(["input", "textarea"]);
// Array<Element | null>
```

Первые две сигнатуры являются публичным API. Третья, более широкая, описывает тело функции и снаружи не участвует в вызовах.

## Почему сигнатура реализации скрыта

Реализации нужен union, чтобы обработать все варианты. Если бы этот union автоматически стал публичным, вызывающий код получил бы широкий результат и потерял связь:

```ts
declare const input: string | string[];

select(input);
// ошибка, если отдельного overload для union нет
```

TypeScript должен выбрать одну публичную сигнатуру целиком. Значение `string | string[]` не гарантированно соответствует только первой или только второй. Если функция действительно принимает union-переменную, это нужно отразить отдельным overload или перепроектировать API.

## Перегрузка, union или generic

**Union-параметр** подходит, когда результат один и тот же:

```ts
function length(value: string | readonly unknown[]): number {
  return value.length;
}
```

Два overloads здесь не добавят информации.

**Generic** подходит, когда действует общее правило:

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}
```

Не нужно перечислять overload для `string[]`, `User[]` и каждого следующего типа.

**Overload** подходит, когда форм несколько и они принципиально отличаются по аргументам или результату, но представляют одну операцию.

## Порядок и совместимость

Более специфичные overloads располагают перед общими, потому что порядок участвует в выборе подходящей сигнатуры. Каждый overload должен быть совместим с реализацией по параметрам и результату.

```ts
function parse(value: "json"): object;
function parse(value: string): unknown;
function parse(value: string): unknown {
  return value === "json" ? {} : value;
}
```

Если общий `string` поставить первым, вызов с `"json"` может потерять более точный результат в сложных наборах overloads.

## Перегрузки в callable types

У arrow function нельзя напрямую записать несколько overload declarations. Callable type всё же может описывать перегруженный API, например тип функции из библиотеки:

```ts
type Convert = {
  (value: string): number;
  (value: number): string;
};

declare const convert: Convert;

const size = convert("text");
// number

const text = convert(42);
// string
```

Для собственной реализации обычная function declaration с overload signatures обычно читается проще.

## Ключевые уточнения

- Implementation signature не является дополнительным публичным overload.
- Overload нужен ради точной связи между конкретной формой аргументов и результатом, а не ради перечисления типов.
- Union-переменная может не пройти набор отдельных overloads, даже если каждый её вариант по отдельности допустим.
- Специфичные сигнатуры располагают раньше общих.
- Большое количество overloads усложняет поддержку; иногда object parameter с discriminant делает API понятнее.
- Overloads существуют только для проверки TypeScript; в runtime вызывается одна JavaScript-функция.
