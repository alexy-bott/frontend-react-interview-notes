## Быстрый ответ

Тип функции описывает параметры, возвращаемое значение и связь между ними. Например, `(value: string) => number` означает функцию, которая принимает строку и возвращает число. TypeScript проверяет не имена параметров, а их позиции и типы.

Параметры могут быть обязательными, необязательными (optional), иметь значение по умолчанию или собираться в rest-параметр. Возвращаемый тип обычно выводится из `return`, но у публичных функций его полезно указывать как часть контракта. Для переиспользуемой связи входа и выхода применяют generics, а для нескольких разных форм вызова — перегрузки (overloads).

`void` в типе функции обратного вызова (callback) означает, что вызывающий код не использует возвращаемое значение. Поэтому функцию, которая фактически что-то возвращает, можно передать как `() => void`; её результат будет проигнорирован. Это не то же самое, что функция, которой запрещено что-либо возвращать в реализации.

## Основная модель

```ts
type Formatter = (value: string, locale?: string) => string;
```

Здесь:

- `value` — обязательный параметр;
- `locale?` — необязательный параметр, внутри функции имеет тип `string | undefined`;
- `string` после стрелки — тип результата.

Функциональный тип можно записать через type alias, call signature в объектном типе или interface:

```ts
type Parse = (input: string) => number;

type ParserWithCache = {
  (input: string): number;
  cache: Map<string, number>;
};
```

Call signature нужна, когда функция сама является объектом с дополнительными свойствами.

## Параметры функции

```ts
function format(
  value: number,
  locale = "ru-RU",
  ...units: string[]
): string {
  return `${value.toLocaleString(locale)} ${units.join("/")}`;
}
```

- параметр со значением по умолчанию считается необязательным для вызывающего кода;
- после параметра с `?` нельзя объявить обязательный параметр; параметр со значением по умолчанию можно не передавать при вызове;
- rest-параметр описывается массивом или tuple, когда важны позиции;
- лишние аргументы при обычном вызове TypeScript не разрешает, даже если JavaScript их проигнорирует.

Для неизвестного количества аргументов разных фиксированных позиций tuple точнее обычного массива:

```ts
function log(...args: [message: string, code?: number]) {
  console.log(...args);
}
```

## `void`, `undefined` и `never`

`void` означает, что результат функции не предназначен для использования:

```ts
const listeners: Array<() => void> = [];

listeners.push(() => 42);
// допустимо: вызывающий код проигнорирует 42
```

У функции, явно объявленной как `function f(): void`, `return` без значения допустим, а `return 42` является ошибкой. Различие связано с назначением callback-типа: API не требует, чтобы переданная функция действительно ничего не возвращала, оно лишь обещает не использовать её результат.

`undefined` — конкретное значение, которое функция может вернуть. `never` означает, что нормального завершения вообще не будет: функция всегда бросает ошибку или бесконечно выполняется.

## Связь параметров и результата

Если результат зависит от типа входа по общему правилу, нужен generic:

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}
```

Если у API есть несколько конечных форм вызова с разными результатами, могут подойти overloads. Union-параметр проще, когда результат для всех вариантов одинаков.

## `this` в типе функции

TypeScript позволяет описать ожидаемый `this` фиктивным первым параметром. Он не попадает в JavaScript:

```ts
type User = { name: string };

function greet(this: User, prefix: string) {
  return `${prefix}, ${this.name}`;
}

greet.call({ name: "Ann" }, "Привет");
```

Стрелочная функция не получает собственный `this`, а захватывает его из внешней области. Поэтому специальный `this`-параметр применяют к обычным функциям.

## Ключевые уточнения

- Имена параметров не влияют на совместимость функций; важны позиции и типы.
- Optional-параметр внутри реализации требует обработки `undefined`.
- Аннотация результата публичной функции фиксирует контракт и помогает заметить случайное изменение API.
- `() => void` разрешает передать функцию с результатом, но вызывающий код этот результат не использует.
- Для callbacks совместимость параметров зависит от `strictFunctionTypes` и variance.
- TypeScript не проверяет количество и типы аргументов в runtime; после компиляции остаётся обычная JavaScript-функция.
