## Быстрый ответ

Большинство прикладных frontend-задач проверяет не сложную математику, а умение выбрать представление данных и не повторять дорогой поиск. Дедупликация, группировка, пересечение списков, нормализация API-ответа и построение дерева обычно решаются одним или двумя проходами с `Map` или `Set`.

Решение удобно строить последовательно: определить вход, выход и пограничные случаи; написать простой корректный вариант; оценить время и память; затем убрать повторные проходы, если они создают проблему. Оптимизированный код обязан сохранить поведение для дублей, отсутствующих связей, пустого входа и нестабильного порядка.

Базовые паттерны: индекс по ключу, множество для проверки наличия, счётчик частот, группировка, два указателя, скользящее окно, стек/очередь и обход дерева. Их нужно узнавать по форме задачи, а не применять `Map` автоматически.

## Порядок решения

1. Уточнить контракт: типы входа и выхода, допустимы ли дубли, важен ли порядок.
2. Назвать размер каждой независимой коллекции.
3. Сформулировать простой алгоритм и проверить его на маленьком примере.
4. Оценить худшее время и дополнительную память.
5. Найти повторный поиск, копирование или сортировку.
6. Выбрать структуру данных и повторно проверить пограничные случаи.

Например, «удалить дубли объектов» не определяет поведение полностью. Нужно знать ключ сравнения и какой объект сохранять при повторе: первый, последний или объединённый.

## Основные паттерны

| Задача | Паттерн | Типичная сложность |
| --- | --- | --- |
| Убрать дубли примитивных значений | `Set` | `O(n)` времени и памяти |
| Убрать дубли объектов по ID | `Map<id, item>` | `O(n)` |
| Посчитать повторения | карта частот (frequency map) | `O(n)` |
| Быстро получать сущность по ID | индекс по ключу (lookup map) | `O(n)` построение, быстрый повторный доступ |
| Найти пересечение списков | `Set` одного списка | `O(n + m)` |
| Сгруппировать элементы | `Map<key, item[]>` | `O(n)` |
| Построить дерево по `parentId` | индекс узлов и второй проход связей | `O(n)` при корректных данных |
| Найти пару в отсортированном массиве | два указателя (two pointers) | `O(n)` |
| Найти лучший непрерывный диапазон | скользящее окно (sliding window) | часто `O(n)` |
| Обойти дерево | стек для DFS, очередь для BFS | `O(V + E)` |

`V` — число узлов, `E` — число связей. DFS (depth-first search) идёт в глубину, BFS (breadth-first search) — по уровням.

## Индекс, Set и частоты

Повторный `find` одного пользователя для каждого заказа даёт `O(o * u)`. Индекс `Map<userId, user>` строится за типичное `O(u)`, после чего обогащение заказов занимает `O(o)`.

Карта частот хранит количество элементов по ключу:

```ts
function countByStatus(tasks: Task[]) {
  const count = new Map<Task["status"], number>();

  for (const task of tasks) {
    count.set(task.status, (count.get(task.status) ?? 0) + 1);
  }

  return count;
}
```

Set подходит для пересечения и проверок наличия. Если память важна, в Set можно поместить меньшую коллекцию:

```ts
function intersect<T>(left: T[], right: T[]): T[] {
  const [smaller, larger] = left.length <= right.length
    ? [left, right]
    : [right, left];
  const values = new Set(smaller);

  return larger.filter(value => values.has(value));
}
```

Этот вариант сохраняет порядок и повторы из `larger`. Если контракт требует порядок `left`, в Set всегда помещают `right` и фильтруют `left`, даже если это потребует больше памяти. Для уникального результата нужен отдельный Set результата. Контракт результата влияет на алгоритм.

## Два указателя и скользящее окно

Два указателя полезны, когда порядок данных позволяет отказаться от вложенного поиска. Для отсортированного массива один указатель начинает слева, второй справа: при слишком маленькой сумме двигается левый, при слишком большой — правый.

Если вход сначала нужно отсортировать, полная стоимость станет `O(n log n)`, а исходный порядок может потеряться. Сортировка копии сохраняет вход, но требует `O(n)` памяти.

Скользящее окно поддерживает состояние непрерывного диапазона, когда его правая и левая границы движутся только вперёд. Так находят максимальную длину подстроки без повторов, сумму последних `k` значений или диапазон событий. Паттерн неприменим к произвольному набору несвязанных элементов: условие должно обновляться при добавлении и удалении границы окна.

## Стек, очередь и дерево

Стек работает по принципу LIFO: последним добавлен — первым извлечён. Он используется для DFS, истории undo, проверки скобок и разбора вложенной структуры.

Очередь работает по принципу FIFO: первым добавлен — первым извлечён. Она используется для BFS и обработки задач по порядку. В JavaScript частый `array.shift()` может стоить `O(n)`, поэтому для большой очереди хранят индекс начала или используют подходящую deque-структуру.

При рекурсивном обходе глубокого дерева нужно учитывать стек вызовов. Данные с неизвестной глубиной безопаснее обходить явным стеком, чтобы не получить переполнение call stack.

## Построение дерева из плоского списка

API часто возвращает меню, категории или комментарии как `{ id, parentId }[]`. Поиск детей через `filter` для каждого узла может дать `O(n²)`. Индекс позволяет создать узлы, а затем связать их вторым проходом:

```ts
type CategoryDto = {
  id: string;
  parentId: string | null;
  title: string;
};

type CategoryNode = CategoryDto & {
  children: CategoryNode[];
};

type CategoryTree = {
  roots: CategoryNode[];
  orphans: CategoryNode[];
};

function buildCategoryTree(categories: CategoryDto[]): CategoryTree {
  const nodeById = new Map<string, CategoryNode>();
  const roots: CategoryNode[] = [];
  const orphans: CategoryNode[] = [];

  for (const category of categories) {
    if (nodeById.has(category.id)) {
      throw new Error(`Duplicate category id: ${category.id}`);
    }

    nodeById.set(category.id, { ...category, children: [] });
  }

  for (const category of categories) {
    const node = nodeById.get(category.id)!;

    if (category.parentId === null) {
      roots.push(node);
      continue;
    }

    const parent = nodeById.get(category.parentId);

    if (parent) {
      parent.children.push(node);
    } else {
      orphans.push(node);
    }
  }

  return { roots, orphans };
}
```

Два прохода дают `O(n)` среднего времени с индексом и `O(n)` памяти. Функция явно обрабатывает дубли и отсутствующего родителя, но предполагает отсутствие циклов. Для недоверенных данных цикл нужно обнаружить отдельно, например через состояния DFS: «не посещён», «в текущем пути», «завершён».

## Где применяется во frontend

| Сценарий | Паттерн |
| --- | --- |
| Выбранные строки таблицы | проверка наличия через Set |
| Заказы и пользователи из разных endpoints | индекс по ключу |
| Количество задач по status | карта частот |
| Сообщения по дате | grouping |
| Menu или comments по `parentId` | tree build |
| Общие permissions пользователя и роли | set intersection |
| Обход DOM-подобной структуры | DFS/BFS |
| Последние `k` метрик | sliding window |

Для очень больших данных одного улучшения Big O может быть недостаточно. Долгая синхронная `O(n)` работа всё равно блокирует главный поток (main thread); тогда применяют pagination, virtualization, Web Worker, серверную обработку или разбиение задачи, выбирая по измерениям.

## Ключевые уточнения

- Контракт дублей, порядка и отсутствующих связей определяется до выбора структуры данных.
- Map и Set обычно заменяют повторный поиск предварительным индексом и требуют дополнительной памяти.
- Два указателя используют порядок данных; стоимость предварительной сортировки входит в итоговую оценку.
- Sliding window относится к непрерывному диапазону, а не к произвольной комбинации элементов.
- DFS и BFS посещают те же узлы, но отличаются порядком, памятью и удобством для конкретной задачи.
- Линейный алгоритм может блокировать интерфейс при большом входе, поэтому Big O дополняют профилированием и стратегией выполнения.
