# Правила репозитория конспекта

Служебный файл определяет требования уровня репозитория: публичные Markdown-страницы, постепенную миграцию, страницы разделов, главную страницу, автоматически обслуживаемую навигацию и репозиторные инварианты.

Он не добавляется в навигацию конспекта и не задаёт второй шаблон страницы темы.

## Источники правил и область ответственности

Правила структуры, содержания, качества, проверки и редактирования **отдельной страницы темы** находятся в каталоге [`note-rules/`](<./note-rules/>).

Короткие точки входа:

- [`note-rules/README.md`](<./note-rules/README.md>) — маршруты создания и проверки;
- [`note-rules/new-note-workflow.md`](<./note-rules/new-note-workflow.md>) — поиск тематического пробела, предварительное исследование и первичная сборка новой заметки.

Каноническая процедура:

- [`note-rules/00-workflow.md`](<./note-rules/00-workflow.md>) — порядок применения уровней и репозиторных проверок.

Канонические файлы уровней:

- [`note-rules/01-file-structure.md`](<./note-rules/01-file-structure.md>) — формат и внешний каркас;
- [`note-rules/02-block-structure.md`](<./note-rules/02-block-structure.md>) — внутренние блоки и их разметка;
- [`note-rules/03-content-distribution.md`](<./note-rules/03-content-distribution.md>) — состав и распределение содержания;
- [`note-rules/04-content-quality.md`](<./note-rules/04-content-quality.md>) — пять критериев качества;
- [`note-rules/05-editing.md`](<./note-rules/05-editing.md>) — редактирование текущего состояния.

Короткие маршруты не вводят требований и не переопределяют канонические файлы уровней.

Если изменение затрагивает и страницу темы, и репозиторий, области ответственности разделяются:

- содержание страницы создаётся, проверяется и редактируется по `note-rules/`;
- существование целей ссылок, входящие связи, страницы разделов и генерируемая навигация проверяются на уровне репозитория;
- элементы, которыми управляет генератор, не редактируются вручную.

## Граница постепенной миграции

Целевая структура `note-rules/` обязательна для:

- новой заметки перед включением в репозиторий;
- существующей заметки, которую явно взяли в миграцию;
- заметки, уже переведённой на целевую структуру.

Остальные существующие заметки считаются legacy-материалами до плановой миграции. Они продолжают проходить действующие корпусные проверки, но не объявляются соответствующими новой содержательной модели.

Изменение правил не запускает массовую переработку всех заметок и не является разрешением автоматически изменять их содержание.

Требование целевых блоков не добавляется в общую CI-проверку, пока у репозитория нет явного признака, который надёжно отличает мигрированные страницы от legacy-страниц.

## Общие правила публичных Markdown-страниц

- Используется GitHub-flavored Markdown без зависимости от пользовательского CSS.
- Имя заметки не получает числовой префикс; порядок задаёт страница раздела.
- Внутренняя ссылка ведёт на существующий файл и использует относительный путь.
- Obsidian frontmatter, wikilinks и callouts не публикуются.
- Если `note-rules/` не задаёт специальную разметку, таблица размещается непосредственно под соответствующим заголовком без обёртки `[!NOTE]`.

Эти требования не переопределяют специальную Markdown/HTML-разметку, закреплённую в `note-rules/`.

## Страница раздела

- H1 совпадает с названием раздела.
- Ссылки на заметки могут объединяться в смысловые группы.
- Положение ссылки на заметку определяет порядок стрелочной навигации.
- Возврат ко всем разделам, количество заметок и переход к первой заметке создаёт генератор.

Страница раздела редактируется вручную только для изменения смысловых групп, состава и порядка ссылок. Блок между `SECTION-NAV:START` и `SECTION-NAV:END` вручную не изменяется.

## Главная страница

- Содержит короткое описание конспекта.
- Даёт один широкий маршрут по всем разделам.
- Не содержит поиска, длинной инструкции по использованию и служебных команд.
- Каждый существующий раздел `notes/<Раздел>/` связан с главной страницей.

## Служебная навигация

Верхняя и нижняя навигация заметки находятся между маркерами:

```text
NOTE-NAV-TOP:START
NOTE-NAV-TOP:END
NOTE-NAV-BOTTOM:START
NOTE-NAV-BOTTOM:END
```

Содержимое этих блоков создаёт `scripts/generate_navigation.py`. Ручное изменение ссылок, порядка или разделителей внутри блоков запрещено.

При добавлении новой заметки сначала добавляется ссылка в нужное место страницы раздела, затем запускается генератор.

## Репозиторные инварианты

Репозиторные проверки выполняются по [`note-rules/00-workflow.md`](<./note-rules/00-workflow.md>) и не заменяют локальные проверки отдельной страницы.

На уровне репозитория проверяются как минимум следующие инварианты:

- каждый пункт в `Связанных темах` ведёт на существующую заметку;
- каждая заметка содержит не менее двух разных исходящих тематических ссылок;
- на каждую заметку ведёт хотя бы одна тематическая ссылка из другой заметки;
- `Связанные темы` не содержат ссылку страницы на саму себя;
- автоматически генерируемая навигация согласована с порядком на страницах разделов;
- каждая заметка присутствует на странице своего раздела;
- каждый раздел присутствует на главной странице;
- автоматически обслуживаемые страницы разделов согласованы с фактическим состоянием репозитория.

Содержательная релевантность конкретной связи определяется уровнем 3. Этот файл задаёт только проверки, которым требуется доступ к другим файлам или состоянию репозитория.

## Правила поддержки

После изменения состава или порядка заметок обновляется навигация:

```bash
python scripts/generate_navigation.py
```

После любых изменений заметок или правил запускаются проверки:

```bash
python scripts/generate_navigation.py --check
python scripts/check_notes.py
```

`scripts/check_notes.py` сохраняет совместимость с legacy-корпусом и пока не требует от всех 262 заметок новые содержательные блоки.

После служебного обновления изменённые новые или мигрируемые заметки снова проходят применимый цикл `note-rules/`.

Итоговые статусы `REPO PASS`, `REPO FAIL` и `REPO NOT CHECKED` интерпретируются по [`note-rules/00-workflow.md`](<./note-rules/00-workflow.md>).
