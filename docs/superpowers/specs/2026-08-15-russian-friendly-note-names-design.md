# Дружелюбные русскоязычные названия и смысловой порядок заметок

## Цель

Сделать структуру конспекта понятной русскоязычному пользователю как в Markdown-навигации, так и при просмотре файловой системы или Obsidian. Устранить неестественные англоязычные и смешанные названия, сохранив оригинальные имена технологий, стандартов, API и распространённые профессиональные термины.

Дополнительно отразить смысловой маршрут изучения в именах файлов, чтобы алфавитная сортировка совпадала с рекомендуемым порядком тем.

## Область изменений

Изменения охватывают:

- названия каталогов разделов;
- имена 262 файлов страниц тем;
- H1 страниц тем;
- подписи и пути внутренних Markdown-ссылок;
- корневой и секционные `README.md`;
- автоматически создаваемую навигацию между темами;
- правила именования страниц конспекта;
- генератор навигации и репозиторные проверки.

Основной текст заметок не редактируется, кроме упоминаний старых названий разделов, если они обозначают навигационные сущности репозитория. Содержательное улучшение или расширение заметок в эту миграцию не входит.

## Система названий

### Общий принцип

Название должно быть естественным и однозначным для русскоязычного фронтенд-разработчика. Механический перевод всех английских слов не используется.

При выборе названия применяется следующий приоритет:

1. Устоявшееся русскоязычное название понятия.
2. Русскоязычное название с исходным английским термином в скобках, если он важен для узнаваемости и поиска.
3. Оригинальное название технологии, библиотеки, стандарта, API или кодовой сущности.

Примеры:

- `Memory leaks и profiling` → `Утечки памяти и профилирование`;
- `Event Loop` → `Цикл событий (Event Loop)`;
- `Critical Render Path` → `Критический путь рендеринга (Critical Render Path)`;
- `Map Set WeakMap WeakSet` → `Map, Set, WeakMap и WeakSet`;
- `useEffect vs useLayoutEffect` → `useEffect и useLayoutEffect`.

### Сохраняемые оригинальные названия

Не переводятся:

- языки, фреймворки и продукты: `JavaScript`, `TypeScript`, `React`, `Vue`, `Next.js`, `Git`, `Jira`;
- библиотеки и инструменты: `Redux Toolkit`, `RTK Query`, `React Hook Form`, `Jest`, `Vite`, `Webpack`;
- стандарты, протоколы и API: `HTML`, `CSS`, `HTTP`, `REST`, `WebSocket`, `Promise`, `AbortController`;
- кодовые идентификаторы: `useEffect`, `requestAnimationFrame`, `async/await`, `Map`.

### Единая терминология

В русскоязычной части названий используются единые формы:

- `фронтенд`;
- `бэкенд`;
- `рендеринг`;
- `кеширование`;
- `профилирование`;
- `паттерны`.

Символ `/` не используется как обычный грамматический разделитель в имени файла. Он сохраняется только внутри общепринятой кодовой записи наподобие `async/await`; в остальных случаях применяется союз, запятая, двоеточие или другая естественная конструкция.

### Согласованность представлений

Для каждой страницы одно и то же название без служебного числового префикса используется:

- в имени файла;
- в H1;
- в подписи ссылки в оглавлениях;
- в автоматически создаваемой навигации.

Каталоги разделов не получают числовые префиксы. Корневой `README.md` уже объединяет их в несколько смысловых маршрутов, поэтому единого линейного порядка между всеми разделами нет.

## Смысловая нумерация файлов

### Формат

Каждая страница темы получает двухзначный числовой префикс и пробел:

```text
01 Название темы.md
02 Следующая тема.md
```

Нумерация:

- начинается с `01` отдельно в каждом разделе;
- идёт без пропусков;
- соответствует порядку ссылок в секционном `README.md`;
- применяется только к страницам тем;
- не применяется к `README.md` и каталогам разделов.

Двух цифр достаточно для самого крупного текущего раздела из 51 темы.

### Отображаемое название

Префикс является только средством сортировки файлов и не входит в пользовательское название темы. Например:

- файл: `06 Цикл событий (Event Loop).md`;
- H1: `Цикл событий (Event Loop)`;
- ссылка: `Цикл событий (Event Loop)`.

Генератор навигации должен удалять префикс из подписей предыдущей и следующей темы.

### Источник порядка

Смысловой порядок продолжает задаваться маршрутами в секционных `README.md`. Числовые префиксы материализуют этот порядок в файловой системе.

Репозиторная проверка должна подтверждать, что порядок ссылок на темы в секционном `README.md` совпадает с числовым порядком файлов и что последовательность префиксов непрерывна.

При добавлении, удалении или перемещении темы `scripts/renumber_notes.py` переименовывает затронутую последовательность и обновляет внутренние ссылки. Ручное рассогласование номера и маршрута считается ошибкой репозитория.

## Изменения правил и инструментов

### Правила

`_templates/note-rules/01-file-structure.md` изменяется следующим образом:

- прежний запрет числового префикса удаляется;
- двухзначный префикс становится обязательным для репозиторного файла страницы темы;
- явно фиксируется, что префикс не входит в H1 и отображаемое название;
- правило согласованности имени файла и H1 сравнивает H1 с именем файла без префикса и расширения.

Связанные репозиторные правила обновляются там, где описаны порядок страниц, имена файлов и служебная навигация. Исторические документы в `docs/superpowers/` не переписываются задним числом.

### Генератор навигации

`scripts/generate_navigation.py` должен:

- работать с переименованными каталогами;
- получать отображаемое название страницы из имени файла без числового префикса;
- не показывать номер в навигационных подписях;
- сохранять существующий порядок, заданный секционным `README.md`.

### Перенумерация

Новый `scripts/renumber_notes.py` должен:

- читать смысловой порядок из секционных `README.md`;
- вычислять непрерывные двухзначные префиксы;
- в режиме `--check` сообщать о рассогласовании без записи файлов;
- в режиме записи переименовывать затронутые страницы и обновлять относительные ссылки во всех действующих Markdown-файлах репозитория;
- до записи проверять коллизии и однозначность всех исходных и итоговых путей.

`scripts/generate_navigation.py` остаётся источником только служебных навигационных блоков. Границы ответственности генератора и скрипта перенумерации фиксируются в репозиторных правилах.

### Проверка заметок

`scripts/check_notes.py` должен дополнительно проверять:

- формат числового префикса каждой страницы темы;
- непрерывность нумерации внутри раздела;
- соответствие числового порядка порядку в секционном `README.md`;
- отсутствие префикса в H1 и отображаемых навигационных подписях;
- совпадение H1 с именем файла без префикса и расширения;
- существование целей всех внутренних ссылок после переименования.

## Порядок миграции

1. Составить явную таблицу соответствий для всех текущих и новых названий тем.
2. Проверить таблицу на коллизии имён внутри каждого раздела и недопустимые для Windows символы.
3. Обновить правила и тестовые ожидания инструментов под новый формат.
4. Переименовать каталоги разделов.
5. Переименовать страницы тем согласно согласованным названиям и маршрутам.
6. Обновить H1, секционные оглавления, корневую навигацию, пути и подписи внутренних ссылок.
7. Пересобрать автоматически управляемую навигацию.
8. Выполнить репозиторные проверки и вручную просмотреть выборку неоднозначных названий.

Переименования выполняются как перемещения существующих файлов без пересоздания содержимого, чтобы Git мог распознать их как renames и сохранить историю.

## Ошибки и ограничения миграции

До перемещения файлов миграция должна остановиться при обнаружении:

- двух одинаковых итоговых имён внутри одного раздела;
- недопустимого символа в имени файла или каталога;
- отсутствующей страницы в маршруте секционного `README.md`;
- страницы, указанной в маршруте несколько раз;
- неоднозначного соответствия старого и нового имени.

Внешние URL и фрагменты кода не изменяются. Относительные Markdown-ссылки обновляются с учётом новых имён файлов и каталогов.

## Проверка результата

Минимальная финальная проверка включает:

```powershell
python scripts/generate_navigation.py
python scripts/generate_navigation.py --check
python scripts/renumber_notes.py --check
python scripts/check_notes.py
git diff --check
```

Дополнительно выполняются:

- поиск ссылок на старые пути разделов;
- проверка отсутствия старых имён файлов среди внутренних ссылок;
- проверка формата и непрерывности нумерации;
- сравнение H1 с отображаемым именем файла;
- просмотр `git diff --summary` для подтверждения распознавания перемещений;
- ручная проверка корневого `README.md`, нескольких секционных маршрутов и навигации первой, средней и последней темы в крупных разделах.

## Критерии готовности

Миграция считается завершённой, когда:

- все названия соответствуют принятой системе;
- все страницы тем имеют корректный смысловой префикс;
- файловый порядок совпадает с маршрутами изучения;
- H1 и подписи ссылок не содержат служебных номеров;
- старые пути разделов и файлов не используются действующей навигацией;
- внутренние ссылки и автоматически управляемая навигация исправны;
- обновлённые правила однозначно описывают новый формат;
- штатные проверки завершаются успешно;
- основной текст заметок не получил посторонних содержательных изменений.
