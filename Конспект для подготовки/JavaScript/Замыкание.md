#### Быстрый ответ

Замыкание (closure) - это функция вместе с возможностью обращаться к привязкам из лексического окружения (lexical environment), в котором функция была создана. Лексическая область видимости определяется положением функции в исходном коде, а не местом её последующего вызова.

Лексическое окружение можно представить как набор привязок текущей области и ссылку на внешнее окружение. Функция сохраняет доступ к этой цепочке. Поэтому возвращённая callback-функция может читать и изменять переменную внешнего вызова даже после его завершения.

Замыкания нужны для фабрик функций, инкапсулированного состояния, обработчиков с параметрами, модулей, `once`, debounce и мемоизации. Они сохраняют доступ к привязке, а не обязательную копию текущего значения. При этом замыкание не фиксирует `this`: у обычной функции он определяется отдельными правилами вызова.

#### Ключевая схема

```text
создание функции
-> функция получает ссылку на внешнее лексическое окружение
-> функция передаётся или возвращается
-> последующий вызов разрешает имена по сохранённой цепочке окружений
```

#### Базовая модель

При каждом вызове внешней функции создаётся новое лексическое окружение со своими привязками. Вложенная функция, созданная в этом вызове, связывается именно с этим окружением. Поэтому две функции, возвращённые двумя вызовами фабрики, получают независимое состояние.

Замыкание существует не только у функции, которая «вышла наружу»: любая функция использует лексическую область места создания. Выход за время жизни внешнего вызова лишь делает поведение особенно заметным.

Привязка связывает имя со значением. Если изменяемую привязку `let` или `var` переназначить, замыкание увидит новое значение; привязку `const` переназначить нельзя. Разные итерации `for (let ...)` и разные вызовы функции создают разные привязки, поэтому их замыкания не обязаны видеть одно и то же.

#### Развернутый ответ

##### Независимое состояние между вызовами фабрики

```js
function createCounter(start = 0) {
  let value = start;

  return function increment() {
    value += 1;
    return value;
  };
}

const first = createCounter(10);
const second = createCounter(0);

first(); // 11
first(); // 12
second(); // 1
```

Каждый вызов `createCounter` создал собственную привязку `value`. Возвращённые функции изменяют разные окружения.

##### Привязка, а не одноразовая копия

```js
let value = 1;

const read = () => value;

value = 2;

console.log(read()); // 2
```

Функция читает текущее значение сохранённой привязки. Однако выражение, вычисленное заранее в другую переменную, само по себе не пересчитывается: замыкание видит привязку этой переменной, а не повторяет исходное вычисление.

##### `var` и `let` в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3
```

Все callback-функции используют одну привязку `i` на уровне функции, значение которой после цикла равно `3`. `for (let i...)` создаёт новую привязку для каждой итерации, поэтому callback-функции выводят `0`, `1`, `2`.

##### Инкапсуляция и границы

```js
function createUserStore() {
  let user = null;

  return {
    setUser(nextUser) {
      user = nextUser;
    },

    getUser() {
      return user;
    },
  };
}
```

`user` недоступен как свойство возвращённого объекта, но методы работают с ним через замыкание. Это инкапсуляция API, а не граница безопасности: код методов всё равно имеет полный доступ, а данные могут быть раскрыты возвращаемыми значениями.

##### Время жизни памяти

Пока замыкание и необходимые ему окружения достижимы, сборщик мусора не может освободить связанные данные. Это нормальный способ хранить состояние. Утечка возникает, если долгоживущий обработчик, таймер или кэш удерживает замыкание, а через него - уже ненужный DOM-узел или большой объект. Обычно устраняют внешнюю долгоживущую ссылку: снимают обработчик, очищают таймер или запись кэша.

#### Где применяется во frontend

| Ситуация | Что сохраняет замыкание | Практический результат |
| --- | --- | --- |
| Обработчик события для конкретного элемента | `id` или объект элемента | обработчик знает, с какой сущностью работать |
| Debounce | идентификатор таймера и последние аргументы | последовательные вызовы координируются между собой |
| Фабрика функции-валидатора | настройки правила | создаются функции с разной конфигурацией |
| Область модуля | закрытые привязки модуля | API экспортирует операции, но не внутреннее состояние напрямую |

#### Ключевые уточнения

- Лексическая область определяется местом создания функции, а не местом её вызова.
- Замыкание сохраняет доступ к привязке; после переназначения функция обычно видит её новое значение.
- Каждый вызов внешней функции создаёт новое окружение, поэтому созданные фабрикой функции могут иметь независимое состояние.
- `this` не является обычной лексической привязкой обычной функции и определяется отдельными правилами вызова.
- Проблема памяти появляется не из-за замыкания как такового, а из-за ненужной долгоживущей ссылки на него и связанные данные.
