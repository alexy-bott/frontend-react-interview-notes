#### Быстрый ответ

В JavaScript `==` выполняет абстрактное сравнение с определёнными правилами приведения типов, а `===` сравнивает без такого приведения. Поэтому `"1" == 1` даёт `true`, а `"1" === 1` - `false`. В прикладном коде по умолчанию выбирают `===`, а необходимое преобразование записывают явно.

`Object.is` также не приводит типы, но считает `NaN` равным самому себе и различает `+0` и `-0`. Он не сравнивает содержимое объектов. Ещё один алгоритм, SameValueZero, используется `Set`, `Map`, `Array.prototype.includes`: он считает `NaN` равным `NaN`, но не различает два нуля.

#### Ключевая схема

| Операция | Приведение типов | `NaN` и `NaN` | `+0` и `-0` | Объекты |
| --- | --- | --- | --- | --- |
| `==` | по правилам абстрактного равенства | не равны | равны | два объекта равны, только если это одна сущность; при сравнении объекта с примитивом объект сначала приводится к примитиву |
| `===` | нет | не равны | равны | одна идентичность |
| `Object.is` | нет | равны | различаются | одна идентичность |
| SameValueZero | нет | равны | равны | одна идентичность |

#### Базовая модель

Оператор сравнения сначала определяет алгоритм, а затем применяет его к двум значениям. Для примитивов результат зависит от типа, значения и специальных числовых случаев. Для двух объектов все перечисленные алгоритмы проверяют, одна ли это объектная сущность; глубокого сравнения полей не происходит.

`==` не выполняет одно универсальное преобразование «обоих значений в число». Алгоритм рассматривает сочетание типов: boolean преобразуется в число, string и number сравниваются после числового преобразования строки, а `null` и `undefined` равны друг другу по специальному правилу. Объект при сравнении с примитивом сначала преобразуется в примитив через `Symbol.toPrimitive`, `valueOf` или `toString`.

#### Развернутый ответ

##### `==` и явное преобразование

Правила `==` детерминированы, но результат труднее увидеть из кода, особенно когда значения приходят из формы, URL, браузерного хранилища или API. Явное преобразование показывает намерение и даёт место для проверки ошибки:

```js
const page = Number(searchParams.get("page"));

if (Number.isInteger(page) && page === 1) {
  // значение действительно является целой единицей
}
```

`Number("oops")` возвращает `NaN`, поэтому само явное преобразование ещё не является валидацией. Проверка результата остаётся частью границы данных.

##### `Object.is` и SameValueZero

`Object.is` реализует алгоритм SameValue. React использует `Object.is` при сравнении зависимостей хуков и в ряде проверок состояния. В обычной бизнес-логике различие `+0` и `-0` требуется редко, но `Object.is(NaN, NaN)` полезно для понимания числовой семантики.

SameValueZero нужен не как отдельный вызываемый API, а как семантика некоторых коллекций и методов. Поэтому `[NaN].includes(NaN)` возвращает `true`, хотя `NaN === NaN` возвращает `false`. `indexOf` использует strict equality и в таком случае вернёт `-1`.

##### Осознанное использование `==`

`value == null` возвращает `true` только для `null` и `undefined`. Такой короткий приём допустим, если команда использует его осознанно и проверка действительно должна объединить оба отсутствующих значения. Во всех остальных случаях явное сравнение обычно читается проще.

#### Пример

```js
0 == false; // true
0 === false; // false

null == undefined; // true
null === undefined; // false

NaN === NaN; // false
Object.is(NaN, NaN); // true

+0 === -0; // true
Object.is(+0, -0); // false

[NaN].includes(NaN); // true: SameValueZero
[NaN].indexOf(NaN); // -1: strict equality

const first = { id: 1 };
const second = { id: 1 };
first === second; // false
```

#### Где применяется во frontend

| Ситуация | Подход | Причина |
| --- | --- | --- |
| Сравнение значения из URL с числом | преобразовать, проверить результат, затем использовать `===` | URL содержит строки, а преобразование может дать `NaN` |
| Проверка только `NaN` | `Number.isNaN(value)` | не выполняет приведение типов, в отличие от глобального `isNaN` |
| Поиск `NaN` в массиве | `includes` | метод использует SameValueZero |
| Сравнение объектов по данным | явная проверка полей или специальная функция сравнения | `===` и `Object.is` проверяют идентичность |
| Проверка `null` или `undefined` вместе | `value == null` как осознанная договорённость | специальное правило объединяет только эти значения |

#### Ключевые уточнения

- `==` использует формальный алгоритм приведения типов, а не случайные эвристики, но скрывает преобразование от читателя.
- `===` не выполняет приведение типов и остаётся базовым выбором для прикладного сравнения.
- `Object.is` отличается от `===` только обработкой `NaN` и знаковых нулей; глубокого сравнения объектов нет.
- `Set`, `Map` и `includes` используют SameValueZero: `NaN` совпадает с собой, а два нуля не различаются.
- Явное преобразование входных данных не заменяет проверку результата преобразования.
