#### Быстрый ответ

Поверхностная копия (`shallow copy`) создаёт новый внешний объект, но сохраняет ссылки на те же вложенные объекты. Spread и `Object.assign` копируют собственные перечисляемые свойства верхнего уровня, поэтому мутация вложенного объекта через копию видна и в оригинале.

Глубокая копия (`deep copy`) рекурсивно создаёт независимый граф поддерживаемых значений. `structuredClone` использует браузерный алгоритм structured clone и поддерживает циклические ссылки, `Date`, `Map`, `Set`, `ArrayBuffer`, типизированные массивы и многие платформенные объекты. Он не клонирует функции и DOM-узлы и не сохраняет произвольный прототип, приватные поля или дескрипторы свойств экземпляра пользовательского класса.

Глубокое клонирование не является обязательным способом неизменяемого обновления. Для состояния обычно копируют только путь до изменившегося значения и сохраняют идентичность остальных ветвей. Это называется структурным разделением (`structural sharing`): оно уменьшает объём работы и позволяет сравнениям по ссылке обнаруживать реальные изменения.

#### Ключевая схема

| Способ | Глубина | Что сохраняется | Основная граница |
| --- | --- | --- | --- |
| `{ ...obj }` | один уровень | собственные перечисляемые строковые и символьные свойства | вложенные объекты остаются общими |
| `Object.assign({}, obj)` | один уровень | собственные перечисляемые строковые и символьные свойства | может вызвать setter целевого объекта |
| `structuredClone(value)` | рекурсивная | поддерживаемые типы, циклы и повторные ссылки | функции, DOM-узлы и произвольный прототип не копируются |
| Преобразование через JSON | рекурсивная с потерями | только JSON-представление | типы меняются или теряются, циклы и `BigInt` вызывают ошибку |
| Предметное клонирование | по правилам задачи | только нужная семантика | реализацию и стоимость определяет приложение |

#### Базовая модель

Копирование начинается с ответа на вопрос, какую независимость нужно получить. Новый внешний объект решает только изменение верхнего уровня. Полностью независимый граф требует правил для каждого встреченного типа, циклических и повторных ссылок, прототипов и специальных ресурсов.

У глубокой копии нет единственной универсальной семантики. Не всегда понятно, нужно ли сохранять два свойства, указывавшие на один вложенный объект, как одну общую копию; как копировать экземпляр класса; что делать с функцией, DOM-узлом, потоком данных или соединением. Поэтому подход выбирают по структуре данных, а не по слову «глубокий».

Копирование также отличается от сериализации. JSON создаёт текстовое представление ограниченной модели данных, а `structuredClone` переносит поддерживаемый граф значений без промежуточного JSON-текста.

#### Развернутый ответ

##### Spread и `Object.assign`

Оба способа читают собственные перечисляемые свойства источника со строковыми и символьными ключами. При чтении свойства доступа вызывается getter, а результат становится обычным значением в копии; исходный дескриптор не переносится. Прототип источника также не сохраняется.

Spread объекта создаёт свойства нового объекта, а `Object.assign(target, source)` записывает их в существующий целевой объект через обычную операцию `Set`, которая может вызвать setter. Для простого `{}` результат обычно похож, но семантика не полностью одинакова.

##### Структурное разделение

При неизменяемом обновлении копируют только изменившиеся контейнеры. Неизменившиеся ветви сохраняют идентичность, а изменившаяся ветвь получает новые объекты по пути от корня. Такой результат не является полностью независимой глубокой копией, но именно эта общая структура часто нужна при управлении состоянием.

##### `structuredClone`

`structuredClone` сохраняет циклы и повторные ссылки внутри клонируемого графа. Для переносимых объектов (`transferable objects`), например `ArrayBuffer`, можно передать параметр `transfer`: ресурс будет перемещён, а исходный буфер станет отсоединённым (`detached`). Без `transfer` создаётся копия поддерживаемых данных.

Функция и DOM-узел приводят к `DataCloneError`. Пользовательский экземпляр класса не следует считать полноценной копией экземпляра: цепочка прототипов и приватные элементы не восстанавливают исходную семантику класса.

##### Копирование через JSON

`JSON.stringify` пропускает свойства объекта со значениями `undefined`, function и symbol; в массиве некоторые неподдерживаемые значения превращаются в `null`. `Date` сериализуется строкой, `Map` и `Set` не получают ожидаемого содержимого, а `BigInt` и циклические ссылки по умолчанию вызывают ошибку. Поэтому такой способ допустим только тогда, когда JSON-модель является намеренным контрактом данных.

Если нужно сохранить прототип и дескрипторы конкретного объекта, используют `Object.getOwnPropertyDescriptors`, `Object.create` и предметную логику. Это поверхностная операция над дескрипторами, а не готовый универсальный алгоритм глубокой копии.

#### Пример

```js
const original = {
  id: 1,
  profile: {
    name: "Ann",
  },
};

const shallow = { ...original };

shallow.profile.name = "Kate";

console.log(original.profile.name); // "Kate"
```

Копирование нужного пути:

```js
const next = {
  ...original,
  profile: {
    ...original.profile,
    name: "Kate",
  },
};
```

Глубокий клон встроенным API:

```js
const data = {
  createdAt: new Date(),
  ids: new Set([1, 2, 3]),
};

const copy = structuredClone(data);

console.log(copy.createdAt instanceof Date); // true
console.log(copy.ids instanceof Set); // true
```

#### Где применяется во frontend

| Задача | Подход | Причина |
| --- | --- | --- |
| Обновить вложенное состояние React | копирование изменившегося пути | сохраняет идентичность неизменившихся ветвей |
| Изолировать черновик из обычных данных | `structuredClone`, если типы поддерживаются | создаёт независимый граф данных |
| Передать большой `ArrayBuffer` в Worker | `structuredClone` с `transfer` | избегает копирования и отсоединяет исходный буфер |
| Подготовить JSON для API | явная сериализация | формат API, а не универсальная копия объекта во время выполнения |

#### Ключевые уточнения

- Spread и `Object.assign` создают только поверхностную копию и не сохраняют прототип и дескрипторы источника.
- Глубокая копия требует правил для типов, циклов, повторных ссылок и ресурсов; универсальной семантики нет.
- `structuredClone` поддерживает многие встроенные типы, но не функции, DOM-узлы и произвольную семантику класса.
- Копирование через JSON является сериализацией с потерями, а не общим алгоритмом клонирования.
- Для неизменяемого состояния обычно нужно структурное разделение, а не полное глубокое клонирование.
