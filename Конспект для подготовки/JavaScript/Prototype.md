#### Быстрый ответ

JavaScript использует цепочку прототипов (`prototype chain`) для делегирования свойств. У обычного объекта есть внутренний `[[Prototype]]`, указывающий на другой объект или `null`. При чтении свойства JavaScript сначала ищет собственное свойство (`own property`), затем идёт по цепочке прототипов до найденного свойства или конца цепочки.

`[[Prototype]]` конкретного объекта и свойство `prototype` функции - разные сущности. При `new Fn()` новый объект обычно получает `Fn.prototype` как свой `[[Prototype]]`. `class`, `extends` и `super` предоставляют более строгий синтаксис поверх той же прототипной модели.

`__proto__` - устаревшее свойство доступа. Прототип читают через `Object.getPrototypeOf`, а объект с нужным прототипом создают через `Object.create`. Динамически менять цепочку прототипов обычно не требуется: это усложняет модель и может сбросить оптимизации формы объектов.

#### Ключевая схема

| Понятие | Что означает |
| --- | --- |
| `[[Prototype]]` | внутренняя ссылка объекта на прототип |
| `Object.getPrototypeOf(obj)` | безопасно получить прототип |
| `Object.create(parent)` | создать объект с заданным прототипом |
| `Fn.prototype` | объект для будущих экземпляров `new Fn()` |
| `obj.__proto__` | устаревший способ доступа к `[[Prototype]]` |
| `class` | синтаксис поверх цепочки прототипов |

#### Базовая модель

Цепочка прототипов участвует только тогда, когда собственного свойства с нужным ключом нет. Найденный унаследованный метод не копируется в объект: вызывается функция, хранящаяся выше по цепочке, а `this` определяется объектом-получателем исходного вызова. Поэтому в `user.say()` метод может лежать в `User.prototype`, но `this` внутри всё равно равен `user`.

Присваивание `obj.key = value` обычно создаёт или обновляет собственное свойство и тем самым скрывает унаследованное свойство с тем же ключом. Но унаследованный setter может перехватить запись, а унаследованное свойство с `writable: false` - запретить её. Поэтому чтение и запись не являются одной и той же операцией.

Цепочка определяет доступ к поведению, а не копирование данных. Для проверки собственного свойства используют `Object.hasOwn`, для чтения непосредственного прототипа - `Object.getPrototypeOf`, а `in` проверяет всю цепочку.

#### Развернутый ответ

##### Поиск, объект-получатель и затенение свойства

```js
const parent = {
  value: 1,
  read() {
    return this.value;
  },
};

const child = Object.create(parent);
child.value = 2;

child.read(); // 2
```

`read` найден в `parent`, но объект-получатель вызова - `child`. Собственное свойство `child.value` скрывает унаследованное `parent.value`.

##### Что делает `new Fn()`

Упрощённая последовательность:

1. создаётся новый объект;
2. его `[[Prototype]]` устанавливается в текущее значение `Fn.prototype`, если оно является объектом;
3. `Fn` вызывается с новым объектом как `this`;
4. явно возвращённый объект заменяет созданный экземпляр, а возвращённый примитив игнорируется.

Изменение свойств существующего `Fn.prototype` видно старым экземплярам через ту же цепочку. Полное присваивание `Fn.prototype = otherObject` влияет только на объекты, созданные последующими вызовами `new`.

##### Методы и `class`

Метод в прототипе один для всех экземпляров, но получает отдельный `this` при каждом вызове. Методы, объявленные в `class`, размещаются в `ClassName.prototype` и являются неперечисляемыми (`enumerable: false`). Поля экземпляра создаются как собственные свойства.

`class` добавляет правила поверх прототипов: constructor вызывается только через `new`, объявление класса находится в TDZ, а методы выполняются в strict mode. Поэтому `class` полезно понимать как отдельный синтаксический и семантический слой, а не как простую текстовую замену функции-конструктора.

##### `instanceof`

Обычная проверка `value instanceof Fn` ищет текущий `Fn.prototype` в цепочке прототипов значения. Она не проверяет структуру объекта и может дать неожиданный результат после замены `Fn.prototype` или между разными глобальными окружениями, например страницей и `iframe`. Для встроенных типов существуют более прямые проверки, например `Array.isArray`.

`Object.create(null)` создаёт объект без `Object.prototype`. У него нет унаследованных `toString` и `hasOwnProperty`, что иногда удобно для словаря, но требует явных API вроде `Object.hasOwn`.

#### Пример

```js
function User(name) {
  this.name = name;
}

User.prototype.sayName = function () {
  return this.name;
};

const user = new User("Ann");

console.log(user.sayName()); // "Ann"
console.log(Object.getPrototypeOf(user) === User.prototype); // true
```

Прототипное делегирование без функции-конструктора:

```js
const parent = {
  ping() {
    return "pong";
  },
};

const child = Object.create(parent);
child.name = "child";

console.log(child.ping()); // "pong"
console.log(Object.hasOwn(child, "ping")); // false
```

#### Где применяется во frontend

| Ситуация | Что важно понимать |
| --- | --- |
| Работа с `class` и методами экземпляров | методы находятся в прототипе, данные обычно в собственных свойствах |
| Проверка входного объекта | `instanceof` проверяет цепочку, а не структуру данных |
| Перебор ключей | унаследованные и собственные свойства обрабатываются разными API |
| Словарь без унаследованных ключей | `Object.create(null)` или чаще `Map` |

#### Ключевые уточнения

- `[[Prototype]]` принадлежит объекту, а `Fn.prototype` используется как прототип будущих экземпляров `new Fn()`.
- Унаследованный метод вызывается с объектом-получателем исходного вызова, а не с объектом, где функция была найдена.
- Собственное свойство скрывает одноимённое унаследованное свойство, не изменяя сам прототип.
- `instanceof` ищет `Fn.prototype` в цепочке и не подтверждает структуру данных.
- `class` использует цепочку прототипов, но также добавляет TDZ, strict mode и специальные правила constructor.
