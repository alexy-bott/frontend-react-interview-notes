#### Быстрый ответ

Контекст выполнения (`execution context`) - состояние, необходимое движку для выполнения текущего скрипта, модуля или вызова функции. Активные контексты образуют стек вызовов (`call stack`): новый вызов помещает контекст наверх, а `return` или необработанная ошибка снимают его.

Лексическое окружение (`lexical environment`) связывает имена с переменными, функциями и классами и содержит ссылку на внешнее окружение. При чтении имени JavaScript ищет привязку сначала в текущем окружении, затем во внешнем и так далее. Эта последовательность называется цепочкой областей видимости (`scope chain`).

JavaScript использует лексическую область видимости (`lexical scope`): внешняя область функции определяется местом её создания в исходном коде, а не местом последующего вызова. На этом основаны замыкания.

Область видимости и лексическое окружение связаны, но не равны. Область видимости описывает участок кода, где доступно имя, а окружение хранит привязки конкретного выполнения этого участка.

#### Ключевая схема

```text
call stack:
┌──────────────────────┐
│ inner context        │
├──────────────────────┤
│ outer context        │
├──────────────────────┤
│ module/global context│
└──────────────────────┘

scope chain inner:
inner environment → outer environment → module/global environment
```

Стек вызовов отвечает на вопрос «какой код выполняется и куда вернуться». Цепочка областей видимости отвечает на вопрос «где искать имя». Эти цепочки часто встречаются в одном примере, но строятся по разным правилам.

#### Контекст выполнения

При запуске скрипта или модуля среда создаёт верхнеуровневый контекст. Каждый обычный вызов функции создаёт новый контекст с состоянием этого вызова: параметрами, локальными привязками, `this` для обычной функции, ссылками на используемые окружения и позицией продолжения.

```js
function outer() {
  return inner();
}

function inner() {
  return 42;
}

outer();
```

Последовательность стека:

```text
global/module
global/module → outer
global/module → outer → inner
global/module → outer
global/module
```

`await` не удерживает синхронный вызов в стеке. `async`-функция приостанавливается, текущий вызов покидает стек, а после выполнения или отклонения ожидаемого Promise продолжение запускается как микрозадача с восстановлением необходимого состояния функции.

#### Подготовка и выполнение

До пошагового выполнения тела JavaScript подготавливает привязки объявлений. Удобная учебная модель делит работу на два этапа:

1. Создать окружения и привязки для объявлений текущего кода.
2. Выполнить инструкции по порядку и инициализировать значения в предусмотренных местах.

`var` получает `undefined`, function declaration получает функцию, а `let`, `const` и `class` существуют неинициализированными до строки объявления. Поэтому обращение к последним в temporal dead zone (TDZ) даёт `ReferenceError`.

Это не физическое перемещение строк вверх. Подробное поведение разобрано в [[Конспект для подготовки/JavaScript/Hoisting и TDZ]].

#### Лексическое окружение

В модели спецификации лексическое окружение состоит из:

- записи окружения (`environment record`), где хранятся привязки и правила доступа к ним;
- ссылки на внешнее окружение (`outer environment`).

При чтении `value` движок выполняет разрешение имени:

```js
const value = "module";

function outer() {
  const value = "outer";

  function inner() {
    return value;
  }

  return inner();
}

console.log(outer()); // "outer"
```

`inner` сначала проверяет своё окружение. Там `value` нет, поэтому поиск идёт во внешнее окружение `outer` и останавливается на его привязке. До области модуля поиск уже не доходит.

#### Виды области видимости

| Область | Что обычно создаёт | Примеры привязок |
| --- | --- | --- |
| Глобальная | запуск классического скрипта на странице | глобальные объявления и свойства среды |
| Модульная | ES module | верхнеуровневые `let`, `const`, импорты и экспорты |
| Функциональная | вызов функции | параметры, `var`, локальные объявления |
| Блочная | `{}`, `if`, `for`, `catch` | `let`, `const`, `class` |

`var` имеет область видимости функции, а не блока:

```js
function example() {
  if (true) {
    var functionScoped = 1;
    let blockScoped = 2;
  }

  console.log(functionScoped); // 1
  // console.log(blockScoped); // ReferenceError
}
```

У `for (let i = ...)` создаются отдельные привязки для итераций, поэтому callback-функции получают ожидаемое значение каждой итерации. `var` использовал бы одну общую привязку функции.

#### Глобальный скрипт и ES module

В классическом браузерном скрипте глобальное окружение сочетает разные механизмы. Верхнеуровневый `var` и некоторые объявления функций могут создать свойства `window`, а `let`, `const` и `class` создают глобальные привязки без одноимённых свойств объекта.

```html
<script>
  var legacy = 1;
  const modern = 2;

  console.log(window.legacy); // 1
  console.log(window.modern); // undefined
</script>
```

В ES module все верхнеуровневые объявления находятся в области модуля, не становятся свойствами `window` и доступны другим модулям только через `export` и `import`.

#### Лексическая область и место вызова

Функция запоминает внешнее окружение при создании. Передача в другой код не меняет scope chain:

```js
const value = "global";

function createReader() {
  const value = "created";

  return function read() {
    return value;
  };
}

function run(callback) {
  const value = "called";
  return callback();
}

console.log(run(createReader())); // "created"
```

`run` находится в стеке во время вызова callback-функции, но его локальное окружение не становится внешним для `read`. Цепочка областей видимости определяется исходным вложением функции `read` в `createReader`.

Если бы язык использовал динамическую область видимости (`dynamic scope`), поиск зависел бы от цепочки вызовов. JavaScript так не работает.

#### Затенение имени

Внутренняя привязка с тем же именем скрывает внешнюю:

```js
const status = "global";

function render() {
  const status = "local";
  console.log(status); // "local"
}
```

Внешнее значение не меняется, но недоступно под этим именем внутри текущей области. Если внутренняя привязка существует, но находится в TDZ, поиск не продолжится к внешнему значению: возникнет `ReferenceError`.

#### Контекст, окружение и замыкание

После `return` контекст функции снимается со стека вызовов. Это не означает немедленное уничтожение всех созданных данных.

Если возвращённая функция использует внешнюю привязку, её внутренняя ссылка `[[Environment]]` сохраняет доступ к нужному окружению:

```js
function createCounter() {
  let count = 0;

  return () => ++count;
}

const next = createCounter();
next(); // 1
next(); // 2
```

Контекста вызова `createCounter` в стеке уже нет, но привязка `count` остаётся достижима через функцию `next`. Это и есть основа замыкания: окружение хранит доступные привязки, а не текстовую копию значений.

#### `this` не ищется как обычное имя

У обычной функции `this` определяется формой вызова, а не поиском по лексической области. Arrow function не создаёт собственного `this` и использует `this` внешнего контекста.

Поэтому две модели нельзя смешивать:

- свободная переменная разрешается по цепочке областей видимости;
- `this` обычной функции определяется местом и формой вызова (`call-site`);
- `this` стрелочной функции берётся из внешнего окружения.

Подробности находятся в [[Конспект для подготовки/JavaScript/this]].

#### Где применяется во frontend

- Callback-функция сохраняет окружение рендера или функции, в которой создана; это объясняет устаревшие замыкания (stale closures).
- `let` в цикле даёт отдельную привязку каждой итерации для обработчиков событий.
- ES modules изолируют верхнеуровневые имена и формируют явные зависимости.
- Debugger отдельно показывает Call Stack и Scope: первая панель отражает активные вызовы, вторая - доступные привязки.
- Утечка через callback-функцию объясняется тем, что живая функция удерживает нужное лексическое окружение.

#### Ключевые уточнения

- Контекст выполнения описывает активное выполнение, а лексическое окружение - разрешение имён и их привязки.
- Стек вызовов строится по вызовам, цепочка областей видимости - по лексическому вложению кода.
- Место вызова callback-функции не меняет её внешнюю область видимости.
- Область видимости является статической частью кода, а окружение создаётся для конкретного выполнения.
- После снятия контекста со стека захваченное окружение может продолжать жить через замыкание.
- `this` обычной функции не ищется как переменная по цепочке областей видимости.
- TDZ внутренней привязки не позволяет «провалиться» к одноимённому внешнему значению.
