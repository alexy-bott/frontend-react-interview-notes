#### Быстрый ответ

`Number` - основной числовой примитив JavaScript, реализованный как 64-битный формат с плавающей точкой IEEE 754. Он хранит целые и дробные значения, а также `NaN`, `Infinity`, `-Infinity` и два знаковых нуля.

Не все десятичные дроби представимы в двоичном виде точно, поэтому `0.1 + 0.2` отличается от `0.3`. Целые точно представлены только в диапазоне от `Number.MIN_SAFE_INTEGER` до `Number.MAX_SAFE_INTEGER` (`±(2^53 - 1)`).

`BigInt` хранит целые произвольной величины без потери точности. Он не поддерживает дроби, не смешивается с `Number` в арифметике и не сериализуется обычным `JSON.stringify` без явного преобразования.

Для денег обычно хранят минимальные единицы валюты целым числом, если диапазон безопасен, либо используют библиотеку десятичной арифметики. Большие идентификаторы API часто передаёт строкой, чтобы разбор JSON не потерял цифры.

#### Ключевая схема

| Требование | Выбор |
| --- | --- |
| Обычные вычисления, координаты, размеры | `Number` |
| Целое в безопасном диапазоне | `Number` + `Number.isSafeInteger` |
| Очень большое точное целое | `BigInt` |
| Точные денежные расчёты | целые минимальные единицы или библиотека десятичной арифметики |
| ID, который не участвует в арифметике | строка |

```js
Number.MAX_SAFE_INTEGER; // 9007199254740991
Number.isSafeInteger(value);
```

#### Почему `0.1 + 0.2 !== 0.3`

IEEE 754 хранит число в двоичной форме. Десятичные `0.1` и `0.2` имеют бесконечное двоичное представление и округляются до ближайших доступных значений.

```js
0.1 + 0.2;       // 0.30000000000000004
0.1 + 0.2 === 0.3; // false
```

Это не случайная ошибка конкретного движка, а следствие конечного двоичного представления чисел с плавающей точкой.

Для приближённого сравнения используют tolerance, соразмерный значениям и предметной задаче:

```js
function approximatelyEqual(a, b, tolerance = Number.EPSILON) {
  const scale = Math.max(1, Math.abs(a), Math.abs(b));
  return Math.abs(a - b) <= tolerance * scale;
}
```

`Number.EPSILON` - расстояние между `1` и ближайшим большим значением Number. Один `EPSILON` не является универсальным допуском для миллионов, измерений или финансовых правил; допустимую погрешность определяет предметная область.

#### Безопасные целые числа

```js
const max = Number.MAX_SAFE_INTEGER;

max + 1 === max + 2; // true
```

За пределами безопасного диапазона соседние целые могут отображаться одним значением Number. Поэтому `Number.isInteger` недостаточно:

```js
Number.isInteger(9007199254740992);     // true
Number.isSafeInteger(9007199254740992); // false
```

Если backend отправил слишком большое число в JSON, точность может потеряться во время разбора до любой проверки. Передавать такой ID нужно строкой.

#### `NaN` и бесконечности

`NaN` означает недопустимый числовой результат, но имеет тип `number`:

```js
typeof NaN; // "number"
Number("text"); // NaN
```

Для проверки используют `Number.isNaN`, потому что глобальный `isNaN` сначала выполняет приведение типов:

```js
Number.isNaN("text"); // false
isNaN("text");        // true
```

`Number.isFinite` проверяет конечное значение Number без приведения типов:

```js
Number.isFinite(42);   // true
Number.isFinite("42"); // false
```

Вычисление с `NaN` обычно распространяет `NaN`, поэтому ошибку лучше обнаружить на границе преобразования, а не в конце формулы.

#### Округление и форматирование

`toFixed` форматирует число и возвращает строку:

```js
(12.5).toFixed(2); // "12.50"
```

Это не способ точного десятичного хранения. Погрешности вычислений с плавающей точкой могли возникнуть ещё до форматирования.

Для отображения валюты и числа используют `Intl.NumberFormat`:

```js
new Intl.NumberFormat("ru-RU", {
  style: "currency",
  currency: "RUB",
}).format(1234.5);
```

Форматирование отделяют от внутреннего значения. Нельзя преобразовывать локализованную строку отображения обратно через `Number` без явных правил локали.

#### `BigInt`

```js
const value = 9007199254740993n;
const parsed = BigInt("9007199254740993");
```

Суффикс `n` доступен только у целочисленного литерала. `BigInt(10)` преобразует целочисленное значение Number, но если Number уже потерял точность, BigInt не восстановит исходные цифры.

Арифметика требует одинаковый числовой тип:

```js
1n + 2n; // 3n
1n + 2;  // TypeError
```

Деление BigInt отбрасывает дробную часть к нулю:

```js
5n / 2n; // 2n
-5n / 2n; // -2n
```

Методы `Math` работают с Number и обычно не принимают BigInt. Для алгоритма с BigInt используют соответствующие операторы или специальную библиотеку.

#### Сравнение Number и BigInt

Строгое равенство не приводит types:

```js
1n === 1; // false
```

Операторы отношения умеют сравнивать многие значения Number и BigInt:

```js
1n < 2; // true
```

Но смешанный массив нельзя численно сортировать функцией `(a, b) => a - b`, потому что вычитание разных числовых типов выбросит `TypeError`. Сравнение задают через `<` и `>` и отдельно определяют поведение для `NaN`.

#### `-0`

IEEE 754 содержит `+0` и `-0`:

```js
0 === -0;          // true
Object.is(0, -0);  // false
1 / 0;             // Infinity
1 / -0;            // -Infinity
```

Для большинства UI-задач они эквивалентны. Различие важно в некоторых математических algorithms и при использовании `Object.is`.

#### Деньги

Хранение рублей как десятичной дроби в Number может накапливать ошибки округления. Распространённая модель - целые копейки:

```js
const priceInKopecks = 1999;
const quantity = 3;
const totalInKopecks = priceInKopecks * quantity;
```

Нужно проверить безопасный диапазон и правила округления налогов и скидок. Для валют с переменным числом знаков, больших значений и регулируемой десятичной арифметики применяют специальную библиотеку или расчёт на backend с согласованным контрактом.

BigInt решает точность целых чисел, но не десятичных дробей и не определяет правила финансового округления.

#### Где применяется во frontend

- Поле формы сначала даёт строку, которая затем проходит явное преобразование и проверку конечности и диапазона.
- Большой ID от backend хранится строкой, а не небезопасным Number.
- Цена хранится в minor units и форматируется через `Intl.NumberFormat`.
- Анимация Canvas и layout использует Number и допустимую временную погрешность.
- Криптографические или протокольные счётчики могут требовать BigInt или типизированные массивы, но не обычную десятичную арифметику.

#### Ключевые уточнения

- Number является типом с плавающей точкой, а не отдельными `int` и `float`.
- Decimal fractions могут быть неточны из-за двоичного представления.
- `Number.isInteger` не гарантирует, что целое находится в безопасном диапазоне.
- `Number.isNaN` и `Number.isFinite` не выполняют приведение типов.
- BigInt сохраняет большие целые, но не дроби и не смешивается с Number в арифметике.
- Преобразование уже неточного Number в BigInt не восстанавливает данные.
- Форматирование для отображения, модель хранения и предметные правила округления являются разными задачами.
