#### Быстрый ответ

В JavaScript есть семь примитивных типов: `string`, `number`, `bigint`, `boolean`, `symbol`, `undefined` и `null`, а также тип `object`. Тип принадлежит значению, поэтому одна переменная в разное время может содержать значения разных типов.

Примитивы неизменяемы: операция создаёт новое значение, а не изменяет существующее. Объект обладает идентичностью и хранит изменяемый набор свойств. Если присвоить один объект двум переменным, обе будут указывать на одну объектную сущность, поэтому мутация через одну переменную видна через другую. Массивы, функции, даты, `Map`, `Set` и `Promise` относятся к объектам; `typeof` для функций возвращает специальную строку `"function"`.

`typeof` подходит для большинства примитивов, но не является универсальной проверкой данных: `typeof null` даёт `"object"`, массив проверяют через `Array.isArray`, а данные из API требуют проверки не только типа, но и структуры.

#### Ключевая схема

| Категория | Примеры | Как распознать | Основное свойство |
| --- | --- | --- | --- |
| Примитивы | `string`, `number`, `bigint`, `boolean`, `symbol`, `undefined`, `null` | `typeof`, а для `null` отдельная проверка | не изменяются на месте |
| Обычные объекты | `{}`, `Date`, `Map`, `Set`, `Promise` | `value !== null && typeof value === "object"` и прикладная проверка | имеют идентичность и свойства |
| Массивы | `[]` | `Array.isArray(value)` | являются объектами со специальным поведением |
| Функции | `function`, arrow function | `typeof value === "function"` | являются вызываемыми объектами |

#### Базовая модель

JavaScript динамически типизирован: операция учитывает тип текущего значения во время выполнения. Объявление `let value` не закрепляет за переменной один тип. TypeScript может ограничить допустимые присваивания при разработке, но его типы удаляются из исполняемого JavaScript.

Неизменяемость примитива не означает неизменяемость переменной. `let text = "a"; text = "b"` меняет привязку `text` к другому строковому значению, но не изменяет строку `"a"`. Аналогично `const` запрещает переназначить привязку, но не замораживает объект внутри неё.

У объектов важна идентичность. Два литерала `{}` создают две разные сущности, даже если их свойства совпадают. Присваивание существующего объекта не клонирует его: новое имя получает доступ к той же сущности.

#### Развернутый ответ

##### Особенности примитивов

- `number` хранит числа в формате IEEE 754, включая `NaN`, `Infinity` и `-0`. Целые значения безопасно представлены только до `Number.MAX_SAFE_INTEGER`.
- `bigint` хранит целые числа произвольной точности. В арифметике его нельзя неявно смешивать с `number`.
- `symbol` создаёт уникальное примитивное значение, часто используемое как ключ свойства или идентификатор протокола.
- `undefined` обычно означает отсутствие присвоенного значения, а `null` - явно заданное отсутствие объекта или значения. Это соглашение, а не автоматическая гарантия конкретного API.

```js
let a = 1;
let b = a;

b += 1;

console.log(a); // 1
console.log(b); // 2: b получил другое number-значение
```

##### Объектная идентичность

```js
const user = { name: "Ann" };
const alias = user;

alias.name = "Kate";

console.log(user.name); // Kate
console.log(alias === user); // true
console.log({ name: "Kate" } === user); // false
```

`alias` и `user` обозначают один объект. Новый литерал создаёт другой объект, поэтому строгое сравнение проверяет идентичность, а не совпадение полей. Выражение «объекты передаются по ссылке» является сокращением: аргументы и присваивания в JavaScript передают значения, но объектное значение предоставляет доступ к одной общей сущности.

##### `typeof` и специализированные проверки

```js
typeof "hello"; // "string"
typeof 42; // "number"
typeof 10n; // "bigint"
typeof true; // "boolean"
typeof Symbol("id"); // "symbol"
typeof undefined; // "undefined"
typeof null; // "object"
typeof {}; // "object"
typeof []; // "object"
typeof function fn() {}; // "function"
```

`typeof null === "object"` - сохранённая историческая особенность языка, а не свидетельство того, что `null` является объектом. `typeof []` не отличает массив от других объектов. Для прикладной проверки выбирают API, соответствующий вопросу:

- `value === null` - это именно `null`;
- `Array.isArray(value)` - массив, в том числе созданный в другом глобальном окружении, например внутри `iframe`;
- `value instanceof Date` - экземпляр ожидаемого конструктора, если объект и конструктор принадлежат совместимому глобальному окружению;
- `Object.prototype.toString.call(value)` - низкоуровневая диагностика встроенного типа; результат можно изменить через `Symbol.toStringTag`;
- валидатор схемы или ручная функция-проверка (type guard) - структура внешних данных.

Wrapper-объекты вроде `new String("text")` почти никогда не нужны. Обычный примитив временно получает доступ к методам через autoboxing, но остаётся примитивом. Подробности вынесены в [[Конспект для подготовки/JavaScript/Autoboxing]].

#### Пример

```js
function describe(value) {
  if (value === null) return "null";
  if (Array.isArray(value)) return "array";
  return typeof value;
}

console.log(describe(null)); // null
console.log(describe([1, 2])); // array
console.log(describe(() => {})); // function
console.log(describe({ id: 1 })); // object
```

Этот код определяет только общую категорию значения во время выполнения. Он не доказывает, что объект соответствует бизнес-структуре `User`: для этого нужно отдельно проверить обязательные поля и их значения.

#### Где применяется во frontend

| Ситуация | Что проверяется | Причина |
| --- | --- | --- |
| Ответ API | структура полей через валидатор схемы | TypeScript не проверяет данные во время выполнения |
| Ветвление по массиву | `Array.isArray` | `typeof` возвращает `"object"` |
| Проверка отсутствия | договорённость API о `null`/`undefined` | эти значения имеют разную семантику при строгом сравнении |
| Изменение объекта в состоянии (state) | идентичность и создание нового объекта | изменение общей объектной сущности видно через все ссылки на неё |

#### Ключевые уточнения

- Тип принадлежит значению во время выполнения, а не имени JavaScript-переменной.
- Примитив неизменяем, но переменную с примитивом можно переназначить, если она объявлена через `let`.
- Объекты сравниваются по идентичности; совпадение свойств само по себе не делает их равными.
- `typeof null` возвращает `"object"`, но `null` остаётся примитивом.
- TypeScript-типы не заменяют проверку внешних данных во время выполнения.
