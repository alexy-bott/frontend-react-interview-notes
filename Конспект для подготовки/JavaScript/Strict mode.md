#### Быстрый ответ

Strict mode - режим выполнения JavaScript с более строгими правилами. Он превращает часть операций, которые иначе завершились бы без результата и без ошибки, в явные исключения, запрещает некоторые неоднозначные конструкции и упрощает движку анализ кода.

Классический скрипт или отдельную функцию переводит в strict mode директива `"use strict"` в начале соответствующего тела. ES modules и тела классов всегда выполняются в strict mode автоматически.

Основные наблюдаемые отличия: присваивание необъявленному имени выбрасывает `ReferenceError`, обычный вызов функции получает `this === undefined`, запись в свойство с `writable: false` и удаление свойства с `configurable: false` выбрасывают `TypeError`, а `with` и часть устаревшего синтаксиса запрещены.

Strict mode не добавляет статическую типизацию, не делает объекты неизменяемыми и не изолирует недоверенный код.

#### Ключевая схема

```js
"use strict"; // весь классический скрипт ниже директивы

function strictFunction() {
  "use strict"; // только тело функции
}
```

```js
// ES module: strict автоматически
export function run() {}

// class body: strict автоматически
class User {}
```

Директива распознаётся только в `directive prologue` - последовательности строковых выражений в начале скрипта или функции. Строка в середине функции режим не меняет.

#### Неявные глобальные переменные

В обычном, или sloppy, режиме присваивание необъявленному имени исторически могло создать свойство глобального объекта:

```js
function legacy() {
  accidental = 42;
}
```

В strict mode это `ReferenceError`:

```js
"use strict";

function safe() {
  accidental = 42; // ReferenceError
}
```

Так опечатка не превращается в глобальное состояние, доступное всему приложению.

Это не относится к явной записи `globalThis.accidental = 42`: она остаётся разрешённой, потому что намерение указано явно.

#### `this` в обычной функции

```js
function showThis() {
  "use strict";
  return this;
}

showThis(); // undefined
```

При обычном вызове функции в классическом браузерном скрипте sloppy mode обычно подставляет `globalThis` вместо `undefined` или `null` и оборачивает примитивное значение `this`. Strict mode сохраняет переданное значение без такой подстановки.

```js
showThis.call(42); // 42 в strict function
```

Это делает потерю объекта-получателя заметнее: метод, переданный как обычная callback-функция, не начинает случайно работать с `window`.

Стрелочная функция по-прежнему не создаёт собственного `this`; strict mode не меняет её лексический `this`.

#### Явные ошибки вместо молчаливого отказа

```js
"use strict";

const object = {};

Object.defineProperty(object, "id", {
  value: 1,
  writable: false,
  configurable: false,
});

object.id = 2;  // TypeError
delete object.id; // TypeError
```

В sloppy mode такие операции часто просто не меняют объект. Ошибка в strict mode показывает нарушение ограничения ближе к его источнику.

Ловушка `set` объекта `Proxy`, которая возвращает `false`, также приводит к `TypeError` при присваивании в strict mode. В sloppy mode такое присваивание может молча завершиться без изменения.

#### Запрещённые и изменённые конструкции

Strict mode запрещает или меняет устаревшее поведение:

- инструкцию `with`;
- удаление имени переменной через `delete name`;
- повторяющиеся имена параметров;
- устаревшие восьмеричные литералы вида `0123`;
- имена привязок `eval` и `arguments` в ряде позиций;
- связь между элементами `arguments` и параметрами функции.

```js
function example(value) {
  "use strict";

  arguments[0] = 10;
  console.log(value); // исходное value, aliasing нет
}
```

В функции без strict mode и с простым списком параметров `arguments[0]` исторически мог быть связан с соответствующим параметром. В strict mode это независимые значения.

#### Область действия strict mode

Директива на уровне классического скрипта действует на весь этот скрипт, но не переводит другие подключённые теги `<script>` автоматически.

Директива внутри функции действует на эту функцию и вложенный код. Вызов отдельной функции без strict mode из строгой функции не меняет правила выполнения вызываемой функции.

ES module работает в strict mode независимо от наличия директивы. Сборщик обычно формирует модули, поэтому в современном frontend-коде большая часть приложения уже выполняется в этом режиме.

Функция с непростым списком параметров - значениями по умолчанию, rest-параметром или деструктуризацией - не может содержать собственную директиву `"use strict"` в теле: это ранняя `SyntaxError`. Такая функция должна находиться в уже строгом модуле или скрипте либо быть переписана.

```js
// SyntaxError
function invalid(value = 1) {
  "use strict";
}
```

#### `eval` и `Function`

Прямой вызов `eval` в строгом контексте выполняет код по правилам strict mode, а созданные внутри привязки не проникают в окружающую область как это могло происходить в старом коде.

`new Function(code)` создаёт функцию в глобальной области и не наследует strict mode от места создания. Если такой API вообще оправдан, директива должна находиться в переданном теле функции.

Динамическое выполнение строк с кодом усложняет применение CSP, оптимизацию и безопасность, поэтому в обычном приложении его избегают независимо от strict mode.

#### Что strict mode не делает

- не проверяет TypeScript-типы во время выполнения;
- не замораживает объекты и массивы;
- не предотвращает XSS;
- не изолирует код от DOM, сети и `globalThis`;
- не делает функции чистыми;
- не исправляет состояния гонки (race conditions).

Он только меняет набор языковых правил и ошибок. Безопасность и архитектурные гарантии требуют отдельных механизмов.

#### Где применяется во frontend

- ES modules автоматически выполняются по правилам strict mode.
- Методы класса не подставляют глобальный объект в потерянный `this`.
- Ошибка присваивания в замороженный объект или свойство с `writable: false` обнаруживается сразу.
- Опечатка в имени не создаёт случайное свойство `window`.
- Сборщик и минификатор могут учитывать отсутствие части устаревших неоднозначностей, но производительность не является основной причиной включать режим вручную.

#### Ключевые уточнения

- `"use strict"` должен находиться в начале скрипта или тела функции, внутри `directive prologue`.
- Модули и тела классов работают в strict mode без директивы.
- Режим относится к конкретному исходному коду, а не передаётся вызываемой функции динамически.
- Обычный вызов строгой функции получает `this === undefined`, что помогает обнаружить потерю объекта-получателя.
- Неудачные присваивания становятся явными ошибками, но strict mode не делает данные неизменяемыми.
- Функция с параметрами по умолчанию, rest-параметром или деструктуризацией не может включить собственную директиву strict mode в теле.
- Strict mode не является проверкой типов или изолированной средой безопасности.
