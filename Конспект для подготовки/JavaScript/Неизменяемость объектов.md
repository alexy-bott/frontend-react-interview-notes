#### Быстрый ответ

Неизменяемость (`immutability`) означает, что существующее значение не изменяют, а следующее состояние представляют новым значением. Для объектов это прежде всего способ проектирования обновлений: создаются новые объекты по изменившемуся пути, а неизменившиеся части переиспользуются через структурное разделение (`structural sharing`).

`Object.preventExtensions`, `Object.seal` и `Object.freeze` решают другую задачу - вводят ограничения для конкретного объекта во время выполнения. `preventExtensions` запрещает новые свойства, `seal` также запрещает удаление и изменение конфигурации свойств, а `freeze` дополнительно устанавливает `writable: false` для собственных свойств данных.

Эти методы поверхностны: вложенные объекты сохраняют собственные правила изменяемости. TypeScript `readonly` и `Readonly<T>` действуют только при проверке типов и также не дают автоматической глубокой защиты во время выполнения.

#### Ключевая схема

| Метод | Добавлять свойства | Удалять свойства | Менять значения |
| --- | --- | --- | --- |
| обычный объект | можно | можно | можно |
| `preventExtensions` | нельзя | можно | можно |
| `seal` | нельзя | нельзя | можно, если `writable: true` |
| `freeze` | нельзя | нельзя | нельзя для свойств данных |

#### Базовая модель

Неизменяемое обновление и замороженный объект не являются синонимами. Можно никогда не вызывать `Object.freeze`, но дисциплинированно создавать новое состояние. И наоборот, замороженный объект может содержать изменяемый вложенный объект или getter, возвращающий меняющееся внешнее значение.

Главная практическая польза неизменяемых обновлений - предсказуемая идентичность. Если ветвь не изменилась, сохраняется прежняя ссылка; если изменилась, появляется новая. Это позволяет React, Redux и мемоизации быстро определять затронутые части по ссылочному сравнению без глубокого обхода всего графа.

Заморозка во время выполнения полезна как защита от случайной записи, особенно для конфигурации, публичного API, тестов и development-проверок. Она не создаёт новое значение и сама по себе не уведомляет наблюдателей об уже произошедшем изменении.

#### Развернутый ответ

##### Уровни ограничений во время выполнения

Дескриптор свойства описывает поведение собственного свойства. Дескриптор данных содержит `value` и `writable`, дескриптор доступа - `get` и `set`; оба вида также имеют `enumerable` и `configurable`.

- `Object.preventExtensions` запрещает добавлять собственные свойства и менять `[[Prototype]]`, но разрешает удалять и обновлять существующие свойства согласно их дескрипторам.
- `Object.seal` запрещает расширение и устанавливает `configurable: false` для всех собственных свойств. Свойство данных с `writable: true` всё ещё можно менять.
- `Object.freeze` дополнительно устанавливает `writable: false` для собственных свойств данных. Свойство доступа не превращается в свойство данных и может продолжать выполнять getter или setter.

Проверить состояние можно через `Object.isExtensible`, `Object.isSealed` и `Object.isFrozen`. Все три операции возвращают тот же объект, а не копию.

##### Поверхностность `freeze`

`freeze` меняет дескрипторы только самого объекта. Если значение свойства указывает на другой объект, этот вложенный объект остаётся отдельной сущностью со своими дескрипторами.

##### Свойства доступа

`freeze` устанавливает `configurable: false` для свойства доступа, но не удаляет getter или setter. Getter может возвращать разные значения, если читает внешнее изменяемое состояние, а setter может изменять другую сущность. Поэтому замороженный объект не гарантирует неизменность всех наблюдаемых результатов.

##### Глубокая заморозка

Глубокая заморозка рекурсивно замораживает достижимые объекты. Реализация должна учитывать циклы, символьные и неперечисляемые ключи, функции, getters и специальные платформенные объекты. Это обход всего графа, поэтому его стоимость и допустимые типы данных определяют заранее.

Ниже пример только для графа обычных данных. `WeakSet` предотвращает бесконечный обход циклов, а `Reflect.ownKeys` включает символьные и неперечисляемые ключи. Чтение свойства доступа всё ещё может выполнить пользовательский код, поэтому функцию нельзя считать универсальной для произвольных объектов.

```js
function deepFreeze(value, seen = new WeakSet()) {
  if (
    value === null ||
    (typeof value !== "object" && typeof value !== "function") ||
    seen.has(value)
  ) {
    return value;
  }

  seen.add(value);

  for (const key of Reflect.ownKeys(value)) {
    deepFreeze(value[key], seen);
  }

  return Object.freeze(value);
}
```

##### TypeScript `readonly`

`readonly` существует только во время проверки типов. После сборки это обычный JavaScript-объект. `Readonly<T>` делает readonly лишь свойства верхнего уровня, если не используется отдельный рекурсивный тип. Даже глубокий TypeScript-тип не мешает другому JavaScript-коду изменить объект во время выполнения.

#### Пример

```js
"use strict";

const config = Object.freeze({
  apiUrl: "/api",
  nested: {
    retry: 3,
  },
});

config.apiUrl = "/new-api"; // TypeError

config.nested.retry = 5; // ok, nested object не заморожен
```

Неизменяемое обновление со структурным разделением:

```js
const state = {
  user: { name: "Ann" },
  settings: { theme: "dark" },
};

const nextState = {
  ...state,
  user: { ...state.user, name: "Kate" },
};

console.log(nextState !== state); // true
console.log(nextState.user !== state.user); // true
console.log(nextState.settings === state.settings); // true
```

#### Где применяется во frontend

| Задача | Подход | Причина |
| --- | --- | --- |
| Обновление состояния React/Redux | новый путь + структурное разделение | идентичность ссылок показывает затронутые ветви |
| Защита статической конфигурации | `Object.freeze` | случайная запись во время выполнения становится заметнее |
| Запрет новых полей при сохранении изменяемых значений | `Object.seal` | набор свойств фиксируется, значения с `writable: true` остаются изменяемыми |
| Контракт API на этапе разработки | `readonly`/`Readonly<T>` | ошибка видна при проверке типов без обхода объекта во время выполнения |

#### Ключевые уточнения

- Неизменяемость является моделью обновлений, а `Object.freeze` - поверхностным ограничением одного объекта во время выполнения.
- `preventExtensions`, `seal` и `freeze` последовательно усиливают ограничения, но не копируют объект.
- Замороженный объект может содержать изменяемые вложенные объекты и свойства доступа с внешним состоянием.
- Структурное разделение сохраняет ссылки неизменившихся ветвей и создаёт новые только по изменившемуся пути.
- TypeScript `readonly` не существует во время выполнения и по умолчанию не является глубоким.
