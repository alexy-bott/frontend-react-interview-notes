#### Ответ на 60 секунд

Реактивность Vue - это система dependency tracking: когда код читает реактивное значение, Vue запоминает зависимость, а когда значение меняется, запускает связанные эффекты. Эффектом может быть render компонента, `computed`, `watch` или `watchEffect`. Во Vue 3 объекты становятся реактивными через `Proxy`, а `ref` работает через объект с `.value`, где getter делает tracking, а setter делает trigger.

Основные примитивы такие: `ref` чаще используют для примитивов и одиночных значений, `reactive` - для объектов, `computed` - для производных значений с ленивым кешем, `watch` - для реакции на конкретный источник, `watchEffect` - для автоматического сбора зависимостей внутри callback. Обновления DOM батчатся и применяются не синхронно сразу после каждой записи, поэтому если нужен уже обновлённый DOM, используют `nextTick` или `flush: "post"` у watcher.

Важные ловушки: в JavaScript коде у `ref` нужен `.value`, в template ref обычно разворачивается автоматически; деструктурирование `reactive`-объекта может потерять реактивность, поэтому используют `toRef`/`toRefs`; `watch` по умолчанию не обязан глубоко отслеживать вложенные изменения, для этого нужны getter, `deep` или более точный источник. В Vue 2 реактивность строилась на `Object.defineProperty`, а во Vue 3 - на `Proxy`, поэтому Vue 3 точнее отслеживает добавление/удаление свойств, массивы и коллекции.

#### Ключевая схема

```text
read reactive value -> track dependency
write reactive value -> trigger effects
effects scheduled -> component re-renders -> DOM patched
```

| Примитив | Для чего |
| --- | --- |
| `ref` | реактивная ссылка на значение |
| `reactive` | proxy-объект для объектов и массивов |
| `computed` | кешируемое производное значение |
| `watch` | реакция на конкретный источник |
| `watchEffect` | реакция с автоматическим сбором зависимостей |
| `nextTick` | дождаться применения DOM-обновлений |

#### Развернутый ответ

**`ref` и `reactive`**

`ref` возвращает объект с `.value`. Это нужно, чтобы Vue мог перехватывать чтение и запись даже для примитивов.

```js
import { ref } from "vue";

const count = ref(0);

count.value += 1;
```

`reactive` возвращает proxy объекта.

```js
import { reactive } from "vue";

const state = reactive({
  count: 0,
  items: [],
});

state.count += 1;
```

**`computed`**

`computed` используют для значения, которое вычисляется из реактивных источников. Оно кешируется и пересчитывается только при изменении зависимостей.

```js
const doubled = computed(() => count.value * 2);
```

Если значение можно получить из состояния без побочного эффекта, чаще нужен `computed`, а не `watch`.

**`watch` и `watchEffect`**

`watch` хорош, когда источник реакции известен явно.

```js
watch(
  () => state.count,
  (next, prev) => {
    console.log(prev, next);
  },
);
```

`watchEffect` сам собирает всё, что было прочитано внутри callback. Это удобно, но может быть менее явно в большом коде.

**DOM update timing**

Vue батчит изменения, чтобы несколько синхронных мутаций не вызывали несколько DOM-патчей подряд.

```js
state.count += 1;
state.count += 1;

await nextTick();
// DOM уже отражает оба изменения
```

**Потеря реактивности при деструктурировании**

```js
const state = reactive({ count: 0 });
const { count } = state;
```

`count` здесь обычное значение, а не реактивная ссылка. Если нужно достать поле и сохранить реактивность, используют `toRef` или `toRefs`.

#### Пример

```vue
<script setup>
import { computed, nextTick, reactive, watch, watchEffect } from "vue";

const state = reactive({
  count: 0,
  items: [1, 2],
});

const doubled = computed(() => state.count * 2);

watchEffect(() => {
  console.log("items:", state.items.length);
});

watch(
  () => state.count,
  (next, prev) => {
    console.log("count:", prev, next);
  },
  { flush: "post" },
);

async function add() {
  state.count += 1;
  state.items.push(state.count);
  await nextTick();
}
</script>

<template>
  <button @click="add">
    {{ state.count }} / {{ doubled }}
  </button>
</template>
```

#### Частые ошибки

- Забывать `.value` у `ref` в JavaScript-коде.
- Деструктурировать `reactive` без `toRef` или `toRefs`.
- Использовать `watch`, когда достаточно `computed`.
- Делать слишком широкий `watchEffect` и случайно подписываться на лишние зависимости.
- Читать DOM сразу после изменения состояния без `nextTick`.
- Смешивать raw object и reactive proxy в сравнениях по ссылке.
