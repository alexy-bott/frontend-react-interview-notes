#### Ответ на 60 секунд

Специфичность - это вес CSS-селектора, который помогает браузеру решить, какое правило применить, если несколько правил конфликтуют. Условно вес считают по группам: inline styles, id, classes/attributes/pseudo-classes, elements/pseudo-elements. Если специфичность одинаковая, побеждает правило, которое объявлено позже.

Cascade зависит не только от специфичности. Также влияют origin, `!important`, cascade layers, порядок подключения и inheritance. На практике селекторы держат простыми, избегают `!important`, не злоупотребляют id и используют понятную архитектуру CSS.

#### Ключевая схема

| Часть селектора | Пример | Вес |
| --- | --- | --- |
| Inline style | `style=""` | самый высокий обычный вес |
| ID | `#app` | высокий |
| Class/attribute/pseudo-class | `.btn`, `[type]`, `:hover` | средний |
| Element/pseudo-element | `button`, `::before` | низкий |

#### Развернутый ответ

Специфичность помогает выбрать победителя среди правил одного уровня каскада. Сначала учитываются origin, importance и cascade layer, затем специфичность, затем порядок объявления. Поэтому более специфичный селектор не всегда побеждает, если правило находится в менее приоритетном слое или origin.

`!important` поднимает объявление в отдельный уровень cascade. Если `!important`-объявлений несколько, между ними снова сравниваются origin, layers, specificity и порядок. Постоянное использование `!important` обычно означает, что архитектура селекторов или слоёв стала слишком хрупкой.

`:is()`, `:not()` и `:has()` берут специфичность от наиболее специфичного селектора внутри аргументов. Они удобны для группировки условий, но могут неожиданно поднять вес правила, если внутри оказался id или сложный селектор.

`:where()` особенный: он всегда имеет нулевую специфичность. Это удобно для base/reset правил, которые должны легко переопределяться компонентами или utility-классами.

> [!faq]+ Уточнения
> - Specificity сравнивается не первой: перед ней идут origin, importance и layers.
> - При равной специфичности побеждает более позднее объявление.
> - `!important` усложняет переопределение и должен быть исключением.
> - `:is()`, `:not()`, `:has()` берут вес от аргументов.
> - `:where()` даёт нулевую специфичность.

#### Пример

```css
button {
  color: black;
}

.button {
  color: blue;
}

#submit {
  color: red;
}
```

Если элемент подходит под все три правила, победит `#submit`, потому что id специфичнее класса и тега.

#### Частые ошибки

- Лечить конфликт стилей через всё более длинные селекторы.
- Использовать `!important` как обычный инструмент.
- Не учитывать порядок подключения CSS-файлов.
- Забывать про cascade layers.
- Делать селекторы настолько специфичными, что компонент трудно переопределить.
