#### Ответ на 60 секунд

`position` управляет тем, как элемент участвует в потоке документа и относительно чего применяются смещения `top`, `right`, `bottom`, `left` или `inset`. По умолчанию элементы имеют `position: static`, находятся в обычном потоке, и смещения на них не работают.

`relative` оставляет элемент в потоке, но позволяет визуально сместить его и создать containing block для absolute-потомков. `absolute` убирает элемент из потока и позиционирует относительно ближайшего позиционированного предка. `fixed` обычно привязан к viewport, а `sticky` ведет себя как relative до порога, после чего “прилипает” внутри scroll-контейнера.

#### Ключевая схема

| Значение | Поведение |
| --- | --- |
| `static` | обычный поток, смещения не работают |
| `relative` | в потоке, можно смещать визуально |
| `absolute` | вне потока, относительно containing block |
| `fixed` | вне потока, обычно относительно viewport |
| `sticky` | relative до порога, затем sticky внутри контейнера |

#### Развернутый ответ

`position` меняет участие элемента в normal flow и правила смещения. `static` - обычное поведение. `relative` оставляет место в потоке, но визуально смещает элемент и может стать containing block для absolute-потомков. `absolute` убирает элемент из потока. `fixed` обычно привязан к viewport. `sticky` совмещает relative и fixed внутри scroll-контейнера.

`absolute` позиционируется относительно ближайшего предка, у которого `position` не `static`. Если такого предка нет, используется initial containing block. Поэтому для badge/dropdown внутри карточки родителю часто задают `position: relative`.

`fixed` не всегда привязан к viewport. Некоторые свойства у предков, например `transform`, `filter`, `perspective`, `contain`, могут создать containing block, и fixed-элемент начнёт позиционироваться относительно такого предка. Это частая причина странного поведения overlays.

`sticky` работает только при наличии порога (`top`, `left` и т.д.) и достаточного пространства для прилипания. Ему может мешать scroll-контейнер, `overflow` у родителей, неправильная ось или отсутствие места между начальной и конечной позицией.

Позиционирование не заменяет layout-модель. Если задачу можно решить Grid/Flexbox/normal flow, такой вариант обычно устойчивее. `position` применяют для badges, overlays, sticky headers, tooltips и точечных смещений.

> [!faq]+ Уточнения
> - `relative` остаётся в потоке, `absolute` и `fixed` выпадают из него.
> - `absolute` ищет ближайший positioned ancestor.
> - `fixed` может зависеть от transformed/contained ancestor.
> - `sticky` требует порога и правильного scroll-контейнера.
> - `z-index` связан со stacking context, а не работает глобально.

#### Пример

```css
.card {
  position: relative;
}

.badge {
  position: absolute;
  top: 8px;
  right: 8px;
}

.header {
  position: sticky;
  top: 0;
}
```

#### Частые ошибки

- Ставить `absolute`, не задав позиционированного родителя.
- Думать, что `relative` освобождает место после смещения.
- Ожидать, что `z-index` работает независимо от stacking context.
- Не учитывать `overflow` у родителей для sticky и dropdown.
- Использовать позиционирование вместо нормальной layout-модели.
