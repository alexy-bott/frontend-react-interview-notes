#### Быстрый ответ

`position` управляет тем, как элемент участвует в потоке документа и относительно чего применяются смещения `top`, `right`, `bottom`, `left` или `inset`. По умолчанию элементы имеют `position: static`, находятся в обычном потоке, и смещения на них не работают.

`relative` оставляет исходное место элемента в потоке, но позволяет сместить его и обычно создаёт containing block для positioned-потомков. `absolute` и `fixed` выпадают из обычного потока. `sticky` остаётся в потоке, но ограничивает своё положение заданным порогом внутри ближайшей области прокрутки.

#### Ключевая схема

| Значение | Поведение |
| --- | --- |
| `static` | обычный поток, смещения не работают |
| `relative` | в потоке, можно смещать визуально |
| `absolute` | вне потока, относительно containing block |
| `fixed` | вне потока, обычно относительно viewport |
| `sticky` | relative до порога, затем sticky внутри контейнера |

#### Базовая модель

Позиционирование состоит из двух вопросов:

1. Сохраняет ли элемент место в normal flow.
2. От какого containing block вычисляются его inset-смещения и процентные размеры.

`relative` и `sticky` сохраняют место в потоке. `absolute` и `fixed` не участвуют в расчёте места для соседей. Затем браузер определяет containing block: это не всегда ближайший родитель и не всегда viewport.

#### Развернутый ответ

`position` меняет участие элемента в normal flow и правила смещения. `static` - обычное поведение. `relative` оставляет место в потоке, но визуально смещает элемент и может стать containing block для absolute-потомков. `absolute` убирает элемент из потока. `fixed` обычно привязан к viewport. `sticky` совмещает relative и fixed внутри scroll-контейнера.

Containing block для `absolute` обычно создаёт ближайший предок с `position`, отличным от `static`. Но его также могут создать `transform`, `filter`, `perspective`, определённые значения `contain` и другие свойства. Если подходящего предка нет, используется initial containing block. Для badge внутри карточки родителю часто достаточно `position: relative`.

`fixed` обычно позиционируется относительно viewport, но transformed или contained ancestor способен создать для него другой containing block. Тогда элемент прокручивается и ограничивается вместе с этим предком, что часто ломает ожидаемое поведение overlay.

`sticky` требует ненулевого ограничения хотя бы по одной стороне нужной оси, например `top: 0`. Он привязывается к ближайшему предку со scrolling mechanism, который может появиться из-за `overflow: hidden`, `auto`, `scroll` или `overlay`, даже если фактически прокручивается другой контейнер. Прилипание также ограничено границами containing block.

Позиционирование не заменяет основную layout-модель. Flexbox, Grid и normal flow распределяют место между элементами; `absolute` полезен, когда элемент действительно должен накладываться поверх layout и не резервировать в нём место.

#### Пример

```css
.card {
  position: relative;
}

.badge {
  position: absolute;
  top: 8px;
  right: 8px;
}

.header {
  position: sticky;
  top: 0;
  z-index: 1;
}
```

Badge вычисляет inset от padding box карточки. Header остаётся участником потока, а после достижения верхнего порога удерживается внутри своего scroll-контейнера; `z-index` нужен только для ожидаемого порядка наложения.

#### Диагностика

Для сломанного `absolute` или `fixed` сначала находят фактический containing block в DevTools и проверяют `position`, `transform`, `filter` и `contain` у предков. Для `sticky` проверяют заданный inset, ось прокрутки, `overflow` всех предков, доступное пространство и границы контейнера. Обрезание overlay диагностируют отдельно через clipping/`overflow`, а порядок наложения - через stacking contexts.

#### Ключевые уточнения

- Смещение `relative` не меняет зарезервированное для элемента место.
- Containing block для `absolute` создаётся не только positioned ancestor.
- `fixed` может зависеть от transformed или contained ancestor вместо viewport.
- `sticky` остаётся в потоке и ограничивается своим scroll-контейнером и containing block.
- `z-index` управляет наложением внутри stacking contexts, но не отменяет clipping через `overflow`.
