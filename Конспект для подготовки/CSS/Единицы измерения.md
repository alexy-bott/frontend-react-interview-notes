#### Ответ на 60 секунд

CSS-единицы задают размеры относительно разных контекстов. `px` удобен для точных границ и иконок, `rem` зависит от root font-size и хорошо подходит для типографики и spacing, `em` зависит от font-size текущего элемента и удобен для локальных компонентов, `%` считается от контекста свойства, а viewport units (`vw`, `vh`, `dvh`, `svh`, `lvh`) завязаны на размер окна.

Выбор единицы зависит от задачи: border в `1px`, текст и отступы часто в `rem`, компонентные размеры иногда в `em`, ширины контейнеров в `%`, адаптивные ограничения через `min()`, `max()`, `clamp()`. Для мобильных экранов старый `100vh` может давать проблемы из-за адресной строки браузера, поэтому появились `dvh`, `svh`, `lvh`.

#### Ключевая схема

| Единица | От чего зависит | Типичный сценарий |
| --- | --- | --- |
| `px` | CSS pixel | borders, icons, precise sizes |
| `rem` | root font-size | typography, spacing scale |
| `em` | font-size текущего элемента | локальные размеры компонента |
| `%` | контекст свойства | fluid widths, relative sizes |
| `vw`, `vh` | viewport | full-screen sections |
| `dvh` | dynamic viewport height | mobile viewport с UI браузера |
| `ch` | ширина символа `0` | ограничение длины строки |
| `clamp()` | min/preferred/max | fluid typography/layout |

#### Развернутый ответ

`rem` считается от font-size корневого элемента, обычно `html`. Он удобен для типографики и spacing scale, потому что уважает пользовательские настройки размера текста. `em` считается от font-size текущего элемента, поэтому может накапливаться во вложенности и удобен для локальных размеров компонента.

`px` нормально использовать для тонких линий, borders, shadow offsets, иконок и случаев, где нужна визуальная точность. Проблема не в `px` как единице, а в полностью фиксированной верстке без адаптивных ограничений.

`%` зависит от свойства: width, padding, transform и line-height имеют разные контексты вычисления. Поэтому процент не всегда означает “процент от родительской ширины” в одном и том же смысле.

Viewport units (`vw`, `vh`) завязаны на viewport. На мобильных браузерах адресная строка и системный UI могут менять видимую высоту, поэтому появились `dvh`, `svh`, `lvh`: dynamic, small и large viewport height.

`clamp(min, preferred, max)` задаёт плавно изменяемое значение с нижней и верхней границей. Это удобно для responsive typography и fluid spacing без большого числа breakpoint-скачков.

> [!faq]+ Уточнения
> - `rem` зависит от root font-size, `em` - от текущего элемента.
> - `px` подходит для точных визуальных деталей.
> - `%` зависит от конкретного CSS-свойства.
> - `100dvh` отражает динамическую высоту мобильного viewport.
> - Unitless `line-height` масштабируется вместе с font-size.

#### Пример

```css
:root {
  font-size: 16px;
}

.article {
  max-width: 70ch;
  padding: clamp(1rem, 2vw, 2rem);
}

.article__title {
  font-size: clamp(1.75rem, 4vw, 3rem);
  line-height: 1.1;
}

.screen {
  min-height: 100dvh;
}
```

#### Частые ошибки

- Делать весь layout в фиксированных `px`.
- Использовать `100vh` для мобильного fullscreen без проверки поведения браузерного UI.
- Задавать `line-height` в `px` и ломать масштабирование.
- Не понимать, от чего считается `%` в конкретном свойстве.
- Использовать `em` во вложенных компонентах и случайно получать каскадное увеличение размеров.
