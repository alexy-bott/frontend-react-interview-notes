#### Быстрый ответ

Flexbox - CSS-модель раскладки, которая распределяет элементы вдоль одной главной оси и выравнивает их по поперечной. Она подходит для toolbar, меню, группы действий, центрирования и компонентов, где важны порядок элементов в линии и распределение свободного места.

`flex-direction` задаёт главную ось, `justify-content` распределяет оставшееся место вдоль неё, а `align-items` выравнивает элементы по поперечной оси. Размер формируется из `flex-basis`, `flex-grow`, `flex-shrink` и min/max-ограничений. Если строки и колонки должны образовать общую двумерную сетку, обычно лучше подходит Grid.

#### Ключевая схема

| Задача | Свойство |
| --- | --- |
| Включить flex-контекст | `display: flex` |
| Направление главной оси | `flex-direction` |
| Выравнивание по главной оси | `justify-content` |
| Выравнивание по поперечной оси | `align-items` |
| Перенос на новую строку | `flex-wrap` |
| Базовый размер элемента | `flex-basis` |
| Рост элемента | `flex-grow` |
| Сжатие элемента | `flex-shrink` |
| Короткая запись | `flex: grow shrink basis` |

#### Базовая модель

Для каждой flex line браузер сначала определяет базовые размеры items. Затем сравнивает их сумму вместе с `gap` с размером контейнера:

```text
осталось свободное место -> распределить по flex-grow
места не хватает         -> уменьшить по flex-shrink с учётом базовых размеров
```

После определения размеров `justify-content` распределяет оставшееся место. Если свободного места нет, например потому что один item растянулся через `flex-grow`, заметного эффекта от `justify-content` не будет.

#### Развернутый ответ

Flexbox строится вокруг главной и поперечной осей. `flex-direction` задаёт главную ось: при `row` она горизонтальная, при `column` вертикальная. `justify-content` работает вдоль главной оси, а `align-items` - вдоль поперечной. Поэтому после смены `flex-direction` визуальный смысл выравнивания меняется.

`flex-basis` задаёт исходную main size перед распределением пространства. При `auto` алгоритм учитывает main-size property (`width` для `row`, `height` для `column`) или размер содержимого. `flex-grow` задаёт пропорцию положительного свободного места, а `flex-shrink` участвует в распределении дефицита с учётом базового размера. Значения - коэффициенты, а не готовые проценты ширины.

В браузерах `flex: 1` раскрывается как `1 1 0%`: items начинают делить пространство от нулевой basis. `flex: auto` соответствует `1 1 auto` и сохраняет влияние исходного размера содержимого. Явная полная запись полезна, когда это различие важно.

По умолчанию flex item имеет автоматический минимальный размер по содержимому. Из-за него длинная строка или вложенный элемент может не сжаться, хотя `flex-shrink: 1`. Для item, которому разрешено стать уже содержимого, задают `min-inline-size: 0` и отдельно управляют переносом или обрезанием текста.

`flex-wrap` создаёт несколько независимых flex lines. Items в разных линиях не образуют общие колонки, поэтому для выровненной двумерной сетки Grid обычно предсказуемее. `align-content` распределяет свободное место между несколькими линиями, а `align-items` выравнивает items внутри линии.

Свойство `order` меняет визуальный порядок, но не порядок DOM, чтения screen reader и обычно не последовательность фокуса. Его нельзя использовать для исправления неверной семантической последовательности.

#### Пример

```css
.toolbar {
  display: flex;
  align-items: center;
  gap: 12px;
}

.toolbar__title {
  flex: 1 1 auto;
  min-inline-size: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

.toolbar__actions {
  display: flex;
  gap: 8px;
}
```

Заголовок получает свободное место, но может сжаться благодаря `min-inline-size: 0`. Группа кнопок остаётся после него по main axis. `align-items: center` выравнивает обе части по cross axis при `flex-direction: row`.

#### Ключевые уточнения

- Main axis определяется `flex-direction`; она не всегда горизонтальна.
- `justify-content` распределяет только оставшееся свободное место.
- `flex-grow` и `flex-shrink` - коэффициенты распределения, а не готовые размеры.
- Автоматический min-size может запретить ожидаемое сжатие; тогда проверяют `min-inline-size: 0` и overflow содержимого.
- Каждая перенесённая flex line рассчитывается отдельно; общие колонки даёт Grid.
- Визуальное переупорядочивание через `order` не меняет логический порядок документа.
