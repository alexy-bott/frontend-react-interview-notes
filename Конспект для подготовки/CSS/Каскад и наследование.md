#### Быстрый ответ

Каскад - это алгоритм, по которому браузер выбирает одно объявление CSS-свойства из всех подходящих объявлений. Сначала учитываются источник и важность стилей, затем порядок cascade layers, специфичность селектора, близость `@scope` и порядок объявления. Поэтому более специфичный селектор побеждает не всегда.

Наследование работает после каскада и решает другую задачу: если для наследуемого свойства у элемента не выбрано собственное значение, оно берётся у родителя. Например, `color` обычно наследуется, а `margin` - нет.

#### Ключевая схема

```text
Подходящие объявления
-> источник и важность
-> cascade layer
-> специфичность
-> близость @scope
-> порядок объявления
-> каскадное значение
-> наследование или initial value, если объявления нет
-> вычисленное значение
```

| Механизм | Что решает |
| --- | --- |
| Релевантность | подходит ли селектор и выполняется ли условие `@media` |
| Источник и важность | откуда пришёл стиль и есть ли `!important` |
| Layer | приоритет слоя `@layer` внутри источника |
| Специфичность | сравнительный вес селектора |
| Scope proximity | насколько близка граница подходящего `@scope` |
| Порядок | более позднее объявление побеждает при равенстве предыдущих критериев |
| Наследование | значение может прийти от родителя, если свойство наследуется |

#### Базовая модель

Для каждого свойства каскад выполняется отдельно. `color` может прийти из одного правила, `padding` - из другого, а `font-family` - по наследованию от родителя. Браузер не выбирает одно CSS-правило целиком.

Чтобы понять, почему конкретное значение победило, нужно отфильтровать неподходящие объявления и сравнивать оставшиеся строго по порядку каскада. Специфичность имеет смысл только после того, как совпали источник, важность и layer.

#### Развернутый ответ

Каскад и наследование решают разные задачи. Каскад выбирает объявление среди правил, применимых к элементу. Если подходящего объявления нет, наследуемое свойство получает значение родителя, а ненаследуемое - своё начальное значение из спецификации.

Текстовые свойства вроде `color` и `font-family` часто наследуются, потому что обычно должны распространяться на потомков. Layout-свойства вроде `margin`, `padding`, `border` не наследуются, иначе вложенная разметка быстро становилась бы непредсказуемой.

Глобальные CSS-значения позволяют явно управлять этим поведением:

| Значение | Результат |
| --- | --- |
| `inherit` | взять вычисленное значение у родителя даже для ненаследуемого свойства |
| `initial` | использовать начальное значение свойства из спецификации |
| `unset` | сработать как `inherit` для наследуемого свойства и как `initial` для остальных |
| `revert` | откатить значение к менее приоритетному источнику каскада |
| `revert-layer` | откатить значение к предыдущему cascade layer внутри текущего источника |

`!important` меняет важность объявления, но не увеличивает специфичность селектора. Среди нескольких важных объявлений каскад снова применяет свои критерии. Важные стили сложнее переопределять, поэтому `!important` оставляют для обоснованных гарантий, а не используют как обычное исправление конфликтов.

`@layer` позволяет заранее задать приоритет групп авторских стилей, например reset, base, components и utilities. Для обычных объявлений более поздний layer приоритетнее более раннего, а обычные стили вне layer приоритетнее layered styles. У важных объявлений порядок layers обращается. Это защищает низкоуровневые стили от случайного усиления селекторов, но требует осознанно зафиксировать порядок слоёв.

#### Пример

```css
@layer reset, base, components, utilities;

@layer base {
  button {
    font: inherit;
    color: inherit;
  }
}

@layer components {
  .button {
    color: white;
    background: royalblue;
  }
}

@layer utilities {
  .text-danger {
    color: crimson;
  }
}
```

Если у кнопки есть классы `.button` и `.text-danger`, обычное объявление из `utilities` победит объявление из `components`, хотя специфичность селекторов одинакова. Решение принято на уровне layers до сравнения специфичности.

#### Диагностика

Если стиль виден в DevTools, но зачёркнут, нужно проверить победившее объявление и идти по порядку каскада: `!important`, origin, layer, специфичность, `@scope`, затем порядок. Если свойства нет среди подходящих объявлений, следует проверить наследование, начальное значение и сокращённые свойства вроде `background` или `margin`, которые могли сбросить связанные значения.

#### Ключевые уточнения

- Каскад выбирает значение каждого свойства отдельно; он не выбирает правило целиком.
- Наследование не конкурирует со своим объявлением элемента: собственное каскадное значение имеет приоритет.
- `!important` меняет уровень важности, а не специфичность.
- Порядок файлов решает конфликт только при равенстве более ранних критериев.
- `revert` откатывает источник каскада, а `revert-layer` - текущий layer.
- `@layer` управляет приоритетом групп правил, но не заменяет понятную структуру селекторов.
