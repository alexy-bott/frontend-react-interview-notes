#### Ответ на 60 секунд

Каскад - это алгоритм, по которому браузер выбирает итоговое значение CSS-свойства, если на элемент подходит несколько правил. Он учитывает релевантность правила, источник стилей, `!important`, cascade layers, специфичность, близость `@scope` и порядок объявления. Наследование - отдельный механизм: некоторые свойства, например `color` и `font-family`, могут переходить от родителя к потомкам, если у потомка нет собственного значения.

Каскад не сводится только к специфичности. Специфичность решает конфликт не всегда: сначала важны origin/layer/importance, потом specificity, и только при равенстве - порядок. Поэтому CSS может “не применяться” не из-за одной причины, а из-за комбинации источника, слоя, селектора и порядка.

#### Ключевая схема

```text
matching rules
-> origin and importance
-> cascade layer
-> specificity
-> scope proximity
-> order of appearance
-> computed value
```

| Механизм | Что решает |
| --- | --- |
| Relevance | подходит ли правило элементу и media query |
| Origin | browser/user/author styles |
| Importance | обычное объявление или `!important` |
| Layer | порядок `@layer` внутри origin |
| Specificity | вес селектора |
| Order | последнее правило побеждает при равенстве |
| Inheritance | значение может прийти от родителя |

#### Развернутый ответ

Каскад и наследование решают разные задачи. Каскад выбирает победившее объявление среди правил, которые применимы к элементу. Наследование берёт значение у родителя, когда у элемента нет собственного значения для наследуемого свойства.

Текстовые свойства вроде `color` и `font-family` часто наследуются, потому что обычно должны распространяться на потомков. Layout-свойства вроде `margin`, `padding`, `border` не наследуются, иначе вложенная разметка быстро становилась бы непредсказуемой.

Ключевые reset-значения работают по-разному. `inherit` принудительно берёт значение у родителя. `initial` сбрасывает к начальному значению свойства по спецификации. `unset` ведёт себя как `inherit` для наследуемых свойств и как `initial` для ненаследуемых. `revert` откатывает значение к результату предыдущего origin/layer.

`!important` поднимает объявление в отдельный уровень cascade и усложняет переопределение. Иногда он уместен в utility-классах или override слоях, но в компонентном CSS часто показывает, что порядок слоёв или селекторы спроектированы неудачно.

`@layer` позволяет явно управлять приоритетом групп стилей: reset, base, components, utilities. Это снижает зависимость от случайной специфичности и порядка импортов.

> [!faq]+ Уточнения
> - Cascade выбирает объявление, inheritance берёт значение у родителя.
> - `color` наследуется, `margin` нет.
> - `inherit`, `initial`, `unset`, `revert` сбрасывают значение по разным правилам.
> - Layers могут победить specificity внутри своего уровня каскада.
> - Reset/base стили удобно держать в низкоприоритетном layer.

#### Пример

```css
@layer reset, base, components, utilities;

@layer base {
  button {
    font: inherit;
    color: inherit;
  }
}

@layer components {
  .button {
    color: white;
    background: royalblue;
  }
}

@layer utilities {
  .text-danger {
    color: crimson;
  }
}
```

Здесь порядок слоёв делает правила предсказуемее: utilities могут переопределять components без разгона специфичности.

#### Частые ошибки

- Объяснять каскад только через специфичность.
- Добавлять `!important` вместо исправления порядка слоёв или селекторов.
- Не понимать, почему inherited `color` влияет на SVG, иконки или кнопки.
- Считать, что порядок файлов всегда важнее специфичности.
- Делать селекторы слишком длинными и затем бороться с ними ещё более длинными селекторами.
