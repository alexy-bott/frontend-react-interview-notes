#### Быстрый ответ

Семантика сообщает браузеру назначение содержимого: где кнопка, ссылка, заголовок, навигация или поле формы. На основе HTML и ARIA браузер строит дерево доступности (accessibility tree) — представление интерфейса для вспомогательных технологий, например скринридера. В этом дереве интерактивный элемент имеет роль, доступное имя, состояния и при необходимости описание.

Сначала используют нативный HTML: `<button>` для действия, `<a href>` для перехода, `<label>` для поля. Нативный элемент уже предоставляет семантику и ожидаемое keyboard-поведение. ARIA дополняет отсутствующее имя, состояние или связь, но не добавляет фокус, обработку клавиш и бизнес-логику.

Accessible name, или доступное имя, отвечает на вопрос «как называется элемент». У текстовой кнопки имя обычно берётся из содержимого, у поля — из связанного `<label>`, у иконки-кнопки его можно задать через `aria-label`. `aria-describedby` добавляет описание и не заменяет имя.

#### Базовая модель

```text
HTML + ARIA + текущее состояние
              |
              v
       дерево доступности
              |
              v
 роль + доступное имя + описание + состояние
              |
              v
       assistive technology
```

| Часть | На какой вопрос отвечает | Пример |
| --- | --- | --- |
| Роль (role) | Что это? | button, link, checkbox, heading |
| Доступное имя (accessible name) | Как это называется? | «Сохранить», «Email», «Закрыть» |
| Описание (description) | Что ещё важно знать? | формат поля, последствие действия |
| Состояние (state) | В каком состоянии находится? | disabled, checked, expanded, invalid |

Скринридер (screen reader) — программа, которая озвучивает структуру и состояние интерфейса и позволяет управлять им с клавиатуры или другими командами. Он не читает страницу как обычный текст сверху вниз: пользователь перемещается по заголовкам, ориентирам, элементам управления и другим узлам дерева доступности.

#### Семантический HTML

Нативный элемент одновременно задаёт роль и поведение. `<button>` входит в последовательность фокуса, активируется клавишами `Enter` и `Space`, поддерживает `disabled` и передаёт состояние в accessibility tree. У `<div role="button">` появляется роль, но разработчику всё равно придётся реализовать фокус, обе клавиши активации, disabled-состояние и визуальный индикатор фокуса.

Семантика относится не только к интерактивным элементам:

- последовательные `h1`–`h6` формируют структуру документа;
- `nav`, `main`, `header` и `footer` создают ориентиры страницы (landmarks);
- `ul`/`ol` и `li` сообщают структуру списка;
- `table`, `th` и `caption` связывают табличные данные;
- `fieldset` и `legend` называют группу связанных полей.

Визуальный стиль не меняет смысл. Ссылка, оформленная как кнопка, остаётся ссылкой, если она переводит на другой адрес. Кнопка может выглядеть как текстовая ссылка, но остаётся кнопкой, если запускает действие на текущей странице.

#### Accessible name и description

Браузер вычисляет доступное имя по алгоритму Accessible Name and Description Computation. Источник зависит от элемента и может включать связанный `<label>`, текстовое содержимое, `alt`, `aria-labelledby` или `aria-label`.

Практический приоритет такой:

1. Использовать видимую подпись, связанную нативной HTML-семантикой.
2. Для составного компонента связать видимый текст через `aria-labelledby`.
3. Применить `aria-label`, когда подходящего видимого текста действительно нет, например у иконки-кнопки.

Это не полная таблица приоритетов алгоритма: явные ARIA-атрибуты могут заменить имя из содержимого, а правила различаются по ролям. Итог нужно проверять в accessibility tree браузерных DevTools.

`aria-describedby` ссылается на дополнительный текст. Например, label даёт полю имя «Пароль», а description объясняет «Не менее 12 символов». Несколько идентификаторов перечисляются через пробел.

```html
<label for="password">Пароль</label>
<input
  id="password"
  type="password"
  aria-describedby="password-hint password-error"
  aria-invalid="true"
>
<p id="password-hint">Не менее 12 символов.</p>
<p id="password-error">Добавьте ещё 4 символа.</p>
```

#### Когда нужна ARIA

ARIA полезна для состояний и связей, которых не выражает выбранный HTML:

| Потребность | Возможное средство |
| --- | --- |
| Назвать иконку-кнопку | `aria-label` |
| Связать dialog с видимым заголовком | `aria-labelledby` |
| Добавить полю подсказку или ошибку | `aria-describedby` |
| Передать раскрытое состояние | `aria-expanded` |
| Указать контролируемую область | `aria-controls` по необходимости |
| Сообщить состояние custom checkbox | `aria-checked` |
| Исключить декоративную иконку из accessibility tree | `aria-hidden="true"` |

ARIA не должна противоречить нативной семантике. Например, изменение роли `<button>` на несовместимую скрывает гарантии кнопки от вспомогательных технологий, хотя браузерное поведение элемента частично останется.

`aria-hidden="true"` скрывает элемент и всех его потомков из дерева доступности. Его нельзя ставить на фокусируемый элемент или контейнер с доступными элементами управления: клавиатурный фокус окажется на узле, который скринридер не видит.

#### Пример

У кнопки есть понятное имя, а SVG остаётся декоративным:

```html
<button type="button" aria-label="Закрыть">
  <svg aria-hidden="true" focusable="false" viewBox="0 0 16 16">
    <!-- декоративная иконка -->
  </svg>
</button>
```

Если рядом уже есть видимый текст, дополнительный `aria-label` не нужен:

```html
<button type="button">
  <svg aria-hidden="true" focusable="false"></svg>
  Сохранить
</button>
```

Во втором варианте доступное имя вычисляется из текста «Сохранить». Одинаковая видимая и доступная подпись также помогает пользователям голосового управления находить элемент по тексту на экране.

#### Проверка

1. Пройти страницу только клавиатурой и убедиться, что элементы управления доступны в логичном порядке.
2. Открыть дерево доступности в DevTools и проверить роль, имя, описание и состояние.
3. Убедиться, что заголовки, landmarks, списки и таблицы сохраняют структуру.
4. Запустить автоматическую проверку, например axe; затем вручную проверить клавиатуру и скринридер, потому что автоматический инструмент не понимает весь пользовательский сценарий.

#### Ключевые уточнения

- Нативный HTML даёт семантику и встроенное поведение; ARIA в основном передаёт дополнительные свойства дерева доступности.
- Доступное имя называет элемент управления, а описание добавляет контекст.
- Видимая подпись обычно является наиболее устойчивым источником имени.
- Роль без keyboard- и focus-поведения создаёт только внешнее обещание, которое компонент ещё должен выполнить.
- Итоговое имя проверяют по дереву доступности, поскольку несколько источников могут перекрывать друг друга.
- Декоративный элемент можно скрыть через `aria-hidden`, если он сам и его потомки не фокусируются.
