#### Быстрый ответ

HTML-форма - нативный механизм ввода и отправки данных. `<form>` задаёт endpoint и способ отправки, form controls получают имена через `name`, `<label>` даёт полю доступное имя, а submit-кнопка запускает валидацию и событие `submit`.

При отправке браузер формирует набор успешных controls (successful controls): учитывает их тип, имя, состояние и кнопку, которой отправили форму. JavaScript может перехватить `submit` и отправить `FormData` через API, но нативная семантика по-прежнему обеспечивает Enter-submit, autocomplete, клавиатуру и интеграцию со вспомогательными технологиями.

#### Ключевая схема

```text
form controls + submitter
-> constraint validation
-> submit event
-> entry list / FormData
-> native navigation или JavaScript request
-> server validation
```

| Сущность | Роль |
| --- | --- |
| `action` | URL назначения |
| `method` | HTTP-метод нативной формы: обычно `get` или `post` |
| `name` | имя поля в отправляемом наборе |
| `label` | видимое и доступное имя control |
| `type` | нативное поведение и начальная проверка |
| `enctype` | формат нативной отправки, важен для файлов |
| Submitter | кнопка, запустившая submit; может добавить своё имя и значение |

#### Базовая модель

В набор отправки входит не каждый DOM-элемент формы. Control без `name`, disabled control и unchecked checkbox обычно не создают пару `name=value`. У checkbox и radio передаётся `value`, а не логическое значение; если `value` не задан, браузер использует значение по умолчанию `on`.

Связь label/control создаётся через `for` и `id` либо вложенностью control в `<label>`. Клик по label переводит focus или активирует связанный control. Placeholder показывает краткую подсказку внутри поля, исчезает при вводе и не заменяет постоянное имя.

Браузерная constraint validation использует `required`, тип input, `min`, `max`, `minlength`, `maxlength`, `pattern` и другие ограничения. Успешная проверка позволяет submit; при ошибке браузер блокирует его и показывает нативную обратную связь, если validation не отключена.

#### Развернутый ответ

**Submit.** Кнопка внутри form по умолчанию имеет `type="submit"`. Для «показать пароль», «добавить поле» и других локальных действий задают `type="button"`. Нажатие Enter может отправить форму без click по конкретной кнопке, поэтому основную логику размещают в обработчике `submit`, а не только `click`.

**`requestSubmit()` и `submit()`.** `form.requestSubmit()` ведёт себя как пользовательская отправка: выбирает submitter, запускает constraint validation и событие `submit`. Старый `form.submit()` отправляет форму напрямую, не выполняя эти этапы. Для программного запуска пользовательского flow обычно нужен `requestSubmit()`.

**`FormData`.** Конструктор `new FormData(form)` собирает текущий набор controls. Несколько полей с одним `name` сохраняются как несколько entries, поэтому для них используют `getAll`. Файл представлен объектом `File`. Нельзя предполагать, что `get()` возвращает только строку: результат имеет тип `FormDataEntryValue | null`.

**Файлы.** Для нативной отправки файла методом POST используется `enctype="multipart/form-data"`. При передаче `FormData` через `fetch` браузер сам добавляет `Content-Type` с boundary; вручную задавать этот header без boundary не нужно.

**Валидация.** Клиентская проверка даёт быструю обратную связь, но сервер повторно валидирует поля, права и бизнес-правила. Ошибка сервера связывается с соответствующим control или общим summary и не должна стирать введённые значения.

**Группы и autocomplete.** Связанные radio/checkbox controls группируют через `<fieldset>` и `<legend>`. Корректные значения `autocomplete`, например `email` и `current-password`, помогают browser и password manager подставлять данные по смыслу поля.

#### Пример

```html
<form id="login-form" action="/login" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email" required>

  <label for="password">Пароль</label>
  <input
    id="password"
    name="password"
    type="password"
    autocomplete="current-password"
    required
  >

  <button type="button" id="show-password">Показать пароль</button>
  <button type="submit">Войти</button>
</form>
```

```js
const form = document.querySelector("#login-form");

if (!(form instanceof HTMLFormElement)) {
  throw new Error("Login form was not found");
}

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  const data = new FormData(event.currentTarget);

  await fetch(event.currentTarget.action, {
    method: event.currentTarget.method,
    body: data,
  });
});
```

Обработчик `submit` работает и для клика, и для клавиатурной отправки. Пример показывает механизм, но production-форма дополнительно отображает pending state, разбирает HTTP-ответ и сохраняет значения при ошибке.

#### Ключевые уточнения

- `name` определяет участие и ключ control в отправке; `id` нужен для DOM-ссылок и связи с `label`, но сам не заменяет `name`.
- Disabled и unchecked controls могут отсутствовать в `FormData`, поэтому отсутствие entry отличается от пустой строки.
- `requestSubmit()` сохраняет validation и событие `submit`, а `form.submit()` обходит их.
- Placeholder является подсказкой формата, а постоянное название поля задаёт `label`.
- Client validation улучшает UX, но границей доверия остаётся server validation.
