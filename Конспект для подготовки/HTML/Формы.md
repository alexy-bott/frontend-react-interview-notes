#### Ответ на 60 секунд

HTML-форма - это нативный механизм сбора и отправки пользовательских данных. Базовая форма строится из `<form>`, связанных `<label>` и controls: `<input>`, `<textarea>`, `<select>`, `<button>`. У формы есть `action`, `method`, событие `submit`, браузерная валидация и встроенная доступность, если правильно связать label и control.

Форма - это не просто набор div-ов и input-ов. Нативные элементы дают клавиатурную навигацию, фокус, submit по Enter, автозаполнение, validation API и понятную семантику для screen readers. В React controlled/uncontrolled формы строятся поверх этих HTML-механизмов, а не вместо них.

#### Ключевая схема

```text
form
-> label + input/select/textarea
-> browser validation
-> submit event
-> FormData or controlled state
-> request to server
```

| Элемент | Зачем нужен |
| --- | --- |
| `<form>` | контейнер отправки данных |
| `<label for>` | доступное имя поля |
| `<input name>` | имя ключа в отправляемых данных |
| `<button type="submit">` | отправка формы |
| `required`, `minlength`, `pattern` | базовая HTML-валидация |
| `FormData` | сбор значений из формы |

#### Развернутый ответ

HTML-форма строится вокруг связи `form -> controls -> submit`. У каждого отправляемого control должен быть `name`: именно он становится ключом в form submission или `FormData`. Поле без `name` может отображаться и работать визуально, но не попадёт в отправляемые данные.

`label` даёт полю постоянное доступное имя. Placeholder не заменяет label: он исчезает при вводе, часто имеет слабый контраст и не всегда удобно читается assistive technologies. Placeholder подходит для подсказки формата, а не для названия поля.

`button` внутри формы без `type` по умолчанию является submit-кнопкой. Это часто ломает интерфейс, если вторичная кнопка “добавить поле”, “очистить” или “показать пароль” случайно отправляет форму. Для таких действий задают `type="button"`.

HTML constraint validation (`required`, `type="email"`, `min`, `max`, `pattern`) улучшает UX, но не заменяет server-side validation. Клиентскую проверку можно обойти, а сервер всё равно отвечает за безопасность, целостность данных и бизнес-правила.

В React controlled input хранит значение в state, uncontrolled input хранит значение в DOM, а приложение читает его через ref или `FormData`. В обоих вариантах базовая HTML-семантика остаётся важной: `form`, `label`, `name`, `button type`, autocomplete и доступные ошибки.

> [!faq]+ Уточнения
> - `name` определяет ключ поля в `FormData` и обычной отправке формы.
> - `label` даёт доступное имя, placeholder не заменяет label.
> - Кнопкам внутри формы явно задают `type`, если это не submit.
> - `fieldset` и `legend` группируют связанные controls.
> - Client-side validation улучшает UX, server-side validation защищает данные.
> - Custom controls должны воспроизводить клавиатуру, роли, состояние и доступное имя.

#### Пример

```html
<form action="/login" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email" required>

  <label for="password">Password</label>
  <input id="password" name="password" type="password" autocomplete="current-password" required>

  <button type="submit">Sign in</button>
</form>
```

JavaScript-обработка без потери семантики:

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();

  const data = new FormData(event.currentTarget);
  const email = data.get("email");
});
```

#### Частые ошибки

- Делать форму из `div` и `onClick`, теряя submit по Enter и accessibility.
- Использовать placeholder вместо label.
- Забывать `name` у полей.
- Не указывать `type="button"` для обычной кнопки внутри формы.
- Полагаться только на клиентскую валидацию.
- Показывать ошибку визуально, но не связывать её с полем для assistive technologies.
