#### Быстрый ответ

TypeScript использует типы JavaScript и добавляет статические способы точнее описывать значения. К runtime-примитивам относятся `string`, `number`, `bigint`, `boolean`, `symbol`, `undefined` и `null`. Объекты описывают через object types, `type` и `interface`; отдельные структуры — через массивы, tuples и типы функций.

Система типов также содержит конструкции, которых нет как отдельных значений в JavaScript: literal types, unions, intersections, generics, `unknown`, `any`, `never` и `void`. Они помогают компилятору проверять код, но в основном стираются при сборке.

Тип отвечает не только на вопрос «какой это вид значения», но и ограничивает допустимые операции. Например, `unknown` может содержать что угодно, но использовать его можно только после проверки; `never` означает, что допустимых значений нет.

#### Типы и значения

TypeScript работает поверх JavaScript. Поэтому важно разделять:

- **runtime-значение** реально существует при выполнении: строка, объект, функция, класс;
- **статический тип** существует для анализа программы и обычно удаляется при компиляции.

```ts
type User = { name: string };

const user: User = { name: "Ann" };
```

`user` существует в JavaScript, а `User` — нет. Поэтому нельзя выполнить `typeof User` или проверить ответ API через `instanceof User`, если `User` является только type alias.

#### Примитивные типы

| TypeScript | Пример | Что представляет |
| --- | --- | --- |
| `string` | `"text"` | строки |
| `number` | `42`, `NaN`, `Infinity` | все обычные числа JavaScript |
| `bigint` | `42n` | целые произвольной длины |
| `boolean` | `true` | логическое значение |
| `symbol` | `Symbol("id")` | уникальный ключ или идентификатор |
| `undefined` | `undefined` | значение отсутствует или не задано |
| `null` | `null` | явно отсутствующее значение |

Используются строчные имена `string`, `number` и `boolean`. `String`, `Number` и `Boolean` обозначают объекты-обёртки, которые JavaScript может создать через `new`; в типах прикладного кода они почти никогда не нужны.

При `strictNullChecks` `null` и `undefined` являются отдельными типами. Если значение может отсутствовать, это указывают явно: `User | null` или необязательным полем `name?: string`.

#### Литеральные типы и unions

Литеральный тип допускает одно конкретное значение:

```ts
type Theme = "light" | "dark";
type RetryCount = 0 | 1 | 2;
```

Union `A | B`, или объединение типов, означает один из вариантов. Он позволяет описывать реальные состояния точнее общего `string` или объекта с множеством необязательных полей.

```ts
type Result =
  | { status: "success"; data: string[] }
  | { status: "error"; error: Error };
```

Чтобы получить доступ к полям конкретного варианта, TypeScript должен сузить union по проверке `status`, `typeof`, `in` или другому runtime-признаку.

#### Объектные типы

```ts
type User = {
  readonly id: string;
  name: string;
  avatarUrl?: string;
};
```

- `readonly` запрещает переприсвоить поле через этот тип;
- `?` означает, что свойства может не быть;
- вложенные типы не становятся `readonly` автоматически;
- TypeScript сравнивает объектные типы прежде всего по их структуре.

`object` означает любое непримитивное значение, включая функции, но обычно слишком широк для полезной работы. `Object` с заглавной буквы описывает общие члены JavaScript-объектов и также допускает примитивы через boxing, поэтому в прикладных типах его обычно не используют.

`{}` не означает «пустой объект»: при `strictNullChecks` он допускает любое значение кроме `null` и `undefined`. `Record<PropertyKey, never>` ближе к объекту без допустимых собственных полей, но чаще модели нужен не «пустой объект», а точный контракт. Для неизвестного входа начинают с `unknown` и сужают его проверками.

#### Массивы и tuples

```ts
const ids: number[] = [1, 2, 3];
const names: Array<string> = ["Ann", "Bob"];

type Point = [x: number, y: number];
const point: Point = [10, 20];
```

Массив содержит произвольное количество элементов одного типа. Tuple, или кортеж, описывает фиксированные позиции и их типы. Tuple удобен для небольшой позиционной структуры, но объект понятнее, если у значений много полей или они часто читаются по имени.

`readonly string[]` и `ReadonlyArray<string>` запрещают изменяющие методы через данный тип. Это статическая гарантия, а не `Object.freeze` в runtime.

#### Типы функций

```ts
type Formatter = (value: number, locale?: string) => string;
```

Тип функции описывает параметры и результат. `void` говорит вызывающему коду, что результат не используется. `never` применяется, когда функция не может завершиться нормально, например всегда бросает ошибку.

Подробности — в [[Конспект для подготовки/TypeScript/Типизация функций]].

#### `unknown`, `any`, `never` и `void`

| Тип | Модель |
| --- | --- |
| `unknown` | значение может быть любым, перед использованием его нужно проверить |
| `any` | проверки для значения практически отключены |
| `never` | допустимого значения не существует |
| `void` | вызывающий код не использует результат функции |

`unknown` подходит для границ доверия. `any` нужен как локальный компромисс при миграции или несовместимых типах, но не как обычная модель данных. `never` помогает проверять исчерпывающую обработку union.

#### Как выбрать точность типа

Тип должен описывать значения, которые код действительно умеет обработать:

```ts
// слишком широко: непонятно, какие строки допустимы
function setStatus(status: string) {}

// точный контракт
type Status = "idle" | "loading" | "success" | "error";
function setStatus(status: Status) {}
```

Слишком широкий тип пропускает ошибочные состояния. Слишком узкий мешает законному расширению модели. Хороший тип следует контракту предметной области, а не просто текущему примеру данных.

#### Ключевые уточнения

- TypeScript-типы не добавляют runtime-валидацию и обычно удаляются из JavaScript.
- `typeof null` в JavaScript возвращает `"object"`, поэтому объект проверяют вместе с `value !== null`.
- `object`, `Object` и `{}` имеют разный смысл; ни один из них не является универсальным обозначением произвольного JSON-объекта.
- `const` не делает объект глубоко неизменяемым; `readonly` тоже действует на уровне типов и только на указанной глубине.
- `?` у свойства означает возможность отсутствия, а не просто удобный способ разрешить `undefined`.
- Union описывает альтернативы, intersection `A & B` — одновременное выполнение требований обоих типов.
- Тип обычно лучше выводить из значения, а явную аннотацию добавлять там, где она задаёт контракт.
