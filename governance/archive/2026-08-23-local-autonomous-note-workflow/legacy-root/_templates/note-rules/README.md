# Правила страниц конспекта

Канонический процесс: [`00-workflow.md`](<./00-workflow.md>).

## Короткий маршрут создания новой заметки

1. Начать с заданной темы либо с явно порученного поиска пробелов в ограниченной области репозитория.
2. Применить [`new-note-workflow.md`](<./new-note-workflow.md>).
3. До записи файла проверить дубли, пересечения, раздел, место в навигации и тематические связи.
4. До черновика исследовать центральную модель и существенные изменяемые утверждения по актуальным первичным источникам.
5. Сформировать временный смысловой план и собрать первую версию уровнями `1 → 2 → 3 BUILD`.
6. Передать заполненную версию в [`00-workflow.md`](<./00-workflow.md>) для проверки, исправления и репозиторной валидации.

Предварительный маршрут не заменяет канонические требования уровней и не разрешает расширять поиск пробелов за пределы области, заданной пользователем.

## Короткий маршрут проверки существующей заметки

1. Убедиться, что заметка уже переведена на целевую структуру либо явно взята в миграцию.
2. Зафиксировать исходную текущую версию.
3. Проверить каркас по [`01-file-structure.md`](<./01-file-structure.md>).
4. Проверить блоки по [`02-block-structure.md`](<./02-block-structure.md>).
5. Проверить состав и распределение по [`03-content-distribution.md`](<./03-content-distribution.md>).
6. Проверить пять критериев качества по [`04-content-quality.md`](<./04-content-quality.md>).
7. Передать конкретные `FAIL` уровню [`05-editing.md`](<./05-editing.md>).
8. После изменения снова выполнить `1 → 2 → 3 → 4`.
9. Сравнить текущую версию с исходной; для крупной правки проверить карту смысла.
10. Не заявлять `готово`, пока остаётся блокирующий `NOT CHECKED`.
11. Запустить применимые репозиторные проверки.

Этот README является маршрутом, а не отдельным набором требований. При расхождении применяются канонические файлы уровней.
