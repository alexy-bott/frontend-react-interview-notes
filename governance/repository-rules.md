# Правила репозитория конспекта

## Source of truth

Опубликованный `main` GitHub является source of truth. Анализ и исполнение всегда привязываются к exact commit SHA.

Основные пути:

- `README.md` — главная читательская навигация;
- `notes/<Раздел>/README.md` — смысловой маршрут раздела;
- `notes/<Раздел>/<NN Название>.md` — страницы тем;
- `scripts/**` — действующие инструменты обслуживания;
- `.github/workflows/check-notes.yml` — действующий CI;
- `governance/**` и `AGENTS.md` — текущая governance.

## Граница постепенной миграции

Активная содержательная модель обязательна для новой заметки, заметки, явно взятой в миграцию/полное ревью, и уже мигрированной заметки.

Остальной корпус остаётся legacy до плановой обработки. Governance-изменение само по себе не разрешает массовую переработку `notes/**`.

Общая CI-проверка остаётся совместимой с legacy-корпусом и не используется как доказательство semantic PASS новой модели.

## Страница заметки

- Markdown-файл находится под `notes/<Раздел>/`;
- имя начинается с двухзначного префикса, соответствующего порядку секционного `README.md`;
- H1 совпадает с видимой частью имени;
- внутренние ссылки относительные и ведут на существующие файлы;
- Obsidian frontmatter, wikilinks и callouts не публикуются;
- специальная Markdown/HTML-разметка определяется активными Levels 1–2.

## Секционный README

- H1 совпадает с названием раздела;
- ручная часть задаёт смысловые группы, состав и порядок ссылок;
- порядок ссылок является источником нумерации заметок;
- `SECTION-NAV:START/END`, счётчик и переход к первой заметке обслуживаются генератором.

Ручное редактирование generated region запрещено.

## Главный README

- содержит короткое описание и широкий маршрут разделов;
- каждый существующий раздел связан с главной страницей;
- счётчики заметок обслуживаются генератором.

## Generated navigation

Заметки содержат generated regions:

```text
NOTE-NAV-TOP:START / NOTE-NAV-TOP:END
NOTE-NAV-BOTTOM:START / NOTE-NAV-BOTTOM:END
```

Их ссылки, порядок и разделители не изменяются вручную.

`scripts/generate_navigation.py` обслуживает только `NOTE-NAV-*`, `SECTION-NAV-*` и счётчики главной страницы.

`scripts/renumber_notes.py` синхронизирует числовые префиксы с порядком секционного README и переписывает внутренние ссылки. Такое переписывание может происходить вне generated regions, но является механическим только когда каждое новое назначение следует exact approved path map. Подписи ссылок, окружающая проза, код и идентичность тематической цели при этом не меняются.

## Добавление, удаление и перемещение заметок

Web change design определяет раздел и точное место заметки в смысловом маршруте.

Codex:

1. изменяет ручную часть нужного секционного `README.md`;
2. создаёт/удаляет/перемещает разрешённые заметки;
3. запускает:

```bash
python scripts/renumber_notes.py --write
python scripts/generate_navigation.py
```

4. сверяет переименования с exact planned path map и проверяет protected-content manifest;
5. подтверждает, что вне generated regions изменены только разрешённые назначения ссылок;
6. проверяет resulting scope;
7. запускает полный набор checks.

Write-команды не запускаются для обычной содержательной правки, которая не меняет состав, порядок, имена и generated navigation.

## Связанные темы

На уровне репозитория проверяется:

- каждая цель существует и является заметкой;
- не менее двух разных исходящих тематических ссылок;
- отсутствие self-link и duplicates;
- наличие хотя бы одной входящей тематической ссылки для каждой заметки.

Содержательную релевантность конкретной связи определяет Web Level 3.

## Действующие проверки

После изменения заметок или governance выполняются применимые команды:

```bash
python -m unittest discover -s scripts -p "test_*.py" -v
python scripts/generate_navigation.py --check
python scripts/renumber_notes.py --check
python scripts/check_notes.py
git diff --check
```

CI выполняет первые четыре repository checks на push и pull request.

`REPO PASS` допустим только после фактического успешного выполнения применимых checks на actual candidate. При отсутствии доступа используется `REPO NOT CHECKED`, а не предположение.

## Governance

Обычная production-задача над заметкой не изменяет `AGENTS.md`, `governance/**`, `.github/**` и `scripts/**`, если эти пути не включены в явный scope.

Архив `governance/archive/**` является неактивным provenance и не загружается как текущая инструкция.

## Publication

Feature branch после Web и repository verification получает только `CANDIDATE READY`.

Перед публикацией снова проверяется live `main`. При изменившемся base совместимость решает ChatGPT Web. Codex не выполняет самостоятельный rebase/merge/cherry-pick.

`READY` допустим только после проверки actual default branch с той же candidate version.
